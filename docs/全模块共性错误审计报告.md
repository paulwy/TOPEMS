## 三、各类共性错误的修复详情

### 3.1 类别 4：INSERT 缺 tenant_id（NOT NULL）—— 最高发，101 处已全部修复

**根因**：多租户业务表的 `tenant_id uuid NOT NULL` 约束（迁移 `20260710161000_add_tenant_id.sql` 等），但大量 INSERT 语句未包含该列，运行时触发 `null value in column "tenant_id" violates not-null constraint`。

**扫描数据**：
- 全部 svc 共 773 条 INSERT 语句
- 数据库 598 张表含 tenant_id 列（442 张 NOT NULL，156 张可空）
- 交叉比对后确认 **101 处真实 bug**（表有 tenant_id NOT NULL，INSERT 缺列）
- 另有 83 处数据隔离风险（表有 tenant_id 可空，INSERT 缺列，不 crash 但数据不隔离）
- 132 处非 bug（表无 tenant_id 列）

**修复方式**（统一模式）：
1. INSERT 列列表尾部追加 `tenant_id`
2. VALUES 追加对应 `$N` 占位符
3. bind 追加 tenant_id 值，来源优先级：
   - 有 `Extension(claims)` 的 handler：`claims.tenant_id` 解析为 Uuid，失败回退 `Uuid::nil()`
   - GIS 模块：`topems_shared_auth::get_tenant_id_from_claims(&claims)`
   - 事件处理器：`payload.tenant_id.unwrap_or(Uuid::nil())`
   - 无 claims/payload 的内部函数：`Uuid::nil()`

**按模块分布**：

| 模块 | 修复数 | 典型文件 |
|------|-------|---------|
| wms | 26 | batch.rs, inbound_order.rs, outbound_order.rs, stock_take.rs, inventory.rs 等 |
| gis | 17 | device.rs, map.rs, spatial.rs, location.rs 等 |
| analytics | 15 | dashboard/crud.rs, comparison_analysis.rs, widget.rs 等 |

### 3.2 类别 3：SQL 列名张冠李戴 —— org_id vs organization_id（22 处已修复）

**根因**：WMS/CRM 模块从其他模块复制 SQL 后未对照真实 DDL 修改，将 `organization_id` 列误写为 `org_id`。数据库中 WMS schema 下**没有任何表**有 `org_id` 列，真实列名一律为 `organization_id`。

**已修复**：

| 模块 | 文件 | 修复内容 |
|------|------|---------|
| wms | inbound_order.rs | 7 处 SELECT/RETURNING `org_id as tenant_id` → `organization_id as tenant_id` |
| wms | outbound_order.rs | 9 处 SELECT/RETURNING + 1 处 WHERE `org_id` → `organization_id` |
| wms | analytics.rs | 1 处 WHERE `org_id = $1` → `organization_id = $1` |
| wms | stock_take.rs | 1 处 WHERE `org_id = '...'` → `organization_id = '...'` |
| wms | warehouse.rs | 1 处 INSERT 列 `org_id` → `organization_id` |
| wms | batch.rs, inventory.rs, serial_number.rs 等 | 26 处 INSERT 中 `org_id` → `organization_id`（与 tenant_id 修复同步） |
| crm | customer.rs | 1 处 INSERT 列 `org_id` → `organization_id` |

**改法依据**：`InboundOrder`/`OutboundOrder` struct 均有 `tenant_id: Uuid`（必填）+ `organization_id: Option<Uuid>`；已修复的 INSERT RETURNING 采用 `organization_id as tenant_id` 模式，全部 SELECT/RETURNING 对齐该模式。

### 3.3 类别 2：FormBuilder number 字段 —— 已全局修复（ba89fda84）

`apps/web/src/components/common/FormBuilder.tsx:405`：`handleChange(field.name, raw === '' ? '' : Number(raw))`，number 字段以 JSON number 提交，不再是字符串。

### 3.4 类别 1：前端 schema 与后端 DTO —— 无编译级错误

- `npx tsc --noEmit`：0 error
- 未发现普遍性的缺必填字段模式；MES 的 productionOrder schema 已在 `ba89fda84` 对齐

### 3.5 类别 5：sqlx query! 宏类型推断 —— 无新增错误

- 仅 analytics（98 宏）、wms（32 宏）、unified-core（16 宏）、crm（6 宏）、portal（3 宏）使用 query! 宏
- 本次修改后 `SQLX_OFFLINE=false cargo check` 在线校验：0 类型错误
- mes 模块已在 `c386a27cd` 修复 48 个类型错误

### 3.6 类别 6：运行时 sqlx::query() 列名错误 —— 部分修复，其余标注遗留

运行时 SQL（`sqlx::query()` / `sqlx::query_as()` + `only_own_schema_query!` 宏）编译期不校验列名，列名错误只在运行时报 500。本次通过列名交叉比对发现并修复了 org_id 问题，其余发现的列名问题标注为遗留（见第五节）。
