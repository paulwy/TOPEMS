# TOPEMS 对账中心与工单体系需求调研

> 版本: 1.0 | 日期: 2026-07-22
> 优先级: P2（V14.1 Phase 3 交付物）
>
> 本文档基于现有系统现状调研，明确统一对账中心和工单体系的功能范围与技术方案，为 V15.0 实施提供需求基线。

---

## 一、现状分析

### 1.1 现有对账能力

| 模块 | 位置 | 现状 | 问题 |
|------|------|------|------|
| **财务对账** | `svc/erp/src/modules/finance/reconciliation.rs` | 仅桩代码（stub），无实际逻辑 | 无自动对账、无差异分析、无银行流水匹配 |
| **应收对账** | `svc/erp/src/modules/finance/receivable.rs` | 有 CRUD，无对账功能 | 应收与实际回款无法自动匹配 |
| **应付对账** | `svc/erp/src/modules/finance/payable.rs` | 有 CRUD，无对账功能 | 应付与实际付款无法自动匹配 |

> 当前 ERP 中的 `reconcile()` 和 `auto_reconcile()` 函数直接返回成功，未执行任何对账逻辑。`AutoReconcileRequest` 接收 `type`、`entity_id`、`period` 参数，但参数校验后仅返回 `{"reconciled": 0}`。

### 1.2 现有工单/任务能力

| 模块 | 位置 | 现状 | 问题 |
|------|------|------|------|
| **MES 工单** | `svc/mes/src/modules/work_order.rs` | 生产工单 CRUD | 仅限生产域，无跨服务流转 |
| **Workflow 审批** | `svc/flow/` | 审批流引擎 | 仅限审批场景，非通用工单 |
| **QMS 质量问题** | `svc/qms/tests/quality_issue_tests.rs` | 质量缺陷跟踪 | 仅限质量域，独立闭环 |
| **Portal 待办** | `svc/portal/src/modules/todos.rs` | 聚合展示层 | 无工单创建/流转/分派能力 |
| **Mobile 任务** | `svc/mobile/src/services/openapi.rs` | 移动端任务 | 仅限移动端巡检/扫码场景 |

### 1.3 核心痛点

1. **对账分散**：应收、应付、银行流水对账分散在不同模块，财务人员需要在多个页面切换操作。
2. **手工对账为主**：缺乏自动匹配规则（如金额+日期+对方账户匹配），大量依赖人工比对。
3. **差异无法追踪**：对账差异没有统一记录和追踪机制，差异原因分析依赖线下沟通。
4. **工单体系缺失**：IT 报修、财务问题、HR 事务、生产异常等没有统一的工单入口和流转体系。
5. **服务请求无 SLA**：用户提交的问题/请求没有响应时间承诺，无法衡量服务质量。

## 二、对账中心需求

### 2.1 业务范围

```
┌─────────────────────────────────────────────────────────────────┐
│                     统一对账中心                                  │
├─────────────────┬─────────────────┬─────────────────────────────┤
│   银企对账       │   应收对账       │   应付对账                  │
├─────────────────┼─────────────────┼─────────────────────────────┤
│ • 银行流水导入   │ • 销售发票匹配   │ • 采购发票匹配              │
│ • 企业账单匹配   │ • 回款记录匹配   │ • 付款记录匹配              │
│ • 自动匹配规则   │ • 账龄分析       │ • 账龄分析                  │
│ • 差异标记       │ • 催收提醒       │ • 付款提醒                  │
│ • 余额调节表     │ • 坏账预警       │ • 逾期预警                  │
└─────────────────┴─────────────────┴─────────────────────────────┘
```

### 2.2 功能需求

#### FR-1 对账数据源管理

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-1.1 | 支持导入银行对账单（CSV/Excel/API），解析字段：交易日期、收入、支出、余额、对方账户、摘要 | P0 |
| FR-1.2 | 支持从 Finance 服务拉取企业账务数据（日记账、总账） | P0 |
| FR-1.3 | 支持从 ERP 拉取应收/应付发票数据 | P0 |
| FR-1.4 | 支持定时自动同步（每日/每周），失败时告警 | P1 |

#### FR-2 自动匹配引擎

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-2.1 | **精确匹配**：金额 + 日期（±3 天）+ 对方账户/名称 完全一致 | P0 |
| FR-2.2 | **模糊匹配**：金额相同，日期在 ±7 天内，对方名称相似度 >80% | P0 |
| FR-2.3 | **拆分匹配**：一笔银行流水对应多笔发票（金额总和相等） | P1 |
| FR-2.4 | **合并匹配**：多笔银行流水对应一笔发票（金额总和相等） | P1 |
| FR-2.5 | 匹配结果标记：已匹配 / 未匹配 / 差异 / 需人工确认 | P0 |
| FR-2.6 | 匹配规则可配置（优先级、容差天数、金额容差比例） | P1 |

#### FR-3 差异处理

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-3.1 | 差异类型标记：时间差、金额差、重复交易、遗漏交易、未知交易 | P0 |
| FR-3.2 | 差异原因录入：支持选择预设原因或自由文本 | P0 |
| FR-3.3 | 差异处理状态：待处理 / 已确认 / 已调整 / 已忽略 | P0 |
| FR-3.4 | 差异生成会计调整分录（联动 Finance 服务） | P1 |
| FR-3.5 | 差异统计报表：按类型/期间/账户汇总 | P1 |

#### FR-4 对账报告

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-4.1 | 余额调节表：银行余额 + 企业未达账项 = 企业余额 + 银行未达账项 | P0 |
| FR-4.2 | 对账完成率统计：已匹配 / 未匹配 / 差异 占比 | P0 |
| FR-4.3 | 账龄分析表：应收/应付按 30/60/90/180/360 天分段 | P0 |
| FR-4.4 | 对账历史查询：支持按期间/账户/操作人筛选 | P1 |

### 2.3 数据模型（建议）

```
reconciliation_sessions        -- 对账会话
  id, tenant_id, type, period_start, period_end,
  bank_account_id, status, created_by, created_at

reconciliation_items           -- 对账明细项
  id, session_id, tenant_id,
  source_type (bank|erp),                    -- 来源
  transaction_date, amount, direction,       -- 交易信息
  counterparty_name, counterparty_account,   -- 对方信息
  reference_no, description,                 -- 参考信息
  match_status (matched|unmatched|diff),     -- 匹配状态
  matched_item_id,                           -- 匹配的对端项
  diff_reason, diff_amount,                  -- 差异信息
  status, created_at

reconciliation_rules           -- 匹配规则
  id, tenant_id, name, priority,
  match_fields, tolerance_days, tolerance_amount,
  auto_match, enabled
```

## 三、工单体系需求

### 3.1 业务范围

```
┌─────────────────────────────────────────────────────────────────┐
│                     统一工单体系                                  │
├──────────────┬──────────────┬──────────────┬────────────────────┤
│  IT 服务台    │  财务问题     │  HR 事务      │  生产异常           │
├──────────────┼──────────────┼──────────────┼────────────────────┤
│ • 系统故障   │ • 对账差异   │ • 入职/离职   │ • 设备故障         │
│ • 权限申请   │ • 发票问题   │ • 薪资查询   │ • 质量异常         │
│ • 数据修复   │ • 付款异常   │ • 请假审批   │ • 物料短缺         │
│ • 功能咨询   │ • 报表错误   │ • 培训申请   │ • 工艺变更         │
└──────────────┴──────────────┴──────────────┴────────────────────┘
```

### 3.2 功能需求

#### FR-5 工单生命周期

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-5.1 | 工单状态流转：新建 → 待分派 → 处理中 → 待确认 → 已解决 → 已关闭 | P0 |
| FR-5.2 | 支持状态回退：处理中可退回待分派，已解决可退回处理中 | P0 |
| FR-5.3 | 工单挂起/恢复：处理中可挂起（等待外部输入），恢复后继续计时 | P1 |
| FR-5.4 | 工单转交：处理人可将工单转交给其他人员或团队 | P0 |
| FR-5.5 | 工单升级：超时未处理自动升级（通知上级/变更优先级） | P1 |

#### FR-6 工单分派与路由

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-6.1 | 基于分类自动分派：根据工单分类（IT/财务/HR/生产）路由到对应团队 | P0 |
| FR-6.2 | 负载均衡分派：分派给当前待处理工单数最少的人员 | P1 |
| FR-6.3 | 技能匹配分派：根据工单标签匹配处理人技能 | P2 |
| FR-6.4 | 手动分派：管理员/团队负责人可手动指定处理人 | P0 |

#### FR-7 SLA 管理

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-7.1 | SLA 模板配置：按工单分类和优先级定义响应时间/解决时间 | P0 |
| FR-7.2 | SLA 计时规则：排除非工作时间、挂起时间不计入 | P1 |
| FR-7.3 | SLA 告警：即将超时（80% 阈值）和已超时通知 | P0 |
| FR-7.4 | SLA 达成率统计：按团队/人员/分类统计达成率 | P1 |

**建议 SLA 标准**：

| 优先级 | 响应时间 | 解决时间 | 升级时间 |
|--------|---------|---------|---------|
| P0 - 紧急 | 15 分钟 | 4 小时 | 2 小时 |
| P1 - 高 | 1 小时 | 8 小时 | 4 小时 |
| P2 - 中 | 4 小时 | 3 天 | 1 天 |
| P3 - 低 | 1 天 | 7 天 | 3 天 |

#### FR-8 工单协作

| 需求 ID | 需求描述 | 优先级 |
|---------|---------|--------|
| FR-8.1 | 内部备注：处理人之间可添加内部备注（对请求人不可见） | P0 |
| FR-8.2 | 客户沟通记录：向请求人发送回复，记录沟通历史 | P0 |
| FR-8.3 | 附件上传：支持上传截图/文档/日志文件 | P0 |
| FR-8.4 | 关联工单：支持关联相关工单（父子/关联/重复） | P1 |
| FR-8.5 | 工单模板：预设常见问题的处理步骤和字段 | P1 |

## 四、技术方案建议

### 4.1 服务归属建议

| 系统 | 建议归属服务 | 理由 |
|------|------------|------|
| **对账中心** | **Finance 服务** | 对账本质是财务核算的延伸，Finance 服务已有科目/凭证/报表能力，对账中心作为子模块最自然 |
| **工单体系** | **新建 Ticket 服务** | 工单是跨领域的通用能力，独立服务可避免与现有业务服务耦合；也可考虑放在 **unified-core** 作为共享能力 |

### 4.2 对账中心架构

```
┌─────────────────────────────────────────────────────────────┐
│                    对账中心 (Finance 子模块)                   │
├─────────────────────────────────────────────────────────────┤
│  导入层        │  CSV/Excel 上传 → 解析 → 数据清洗           │
│  连接层        │  银行 API / ERP API / Finance API 拉取      │
│  匹配引擎      │  规则配置 → 自动匹配 → 差异标记              │
│  处理层        │  差异确认 → 调整分录 → 联动 Finance          │
│  报表层        │  余额调节表 / 对账统计 / 账龄分析            │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 工单体系架构

```
┌─────────────────────────────────────────────────────────────┐
│                    工单服务 (Ticket Service)                  │
├─────────────────────────────────────────────────────────────┤
│  接入层        │  Portal / Email / API / Mobile             │
│  路由引擎      │  分类识别 → 团队匹配 → 人员分派              │
│  生命周期      │  状态机 → SLA 计时 → 升级/告警              │
│  协作层        │  评论 / 附件 / 关联 / 模板                  │
│  报表层        │  工单统计 / SLA 达成率 / 团队绩效            │
└─────────────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────────┐
│  集成：通知中心 (unified-core) → 邮件/短信/站内通知           │
│  集成：Workflow (svc/flow) → 审批流/自动分派规则             │
│  集成：Portal (svc/portal) → 用户工单入口 / 状态查询         │
└─────────────────────────────────────────────────────────────┘
```

### 4.4 与现有系统集成点

| 集成点 | 方向 | 说明 |
|--------|------|------|
| Finance 服务 | ← 对账中心 | 对账中心调用 Finance API 获取账务数据、提交调整分录 |
| ERP 服务 | ← 对账中心 | 拉取应收/应付发票数据 |
| 银行 API | ← 对账中心 | 拉取银行流水（未来扩展） |
| unified-core/notification | ← 工单服务 | 工单状态变更/SLA 告警时发送通知 |
| svc/flow | ← 工单服务 | 复杂审批流（如预算审批工单）委托给 Flow 服务 |
| Portal | → 工单服务 | 用户通过 Portal 提交/查询工单 |
| HRM | → 工单服务 | 获取团队/人员信息用于分派 |

## 五、实施建议

### 5.1 优先级排序

| 阶段 | 内容 | 预计工时 | 依赖 |
|------|------|---------|------|
| **Phase 0** | 需求细化 + 数据模型设计 + API 契约 | 1 周 | 无 |
| **Phase 1** | 对账中心 MVP：银企对账 + 简单匹配 | 3 周 | Finance 服务稳定 |
| **Phase 2** | 工单体系 MVP：基础工单 + 分派 + SLA | 3 周 | 通知中心可用 |
| **Phase 3** | 对账增强：应收/应付对账 + 自动规则 | 2 周 | Phase 1 完成 |
| **Phase 4** | 工单增强：升级/模板/报表/知识库 | 2 周 | Phase 2 完成 |

### 5.2 验收标准

| 验收项 | 标准 |
|--------|------|
| AC-1 | 对账中心支持银行流水导入 + 企业账务拉取 + 自动匹配 |
| AC-2 | 匹配引擎支持精确匹配和模糊匹配，匹配率 >70% |
| AC-3 | 差异处理支持类型标记、原因录入、状态跟踪 |
| AC-4 | 工单体系支持新建/分派/处理/关闭完整生命周期 |
| AC-5 | SLA 管理支持模板配置、计时、告警、达成率统计 |
| AC-6 | 工单与通知中心集成，状态变更自动通知请求人 |

## 六、附录

### A. 现有对账代码分析

`svc/erp/src/modules/finance/reconciliation.rs`（当前实现）：

```rust
// 当前仅为桩代码，无实际对账逻辑
pub async fn reconcile(...) -> Json<ApiResponse<()>> {
    Json(ApiResponse::success((), "对账成功"))  // 直接返回成功
}

pub async fn auto_reconcile(...) -> Json<ApiResponse<Value>> {
    // 仅校验 period 非空，返回 {"reconciled": 0}
    Json(ApiResponse::success(json!({ "reconciled": 0 }), "自动对账完成"))
}
```

**迁移建议**：对账中心在 Finance 服务中实现后，ERP 中的 `reconciliation.rs` 标记为 `@deprecated`，API 路由代理到 Finance 服务。
