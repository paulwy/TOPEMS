# ERP 瘦身路线图

> 版本: 1.0 | 更新日期: 2026-07-22
> 状态: 规划中

## 一、背景与目标

### 1.1 现状分析

当前 ERP 服务承载了过多职责，与多个独立服务存在功能重叠：

| 功能域 | ERP 模块 | 重叠服务 | 重叠程度 |
|--------|---------|---------|---------|
| 财务核算 | `finance/`, `finance_reports/` | Finance 服务 | ⭐⭐⭐⭐⭐ 高度重叠 |
| 人力资源管理 | `hr/` | HRM 服务 | ⭐⭐⭐⭐ 高度重叠 |
| 审批流程 | `approval/` | Workflow 服务 | ⭐⭐⭐ 中度重叠 |
| 公告通知 | `announcement/` | Unified Core | ⭐⭐⭐ 中度重叠 |
| 文档管理 | `document/` | Doc 服务 | ⭐⭐ 低度重叠 |
| 供应链核心 | `purchase/`, `sales/`, `inventory/` | SCM 服务 | ⭐⭐ 部分重叠 |

### 1.2 瘦身目标

1. **财务迁出**：财务核算功能完全迁移到 Finance 服务
2. **人事独立**：人力资源功能由 HRM 服务独立承载
3. **聚焦供应链**：ERP 聚焦核心供应链能力（采购、销售、库存）
4. **降低维护成本**：减少重复代码，降低维护复杂度

### 1.3 企业管理视角定位

根据《企业管理视角分层拆解》：

- **财务底层管控** → 基础必须层 → 独立 Finance 服务
- **人力底层管控** → 基础必须层 → 独立 HRM 服务
- **供应链执行** → 可叠加增值层 → ERP 核心

## 二、功能迁移规划

### 2.1 财务域迁移（P0）

详见 [finance-migration-plan.md](./finance-migration-plan.md)

**迁移内容**：
- `modules/finance/` → Finance 服务
- `modules/finance_reports/` → Finance 服务 + BI 服务
- `modules/budget/` → Finance 服务
- `modules/fixed_asset/` → Finance 服务（P2 评估）

**迁移时间线**：6-8 周

### 2.2 人力资源域迁移（P1）

**迁移内容**：

| ERP 模块 | 功能 | 目标服务 |
|---------|------|---------|
| `hr/employee/` | 员工档案管理 | HRM 服务 |
| `hr/attendance/` | 考勤管理 | HRM 服务 |
| `hr/leave/` | 请假管理 | HRM 服务 |
| `hr/payroll/` | 薪资核算 | HRM 服务 + Finance 联动 |
| `hr/training/` | 培训管理 | HRM 服务 |
| `hr/recruitment/` | 招聘管理 | HRM 服务 |
| `hr/performance/` | 绩效管理 | HRM 服务 |

**迁移策略**：
- HRM 服务已有完整的 HR 功能，ERP 只需移除重复代码
- 数据迁移：ERP hr_* 表数据迁移到 HRM 服务
- API 兼容：ERP 原 HR API 改为代理到 HRM 服务

**迁移时间线**：4-6 周

### 2.3 OA 类功能独立（P2）

**评估中的 OA 类功能**：

| 功能 | 当前位置 | 建议去向 |
|------|---------|---------|
| 公告管理 | `modules/announcement/` | Unified Core 或独立 OA 服务 |
| 通知公告 | `modules/notification/` | Unified Core |
| 会议管理 | `modules/meeting/` | 评估：独立或合并 |
| 任务管理 | `modules/task/` | Workflow 服务 |
| 日程管理 | `modules/schedule/` | Unified Core |

**迁移策略**：
- 公告/通知已迁移到 Unified Core
- 其他 OA 功能评估后决定是否独立

### 2.4 保留在 ERP 的核心功能

**聚焦供应链执行**：

| 功能域 | 模块 | 说明 |
|--------|------|------|
| 采购管理 | `purchase/` | 采购申请、订单、收货、退货 |
| 销售管理 | `sales/` | 销售报价、订单、出库、退货 |
| 库存管理 | `inventory/` | 入库、出库、调拨、盘点 |
| 价格管理 | `price/` | 采购价、销售价、价格策略 |
| 合同管理 | `contract/` | 采购合同、销售合同 |
| 客户管理 | `customer/` | 客户档案（业务视图，主数据归 MDM） |
| 供应商管理 | `supplier/` | 供应商档案（业务视图，主数据归 MDM） |
| 产品管理 | `product/` | 产品档案（业务视图，主数据归 MDM） |

## 三、分阶段实施计划

### Phase 1：财务迁移（已在进行）

参考 [finance-migration-plan.md](./finance-migration-plan.md)

**时间线**：第 1-8 周

### Phase 2：人力资源迁移

**目标**：HRM 服务独立承载所有 HR 功能

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W1-2 | ERP HR 模块功能盘点 | 功能清单 + 差异分析 |

| W5-6 | ERP HR 模块下线 | 代码移除 + 文档更新 |

### Phase 3：OA 功能评估与迁移

**目标**：明确 OA 功能边界，完成迁移或独立

| 周次 | 任务 | 交付物 |
|------|------|--------|
| W1 | OA 功能需求调研 | 需求清单 + 使用频率分析 |
| W2 | OA 独立服务可行性评估 | 评估报告 + 决策建议 |
| W3-4 | 公告/通知迁移到 Unified Core | 功能迁移 + API 兼容 |
| W4-6 | 其他 OA 功能按决策执行 | 迁移完成或保持现状 |

### Phase 4：代码清理与文档更新

**目标**：移除冗余代码，完善文档

| 任务 | 说明 | 验收标准 |
|------|------|---------|
| 冗余模块移除 | 删除已迁移模块代码 | 无残留引用，编译通过 |
| 数据库表清理 | 归档或删除已迁移功能的表 | 数据完整归档 |
| API 文档更新 | 更新 OpenAPI 文档 | 文档与实际一致 |
| 架构文档更新 | 更新系统架构图 | 反映瘦身后的架构 |
| 运维手册更新 | 更新部署和运维文档 | 文档可用 |

## 四、瘦身后的 ERP 架构

### 4.1 最终形态

```
┌─────────────────────────────────────────────────────────┐
│                     ERP 服务（瘦身版）                     │
├─────────────────────────────────────────────────────────┤
│  采购管理    │  销售管理    │  库存管理    │  价格管理    │
│  - 采购申请  │  - 销售报价  │  - 入库管理  │  - 采购价    │
│  - 采购订单  │  - 销售订单  │  - 出库管理  │  - 销售价    │
│  - 收货退货  │  - 出库退货  │  - 调拨盘点  │  - 价格策略  │
├─────────────────────────────────────────────────────────┤
│  合同管理    │  主数据视图  │  集成接口    │  报表分析    │
│  - 采购合同  │  - 客户视图  │  - Finance   │  - 采购报表  │
│  - 销售合同  │  - 供应商视图│  - HRM       │  - 销售报表  │
│              │  - 产品视图  │  - SCM       │  - 库存报表  │
└─────────────────────────────────────────────────────────┘
```

### 4.2 服务依赖关系

- **ERP → Finance**：采购付款、销售收款调用 Finance 服务
- **ERP → HRM**：采购员、销售员信息查询
- **ERP → SCM**：供应链协同
- **ERP → MDM**：客户、供应商、产品主数据

### 4.3 代码规模预估

| 指标 | 当前 | 瘦身后 | 减少 |
|------|------|--------|------|
| 模块数 | ~30 | ~15 | 50% |
| API 端点 | ~200 | ~100 | 50% |
| 数据表 | ~80 | ~40 | 50% |
| 代码行数 | ~15,000 | ~8,000 | 47% |

## 五、风险与缓解

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|---------|
| 业务中断 | 供应链功能不可用 | 低 | 灰度发布 + 双轨运行 + 快速回滚 |
| 数据丢失 | 迁移过程中数据损坏 | 低 | 完整备份 + 迁移验证 + 回滚脚本 |
| 性能下降 | 服务调用链变长 | 中 | 缓存优化 + 并行调用 + 性能测试 |
| 用户习惯改变 | 用户需要适应新界面 | 高 | 培训文档 + 过渡期双入口 |
| 集成问题 | 服务间调用失败 | 中 | 熔断降级 + 重试机制 + 监控告警 |

## 六、验收标准

### AC-1：功能完整性
- 供应链核心功能（采购、销售、库存）100% 可用
- 财务、HR 功能通过服务调用正常可用
- 性能不低于瘦身前

### AC-2：代码质量
- 无冗余模块代码残留
- 编译零错误零警告
- 代码覆盖率达到标准

### AC-3：文档完整性
- API 文档与实际一致
- 架构文档更新
- 运维手册更新

### AC-4：可运维性
- 有完整的监控和告警
- 有详细的部署和回滚手册
- 有清晰的故障排查指南
