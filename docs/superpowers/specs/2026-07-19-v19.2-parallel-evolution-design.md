# V19.2 并行演进设计文档

> 版本: V19.2 | 创建日期: 2026-07-19
> 范围: 4 个工作流并行推进（权限枚举宏推广 / WMS 库存事件联动 / ERP 财务模块深化 / i18n 基础设施补齐）

## 一、背景

V19.1 完成共享库深化与服务边界完善后，识别出 4 个可并行推进的演进方向。本设计通过并行执行最大化迭代效率，每个工作流范围明确、相互独立。

## 二、工作流 A：权限枚举宏推广（8 个服务）

### 2.1 范围

迁移以下 8 个服务到 `define_module_permissions!` 宏：
- qms（29 变体）、mes（27 变体）、hrm（14 变体）、scm（14 变体）
- erp（12 变体，含 Approve）、srm（10 变体）、crm（8 变体）、ehs（7 变体）

**不迁移**：ai（`Manage` vs `All` 命名冲突）、pm（`View/Create/Edit` 命名差异）、rd（项目级 RBAC，语义不匹配）、lims/pdm/finance（无 dedicated 枚举）

### 2.2 实施步骤

1. 在 `lib/src/permission.rs` 的 `ModuleCode` 枚举中新增 `Srm` 变体（当前 srm 错误使用 `Scm`）
2. 对每个服务：
   - 读取现有 `shared/permission.rs`，提取变体清单和 module_code
   - 用宏调用替换 manual 实现（参考 `svc/wms/src/shared/permission.rs` 模式）
   - 保留 `check_permission` 包装函数和辅助方法
3. 逐个 `cargo check -p <service>` 验证

### 2.3 预计产出

- 8 个文件从 ~80-160 行缩减到 ~30-40 行
- 消除约 650 行 boilerplate 代码
- 统一的权限枚举生成模式

### 2.4 风险与缓解

- **风险**：srm 的 ModuleCode 变更可能影响权限校验字符串
- **缓解**：保留 srm 现有的字符串兼容性，新增 `Srm` 变体但不删除 `Scm`

## 三、工作流 B：WMS 库存事件联动（最小化订阅）

### 3.1 范围

在 WMS 三个模块发布事件 + ERP/Unified-Core 最小化订阅（仅日志记录）。

### 3.2 实施步骤

1. **新增事件类型**（`lib/src/event/event_types.rs`）：
   - `InventoryUpdated` + `InventoryUpdatedPayload`
   - `StockTransferred` + `StockTransferredPayload`
   - `StockTakeCompleted` + `StockTakeCompletedPayload`
2. **re-export**（`lib/src/event/mod.rs`）
3. **WMS 发布事件**：
   - `inventory.rs::update_inventory` → `InventoryUpdated`
   - `transfer_order.rs::ship_transfer` → `StockTransferred`（status=shipped）
   - `transfer_order.rs::receive_transfer` → `StockTransferred`（status=received）
   - `transfer_order.rs::complete_transfer` → `StockTransferred`（status=completed）
   - `stock_take.rs::adjust_stock_take` → `StockAdjusted`（复用现有类型）
   - `stock_take.rs::complete_stock_take` → `StockTakeCompleted`
4. **下游订阅**（最小化）：
   - `svc/erp/src/event_handlers/mod.rs` 新增 `handle_inventory_updated`（仅日志）
   - `svc/unified-core/src/event_handlers/mod.rs` 新增 `handle_stock_transferred`（仅日志）

### 3.3 发布模式

沿用现有模式：
```rust
if let Some(ref publisher) = state.event_publisher {
    let publisher = publisher.clone();
    tokio::spawn(async move {
        let payload = XxxPayload { ... };
        if let Err(e) = publisher.publish_event(EventType::Xxx, payload).await {
            tracing::warn!("发布事件失败: {}", e);
        }
    });
}
```

### 3.4 预计产出

- 3 个新事件类型 + 3 个 Payload 结构
- WMS 6 个发布点
- 2 个下游订阅 handler
- 库存变动全链路可观测

## 四、工作流 C：ERP 财务模块深化

### 4.1 范围

删除 V19.1 冗余 stub + 新建对账表 + 真实化 reconciliation。

### 4.2 实施步骤

1. **删除冗余文件**：
   - `svc/erp/src/modules/finance/reports.rs`（与 finance_reports/core_reports.rs 重复）
   - `svc/erp/src/modules/finance/vouchers.rs`（与 voucher/vouchers.rs 重复）
   - `svc/erp/src/services/financial_report.rs`（与 finance_reports 模块重复）
2. **更新路由注册**：`svc/erp/src/modules/finance/mod.rs` 移除已删除文件的路由
3. **检查前端 API 调用**：确认前端是否调用 `/api/erp/finance/reports/*` 或 `/api/erp/finance/vouchers/*`，如有则迁移到新路径
4. **新建迁移文件** `svc/erp/migrations/20260720000001_create_finance_reconciliation_tables.sql`：
   - `erp.fin_reconciliations`（对账主表）
   - `erp.fin_reconciliation_records`（对账明细）
   - `erp.fin_reconciliation_rules`（自动对账规则）
5. **新增模型** 在 `svc/erp/src/models/finance.rs`：
   - `Reconciliation`、`ReconciliationRecord`、`ReconciliationRule`
6. **真实化 reconciliation.rs**：
   - `reconcile`：基于 record_ids 批量标记对账状态
   - `auto_reconcile`：基于规则表自动匹配（按金额、日期、参考号）

### 4.3 数据表设计

```sql
-- erp.fin_reconciliations
CREATE TABLE erp.fin_reconciliations (
    id UUID PRIMARY KEY,
    reconciliation_no VARCHAR(50) NOT NULL,
    reconciliation_type VARCHAR(20) NOT NULL,  -- bank/ar/ap/manual
    status VARCHAR(20) NOT NULL DEFAULT 'pending',  -- pending/in_progress/completed/cancelled
    period VARCHAR(20) NOT NULL,
    reference_id VARCHAR(100),
    total_amount DECIMAL(15,2) DEFAULT 0,
    reconciled_amount DECIMAL(15,2) DEFAULT 0,
    discrepancy_amount DECIMAL(15,2) DEFAULT 0,
    tenant_id UUID NOT NULL,
    created_by UUID,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- erp.fin_reconciliation_records
CREATE TABLE erp.fin_reconciliation_records (
    id UUID PRIMARY KEY,
    reconciliation_id UUID NOT NULL REFERENCES erp.fin_reconciliations(id),
    record_type VARCHAR(20) NOT NULL,  -- invoice/payment/receipt/bank_transaction
    record_id VARCHAR(100) NOT NULL,
    amount DECIMAL(15,2) NOT NULL,
    matched_amount DECIMAL(15,2) DEFAULT 0,
    status VARCHAR(20) DEFAULT 'unmatched',  -- unmatched/matched/ignored
    matched_record_id UUID,
    tenant_id UUID NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- erp.fin_reconciliation_rules
CREATE TABLE erp.fin_reconciliation_rules (
    id UUID PRIMARY KEY,
    rule_name VARCHAR(100) NOT NULL,
    reconciliation_type VARCHAR(20) NOT NULL,
    match_field VARCHAR(50) NOT NULL,  -- amount/date/reference
    tolerance DECIMAL(15,2) DEFAULT 0,
    priority INT DEFAULT 0,
    enabled BOOLEAN DEFAULT true,
    tenant_id UUID NOT NULL,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 4.4 预计产出

- 删除 3 个冗余文件（约 400 行 stub 代码）
- 新建 1 个迁移文件（3 张表）
- 新增 3 个数据模型
- reconciliation.rs 从 stub 变为真实实现
