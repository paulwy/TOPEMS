## 一、架构决策记录

| 决策项 | 选择 | 说明 |
|-------|------|------|
| 插件本地分发 | **ZIP + Docker** | 主推 ZIP 脚本包，配套 Docker 镜像供大客户 |
| SaaS 多租户隔离 | **行级 + 独立 Schema** | 公有 SaaS 行级租户，合规私有化独立 Schema |
| 财务/项目管理 | **预装核心插件** | 默认预装核心插件，不内置核心 |
| 前端插件化 | **SystemJS + MF** | SystemJS 通用底座，内置核心插件复用 MF 优化性能 |
| 数据库迁移 | **插件独立 + SDK** | 插件独立迁移 + Core 通用迁移执行 SDK |
| 卸载策略 | **三级可配置** | 默认逻辑注销，财务禁止彻底删除 |
| 主数据权限 | **混合模式** | Core 管标准基础主数据，插件管业务扩展主数据 |
| 前端插件体积 | **软限制 1MB** | 超量警告，大组件强制懒加载 |
| 收费模式 | **订阅制 + 授权制** | SaaS 订阅，本地部署授权 |

## 三、核心插件定义

### 3.1 内置核心插件 (MF)

| 插件代码 | 名称 | 功能 | 体积限制 |
|---------|------|------|---------|
| `finance-core` | 财务核心 | 凭证、账簿、应收应付、固定资产、预算 | < 1MB |
| `project-core` | 项目管理核心 | 项目、任务、资源、成本、里程碑 | < 1MB |
| `iam-core` | 身份权限核心 | 用户、角色、权限、租户、SSO | < 500KB |
| `comm-core` | 通讯核心 | 通知中心、消息、邮件服务 | < 500KB |
| `doc-core` | 文档核心 | 知识库、文件管理、版本控制 | < 500KB |

### 3.2 业务插件 (SystemJS)

| 套件 | 插件 | 依赖 | 体积限制 |
|-----|------|------|---------|
| 经营套件 | ERP | finance-core, project-core | < 1MB |
| 协同套件 | HRM | finance-core | < 1MB |
| 协同套件 | Admin | - | < 800KB |
| 协同套件 | Archive | doc-core | < 800KB |
| 智能套件 | AI Suite | doc-core | < 1.5MB |
| 生产套件 | MES | project-core, finance-core | < 1MB |
| 生产套件 | PDM | project-core | < 800KB |
| 供应链套件 | SCM | finance-core, project-core | < 1MB |
| 供应链套件 | WMS | mes, scm | < 1MB |
| 供应链套件 | SRM | scm | < 800KB |
| 分析套件 | BI | finance-core, project-core | < 1.5MB |

### 3.3 预装策略

```yaml
presets:
  minimal:
    - iam-core
    - comm-core
    - doc-core
    - finance-core
    - project-core

  standard:
    extends: minimal
    plugins:
      - erp
      - hrm
      - admin

  enterprise:
    extends: standard
    plugins:
      - mes
      - scm
      - wms
      - ai-suite
      - bi
```

## 五、数据库迁移机制

### 5.1 Migration SDK 架构

```
MigrationSDK
├── MigrationExecutor      # 执行引擎
├── MigrationLock         # 分布式锁 (Redis)
└── MigrationHistory      # 迁移历史表
```

### 5.2 迁移执行流程

1. 插件启动 → 调用 SDK.register()
2. SDK 检测未执行迁移
3. 获取分布式锁
4. 按版本顺序执行迁移
5. 失败自动回滚

## 六、插件卸载策略

### 6.1 三级策略

| 策略 | 说明 | 可逆性 |
|-----|------|-------|
| `logical_delete` | 逻辑注销，数据保留 | ✅ 可恢复 |
| `archive` | 归档到历史表，保留 90 天 | ✅ 可恢复 |
| `force_delete` | 彻底删除 | ❌ 不可恢复 |

### 6.2 特殊限制

- 财务模块禁止 `force_delete`
- 默认策略为 `logical_delete`

## 七、主数据管理规范

### 7.1 主数据分类

| 层级 | 管理方 | 内容 |
|-----|-------|------|
| Core 层 | iam-core, finance-core | 组织架构、人员、会计科目 |
| Plugin 层 | 各业务插件 | 客户、供应商、物料、工艺路线 |

### 7.2 权限规则

- Core 层主数据：只读 API，各插件可引用
- Plugin 层主数据：完整 CRUD，插件自主管理

## 八、前端插件加载规范

### 8.1 加载流程

1. 获取插件 manifest
2. 体积检查 (< 1MB 警告)
3. SystemJS 注册模块
4. 动态注册路由和菜单

### 8.2 懒加载强制

- 大组件必须使用 React.lazy
- 路由级别支持按需加载

## 九、收费模式设计

### 9.1 收费模式矩阵

| 部署模式 | 计费方式 | 说明 |
|---------|---------|------|
| SaaS | 订阅制 | 月付/年付，按套件/用户数 |
| 本地部署 | 授权制 | 一次性授权 + 年度维护 |

### 9.2 定价示例

| 套件 | 月价 | 年价 |
|-----|-----|-----|
| 基础版 | ¥500 | ¥5,000 |
| 财务版 | ¥1,500 | ¥15,000 |
| 经营版 | ¥2,500 | ¥25,000 |
| 智能版 | ¥2,000 | ¥20,000 |
| 企业版 | ¥10,000 | ¥100,000 |

### 9.3 许可证管理

```
LicenseService
├── validate()        # 验证许可证
├── checkFeature()    # 检查功能权限
├── getSubscription() # 获取订阅信息
└── getAvailablePlugins() # 获取可用插件
```
