# TOPEMS 插件化架构设计文档

> 创建时间: 2026-06-22
> 版本: v1.0
> 状态: 已实现

## 一、设计目标

以插件市场为核心，实现"套件化"组织方式，将功能相近的插件聚合为套件，提供统一的用户体验。

## 二、架构概述

```
┌─────────────────────────────────────────────────────────────┐
│                     前端层 (React + TypeScript)              │
├─────────────────┬─────────────────┬─────────────────────────┤
│   插件市场页面   │    导航系统     │     插件上下文管理       │
│ PluginMarketplace│ Navigation-v2  │    PluginContext        │
└─────────────────┴─────────────────┴─────────────────────────┘
├─────────────────────────────────────────────────────────────┤
│                      API 层                                 │
│  plugin.ts (插件管理、套件信息、健康检查)                    │
└─────────────────────────────────────────────────────────────┘
├─────────────────────────────────────────────────────────────┤
│                    Vite 代理层                              │
│  /api/{module}/* → http://localhost:{port}                  │
└─────────────────────────────────────────────────────────────┘
```

|---------|---------|---------|
| 生产套件 | MES、PDM | 离散/流程制造管理 |

## 六、权限集成

导航系统集成了权限控制：
- 超级管理员可见所有菜单
- 普通用户根据权限过滤
- 未安装插件自动隐藏对应菜单

## 七、待讨论问题

### 7.1 核心模块定位
- 核心模块作为整体，其功能是最基本的
- 要能单独实现功能，满足基本需求
- 同时能很好的对接插件模块
- 在没有插件的情况下，也能有很好的实现

### 7.2 插件独立性
- 插件作为独立的，既要和核心模块有连结
- 也能和其他插件有协作（通过核心模块）

### 7.3 插件自升级能力
- 插件模块要能自我升级、功能自我完善
- 插件的前端资源（菜单、前端组件）是否要来自插件本身？
- 整体架构是否需要调整？

### 7.4 统一规划
- 基于以上整个系统的菜单、模块、功能、系统设置等等
- 是否也要统一规划？
