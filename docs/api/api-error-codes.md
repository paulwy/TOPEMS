## 错误响应格式

### 标准错误响应

所有 API 错误都使用统一的 JSON 响应格式：

```json
{
  "error": {
    "code": "AUTH_001",
    "message": "用户名或密码错误",
    "details": "提供的用户名或密码不正确，请检查后重试",
    "timestamp": "2026-08-28T10:30:00Z",
    "request_id": "req_abc123def456",
    "path": "/api/core/auth/v1/login",
    "method": "POST"
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | string | 错误码，唯一标识错误类型 |
| `message` | string | 简短的错误描述（用户友好） |
| `details` | string | 详细的错误说明和解决建议（可选） |
| `timestamp` | string | 错误发生时间（ISO 8601 格式） |
| `request_id` | string | 请求唯一标识，用于问题追踪 |
| `path` | string | 请求的 API 路径 |
| `method` | string | 请求的 HTTP 方法 |

### 验证错误响应

数据验证错误使用特殊格式，包含字段级别的错误信息：

```json
{
  "error": {
    "code": "VALID_001",
    "message": "请求参数验证失败",
    "details": "请检查以下字段",
    "timestamp": "2026-08-28T10:30:00Z",
    "request_id": "req_abc123def456",
    "path": "/api/core/erp/v1/orders",
    "method": "POST",
    "fields": [
      {
        "field": "email",
        "message": "邮箱格式不正确",
        "value": "invalid-email"
      },
      {
        "field": "amount",
        "message": "金额必须大于 0",
        "value": -100
      }
    ]
  }
}
```

## HTTP 状态码

### 标准 HTTP 状态码

| 状态码 | 名称 | 说明 |
|--------|------|------|
| **200** | OK | 请求成功 |
| **201** | Created | 资源创建成功 |
| **204** | No Content | 请求成功，无返回内容 |
| **400** | Bad Request | 请求参数错误 |
| **401** | Unauthorized | 未认证或认证失败 |
| **403** | Forbidden | 无权限访问 |
| **404** | Not Found | 资源不存在 |
| **405** | Method Not Allowed | HTTP 方法不允许 |
| **409** | Conflict | 资源冲突 |
| **410** | Gone | 资源已被永久删除 |
| **413** | Payload Too Large | 请求体过大 |
| **415** | Unsupported Media Type | 不支持的媒体类型 |
| **422** | Unprocessable Entity | 语义错误，无法处理 |
| **429** | Too Many Requests | 请求过于频繁，速率限制 |
| **500** | Internal Server Error | 服务器内部错误 |
| **502** | Bad Gateway | 网关错误 |
| **503** | Service Unavailable | 服务不可用 |
| **504** | Gateway Timeout | 网关超时 |

## 通用错误码

### 通用错误码列表

| 错误码 | HTTP 状态码 | 说明 | 可能原因 | 解决方法 |
|--------|------------|------|---------|---------|
| `COMMON_001` | 400 | 请求参数错误 | 请求参数格式不正确或缺少必填参数 | 检查请求参数，确保所有必填参数都已提供且格式正确 |
| `COMMON_002` | 400 | 请求体格式错误 | JSON 格式不正确或 Content-Type 错误 | 确保请求体是有效的 JSON，Content-Type 设置为 application/json |
| `COMMON_003` | 404 | 资源不存在 | 请求的资源 ID 不存在或已被删除 | 检查资源 ID 是否正确，确认资源未被删除 |
| `COMMON_004` | 405 | 方法不允许 | 使用了不支持的 HTTP 方法 | 检查 API 文档，使用正确的 HTTP 方法 |
| `COMMON_005` | 406 | 不接受的响应格式 | Accept 头指定了不支持的格式 | 设置 Accept 为 application/json |
| `COMMON_006` | 409 | 资源冲突 | 资源已存在或状态冲突 | 检查资源是否已存在，处理冲突情况 |
| `COMMON_007` | 410 | 资源已删除 | 请求的资源已被永久删除 | 使用新的资源或恢复数据 |
| `COMMON_008` | 413 | 请求体过大 | 请求体超过大小限制 | 减小请求体大小，使用分块上传 |
| `COMMON_009` | 415 | 不支持的媒体类型 | Content-Type 不被支持 | 使用支持的 Content-Type（通常是 application/json） |
| `COMMON_010` | 422 | 无法处理的实体 | 请求语义错误 | 检查请求数据的业务逻辑是否正确 |
| `COMMON_011` | 429 | 请求过于频繁 | 超过 API 速率限制 | 降低请求频率，等待限制重置 |
| `COMMON_012` | 500 | 服务器内部错误 | 服务器发生未知错误 | 稍后重试，如持续出现请联系支持 |
| `COMMON_013` | 502 | 网关错误 | 上游服务返回无效响应 | 稍后重试，检查服务状态 |
| `COMMON_014` | 503 | 服务不可用 | 服务正在维护或过载 | 稍后重试，查看服务状态 |
| `COMMON_015` | 504 | 网关超时 | 上游服务响应超时 | 稍后重试，检查网络连接 |

## 错误排查指南

### 排查步骤

遇到 API 错误时，按照以下步骤排查：

#### 1. 检查错误响应

```bash
# 查看完整的错误响应
curl -v -X POST http://localhost:8000/api/core/auth/v1/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"wrong"}'
```

重点关注：
- HTTP 状态码
- 错误码（error.code）
- 错误信息（error.message）
- 详细信息（error.details）
- 请求 ID（error.request_id）

#### 2. 检查请求

- 请求 URL 是否正确
- HTTP 方法是否正确
- 请求头是否完整（Content-Type、Authorization 等）
- 请求体格式是否正确
- 请求参数是否完整

#### 3. 检查认证

- Token 是否有效且未过期
- Token 是否正确添加到请求头
- 用户是否有相应权限
- 账户状态是否正常（未锁定、未禁用）

#### 4. 检查服务状态

```bash
# 查看所有服务状态
./scripts/topems.sh status

# 健康检查
curl http://localhost:8000/health
curl http://localhost:8000/ready

# 查看服务日志
./scripts/topems.sh logs <service>
```

#### 5. 检查依赖服务

```bash
# 检查数据库
pg_isready -h localhost -p 5432

# 检查 Redis
redis-cli ping

# 检查 Ollama（AI 服务）
curl http://localhost:11434/api/tags
```

### 常见问题排查

#### 401 Unauthorized

**可能原因：**
- 未提供 Token
- Token 无效或过期
- Token 格式错误

**解决方法：**
```bash
# 1. 确认 Token 已添加到请求头
curl -H "Authorization: Bearer <your-token>" http://localhost:8000/api/core/erp/v1/orders

# 2. 重新登录获取新 Token
curl -X POST http://localhost:8000/api/core/auth/v1/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"admin123"}'

# 3. 使用 Refresh Token 刷新
curl -X POST http://localhost:8000/api/core/auth/v1/refresh \
  -H "Content-Type: application/json" \
  -d '{"refresh_token":"<your-refresh-token>"}'
```

#### 403 Forbidden

**可能原因：**
- 用户没有相应权限
- IP 地址被限制
- 访问时间被限制

**解决方法：**
- 联系管理员分配权限
- 检查 IP 白名单配置
- 检查访问时间限制

#### 404 Not Found

**可能原因：**
- 请求的资源 ID 不存在
- API 路径错误
- 资源已被删除

**解决方法：**
- 检查资源 ID 是否正确
- 核对 API 文档中的路径
- 确认资源未被删除

#### 429 Too Many Requests

**可能原因：**
- 超过 API 速率限制
- 短时间内发送过多请求

**解决方法：**
- 降低请求频率
- 实现请求重试和退避策略
- 联系管理员提升速率限制

#### 500 Internal Server Error

**可能原因：**
- 服务器内部错误
- 数据库连接失败
- 代码 Bug

**解决方法：**
- 稍后重试
- 查看服务日志获取详细错误信息
- 联系技术支持并提供 request_id
