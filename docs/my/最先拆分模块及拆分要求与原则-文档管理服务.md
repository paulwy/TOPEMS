# 文档管理服务拆分实施指南

## 一、概述

### 1.1 为什么从文档管理服务开始拆分
文档管理服务（Document Service）是最适合作为拆分起点的模块，原因如下：

| 优势 | 详细说明 |
|------|---------|
| **业务独立性强** | 文件的上传、下载、存储、版本管理是通用且边界清晰的功能，作为基础服务被其他模块调用，自身依赖最少 |
| **技术复杂度适中** | 主要涉及文件I/O、存储、权限控制，业务逻辑相对简单，无复杂事务处理 |
| **风险可控** | 即使拆分出现问题，影响范围仅限于文件操作，不会导致核心业务瘫痪，便于快速修复和回滚 |
| **价值验证** | 成功拆分后可作为独立的"企业网盘"服务存在，快速验证微服务架构的可行性 |

### 1.2 当前项目现状

1. **创建数据库Schema**

   **文件位置：** [`platform/topems-doc/backend/src/db/migrations/20260523000001_create_doc_schema.sql`](file:///Users/xingzhai/TOPEMS/platform/topems-doc/backend/src/db/migrations/20260523000001_create_doc_schema.sql)

   ```sql
   -- 文档管理服务独立数据库 Schema
   CREATE SCHEMA IF NOT EXISTS doc_service;

   -- 文件表
   CREATE TABLE IF NOT EXISTS doc_service.files (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       name VARCHAR(255) NOT NULL,
       folder_id UUID,
       size BIGINT NOT NULL,
       content_type VARCHAR(255) NOT NULL,
       storage_path TEXT NOT NULL,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       created_by VARCHAR(255) NOT NULL
   );

   -- 文件夹表
   CREATE TABLE IF NOT EXISTS doc_service.folders (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       name VARCHAR(255) NOT NULL,
       parent_id UUID,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       created_by VARCHAR(255) NOT NULL,
       FOREIGN KEY (parent_id) REFERENCES doc_service.folders(id) ON DELETE CASCADE
   );

   -- 文件版本表
   CREATE TABLE IF NOT EXISTS doc_service.file_versions (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       file_id UUID NOT NULL REFERENCES doc_service.files(id) ON DELETE CASCADE,
       version INT NOT NULL,
       size BIGINT NOT NULL,
       checksum VARCHAR(255) NOT NULL,
       storage_path TEXT NOT NULL,
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
       created_by VARCHAR(255) NOT NULL,
       UNIQUE(file_id, version)
   );

   -- 文件权限表
   CREATE TABLE IF NOT EXISTS doc_service.file_permissions (
       id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
       file_id UUID NOT NULL REFERENCES doc_service.files(id) ON DELETE CASCADE,
       user_id UUID,
       role_id UUID,
       permission VARCHAR(50) NOT NULL, -- read, write, delete, admin
       created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
   );

   -- 索引
   CREATE INDEX idx_files_folder_id ON doc_service.files(folder_id);
   CREATE INDEX idx_files_created_by ON doc_service.files(created_by);
   CREATE INDEX idx_folders_parent_id ON doc_service.folders(parent_id);
   CREATE INDEX idx_file_versions_file_id ON doc_service.file_versions(file_id);
   ```

### 7.2 使用 JWT 认证

文档服务已集成 JWT 认证，所有 API 端点（除了 `/` 和 `/health`）都需要有效的 Bearer Token。

**测试认证功能：**
```bash
# 没有提供 token，应该返回 401 Unauthorized
curl http://localhost:8001/api/v1/files -v
```

**获取 Token：** 从 IAM 服务登录获取 JWT Token（默认密钥：`topems_secret_key_for_jwt_signing_2024`）
```bash
# 使用 IAM 服务的登录接口获取 Token
# 然后使用 token 访问文档服务 API
curl http://localhost:8001/api/v1/files \
  -H "Authorization: Bearer YOUR_JWT_TOKEN"
```

### D. 权限检查实现

文档管理服务已实现基于 JWT 的权限检查机制：

1. **Claims 结构** ([`middleware/auth.rs`](file:///Users/xingzhai/TOPEMS/platform/topems-doc/backend/src/middleware/auth.rs))
   - 包含用户 ID、角色列表和权限列表
   - 支持 `has_role()` 和 `has_permission()` 验证方法
   - 实现了 `FromRequestParts` 提取器，可在请求处理函数中直接使用

2. **权限规则**
   - 文件列表、获取详情、下载和预览：需要 `read` 权限或 `admin` 角色
   - 文件上传：需要 `write` 权限或 `admin` 角色
   - 文件删除：需要 `delete` 权限或 `admin` 角色

3. **使用方式**
   - 在处理函数参数中添加 `claims: Claims` 即可自动获取并验证
   - 权限不足时返回 403 Forbidden 错误和相应的 JSON 响应
