# TOPEMS 系统测试方案

## 1. 概述

本测试方案为 TOPEMS 系统提供了全面的测试策略，包括单元测试、集成测试、端到端测试和性能测试。

## 2. 测试层级

### 2.1 单元测试

**目的**：验证单个模块、函数或组件的功能正确性。

**范围**：
- 后端：Rust 模块和函数
- 前端：React 组件、自定义 Hook、工具函数

**执行命令**：
```bash
# 后端
cd services/backend
cargo test

# 前端
cd frontend
npm run test
npm run test:coverage  # 带覆盖率
```

**通过标准**：
- 所有测试通过
- 代码覆盖率 >= 70%

### 2.2 集成测试

**目的**：验证多个模块或服务之间的交互。

**范围**：
- 服务间 API 调用
- 数据库集成
- 身份认证流程
- 微服务协作

**测试工具**：
- Rust cargo test
- Postman 集合
- 自定义 Bash 脚本

**执行步骤**：
1. 启动所有服务（docker-compose）
2. 执行健康检查
3. 测试 IAM 认证
4. 使用 Token 访问其他服务 API

### 2.3 端到端 (E2E) 测试

**目的**：验证用户完整操作流程。

**范围**：
- 用户登录/登出
- 主要业务流程
- 核心功能操作

**测试工具**：Playwright

**执行命令**：
```bash
cd frontend
npm run e2e
npm run e2e:ui  # 可视化模式
```

### 2.4 性能测试

**目的**：验证系统在负载下的性能表现。

**测试工具**：
- k6
- Apache Bench (ab)
- wrk

**关键指标**：
- 响应时间 (p95 < 500ms, p99 < 1000ms)
- 错误率 < 1%
- 吞吐量 (RPS)
- 资源使用率 (CPU、内存)

## 3. 测试执行计划

### 3.1 开发阶段测试

**每次代码提交时**：
- 运行单元测试
- 检查代码覆盖率

**PR 合并时**：
- 运行完整单元测试
- 运行集成测试
- 检查覆盖率门槛

### 3.2 每日测试

**定时执行（每日 2:00 AM）**：
- 完整单元测试
- 集成测试
- 性能测试（可选）

### 3.3 发布前测试

**完整测试流程**：
1. 单元测试 + 覆盖率
2. 集成测试
3. E2E 测试
4. 性能基准测试
5. 手工功能测试

## 4. 测试环境

### 4.1 本地开发环境

- 使用 docker-compose 启动测试服务
- 使用测试数据库
- 使用本地配置

### 4.2 CI/CD 环境

- GitHub Actions 工作流
- 临时容器服务
- 自动化报告生成

## 5. 测试报告

### 5.1 报告类型

- 单元测试报告（Jest/Cargo）
- 覆盖率报告（lcov/html）
- E2E 测试报告（Playwright）
- 性能测试报告（k6）

### 5.2 报告存储

- 本地：`coverage/`, `playwright-report/`
- CI：上传到 GitHub Actions Artifacts
- 代码覆盖率：Codecov

## 6. 验收标准

### 6.1 发布要求

- 所有单元测试通过
- 代码覆盖率 >= 70%
- 所有 E2E 测试通过
- 性能指标达标
- 无严重 bug

### 6.2 优先级定义

- **P0**：必须通过，否则不发布（登录、核心功能）
- **P1**：重要功能，建议修复后发布
- **P2**：一般功能，可后续优化
