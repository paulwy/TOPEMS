# TOPEMS 主模块功能缺陷与前后端补位评估（2026-11-19）

- 评估基线：`git HEAD` = `b95700640`（2026-11-19 10:39 CST），工作区有 2 处未提交 SQL/代码改动，未纳入结论。
- 方法：静态代码实测（Rust 路由/handler、前端页面/API 调用、`not_implemented` 标记）+ 复用项目既有门禁读数（P6 API 对账、导航路由一致性、功能闭环三清单）。
- 边界：未启动全栈、未跑 e2e、未连生产库；本文件只做评估，未改任何代码、未提交。

---

## 0. 结论

**主模块“骨架”没有缺口，缺陷集中在三处：前端仍在展示假数据、少数前端已接线的能力后端只返回 501、EHS 职业健康域整块未交付。**

| 判断 | 结论 |
|---|---|
| 是否需要新增后端服务 | **不需要**。29 个服务与 35 个前端模块已一一覆盖，无“有前端无后端”的模块 |
| 是否需要补后端接口 | **不需要补“缺的接口”**。P6 实测 1012 个前端调用点、843 个不同 API 方法，RED=0，前端没有任何调用落到不存在的后端方法 |
| 是否需要补后端“功能” | **需要，6 个域**：EHS 职业健康/危化品/应急/同步、AI 用量计量、MES 成本归集、GIS 轨迹、SCM 需求预测、SRM 合同条款；另有文件中心 3 个接口、IAM 权限定义写接口、财务合并报表 3 个动作仍是 501 |
| 是否需要补前端 | **需要，但只补接线**：8 个生产页面仍用 mock 数据（其中银行账户管理整页纯 mock，真实接口已存在）；6 处提交失败仍提示“成功”；GIS 空间分析、LIMS 校准台账等后端能力无 UI，按产品需要补 |
| 最大风险项 | 前端 mock 兜底会掩盖后端故障并向用户展示虚构业务数据，与后端“宁可 501 也不造假”的既定原则正面冲突 |

严重度排序：**P0 数据真实性（前端）> P1 前后端 501 对接 > P1 后端功能半成品 > P2 EHS 域未交付 > P3 覆盖厚度不均**。

## 2. 缺陷清单

### 2.1 P0｜前端假数据（8 页，全部已挂路由）

| # | 页面 | 证据 | 性质 |
|---:|---|---|---|
| 1 | `apps/web/src/pages/admin/BankAccountManagementPage.tsx` | `mockBankAccounts` 作为唯一数据源，新增/编辑/删除均写内存数组（`:29`、`:65`、`:101-117`）；页面在 `module-configs/admin/config.ts:196` 注册 | **纯 mock CRUD**。真实后端 `svc/erp/src/modules/bank_account.rs:28`（`/bank-accounts`）与前端 `api/erp/bankAccount.ts` 都已存在，只是没接线 |
| 2-4 | `pages/crm/CrmCustomerRedesignPage.tsx`、`CrmContractRedesignPage.tsx`、`CrmOpportunityRedesignPage.tsx` | API 抛错时 `setIsMockData(true)` 后返回 `mockCustomers/Contracts/Opportunities`（如 `:315`） | 降级为假数据；列表有 mock 提示，但数据本身虚构 |
| 5 | `pages/wms/WmsStocktakePage.tsx` | `catch` 后 `let filtered = mockStocktakes`（`:314`） | 同上，有 `isMockData` 横幅（`:600`） |
| 6 | `pages/mes/MesWorkOrderPage.tsx` | `return mockOrders`（`:268`）、`const orders = data \|\| mockOrders`（`:284`） | 同上，且 mock 工单可继续触发删除操作 |
| 7 | `pages/erp/PurchaseOrderPage.tsx` | `return mockOrders`（`:301`）、`:317` | 同上 |
| 8 | `pages/monitor/MonitorAlertRulesPage.tsx` | `mockApiAdapter`（`:251`） | 规则页以内存适配器为数据源 |

**为什么定 P0**：后端在 EHS/财务/文件等域明确选择“宁返回 501 也不返回模拟数据”（如 `svc/finance/src/modules/report_center.rs:878` 注释「已停止返回模拟报表」）。前端这 8 页与之一致性相反 —— API 一挂就显示看起来正常的虚构数据，用户无法区分“系统故障”和“业务为空”，管理人员还可能据此做决策。

**修法**：接真实 API；失败态改为显式错误 + 重试入口；确需演示数据时用 `import.meta.env.DEV` 硬门禁，生产构建直接剔除。

## 4. 不建议做的事

1. **不新增服务、不新增前端模块**：29 服务 / 35 模块已一一对应，`check-nav-route` 一致，再加只会稀释边界。
2. **不为“零引用表”补页面**：477 张待处置表里 207 张是删除候选，补 UI 等于给死表续命。
3. **不为内部/集成端点补 UI**：portal 340 条未引用路由多为平台能力，不是用户功能。
4. **不靠“再包一层 mock”过渡**：会继续放大 §2.1 的数据真实性问题。
