## 3. 并发压测设计（硬验收）

前置：验收 DSN 必须 `rolsuper=false && rolbypassrls=false`，脚本首行打印库身份，角色不合格直接退出（exit 2）。
数据准备用超户，业务请求用租户管理员 token（HTTP，走完整中间件）。

- **A 出库超卖（20 线程）**：T1 一个库存行 `qty=available=100`（batch B1）；造 20 张出库单各 1 明细（同 org/material/batch，qty=10）。20 个 `POST /outbound-orders/{id}/ship` 同时发。
  断言：200 恰 10 个；其余全 4xx 无 5xx；`quantity=available=0`；无负数；`sum(shipped_quantity)=100`；outbound movement 恰 10 条；无 deadlock 导致的库存丢失。
- **B 库存调整并发覆盖（20 线程）**：同一 inventory 行，20 个 `PUT /inventory/{id}` 各提交不同绝对值（含 available）。
  断言：最终值 ∈ 20 个提交值集合；`初始值 + sum(movement.delta) = 最终值`；movement 条数 = 成功请求数（差值 0 除外）→ 证明没有“读旧值算差额”的丢更新。
- **C 入库并发累加（20 线程）**：同 org/material/batch 各自收货 5；断言 `quantity/available = 100`，movement 20 条，无丢增量。
- **D RLS 矩阵（非超户）**：T1/T2 各 1 行；T1 只见 T1；T2 按 id 取 T1 → 404；T1 插 T2 tenant → 拒绝；超管 + `x-tenant-id: T1` 创建 → `tenant_id=T1`；超管无头 → 400；`start_stock_take` 明细 `tenant_id=T1` 且全表 `NULL` 计数不增。
- **E 0 行语义**：删不存在 → 404；对已 shipped 单再 ship → 409；子行越权/不存在 → 404 且父行不落库。
