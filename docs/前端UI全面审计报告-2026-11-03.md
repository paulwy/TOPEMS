## 1. 审计口径与方法

- **页面清单来源**：`src/routes/v2/index.ts` 模块注册表（36 模块）→ 各模块 `src/modules/<mod>/config.ts` 的 `<MOD>ModuleConfig.routes[]`（含外部路由变量，如 `wmsRoutes`）→ 提取 `path + element` 路由对；叠加静态路由 `auth.ts`（3）/ `common.ts`（3）/ `dashboard.ts`（11）/ `appRoutes.tsx` 硬编码（/performance、/core/users、/core/roles）。
- **页面文件**：组件 `@/pages/...` 映射 `src/pages/...tsx` 或目录形式 `.../index.tsx`（如 `mes/ProductionDashboardPage/`、`system/FeatureFlagPage/`）。
- **页面级测试**：同名测试（`<pdir>/__tests__/<Page>.test.tsx`、顶层 `src/pages/__tests__/<Page>.test.tsx`）或聚合测试 import 该页面路径。
- **API 接线**：页面文件内直接 import `@/api` / `@/services` / 相对 api/services 模块；间接层（hooks、统一 service 入口）不在本口径内，无直接 import 的 49 页需人工复核。
- **三态**：页面源码 grep `isLoading/loading/skeleton`、`EmptyState/empty`、`error/ErrorBoundary`（近似统计，与 10-07 同口径）。
- **e2e**：`apps/web/e2e/**/*.spec.ts` 中 `page.goto('/...')` 路由去重后与全量清单对照。

## 4. 审计发现

### 4.1 页面级测试覆盖缺口（主风险）

- 全量 513 动态路由中仅 **107 页（20.9%）**有页面级测试（同名或聚合 import）。
- **7 个模块零页面级测试**：rd（20 路由）、aps（12）、master（12）、integration（9）、monitor（7）、doc（6）、im（2）——合计 **68 个页面无任何直接测试**。
- 大模块偏低：wms 6/34（18%）、scm 1/20（5%）、hrm 3/25（12%）、admin 3/22（14%）、pdm 3/21（14%）。
- 覆盖较好：automation 80%、iam 80%、gis 60%、oa 60%、ehs 47%、lims 45%、mes 34%。
- 背景：`src/pages/__tests__/` 顶层聚合目录有 131 个测试文件（117 页面级 + 组件级），另有模块内 `__tests__/` 与组件/hooks 测试（全库测试文件 442 个）——**组件级覆盖尚可，页面级（路由级）是真空带**。

### 4.2 无直接 API 接线的页面（49 页）

口径：页面文件内无 `@/api` / `@/services` 直接 import（可能经 hooks/service 间接调用，需人工复核）。代表性样本：

| 类型 | 页面 |
|---|---|
| dashboard 类 | `/admin/system`、`/ai/chat`、`/asset`、`/ehs/dashboard`、`/im/dashboard`、`/integration/dashboard` |
| 配置/调试类 | `/admin/config-debug`、`/admin/feature-flag`、`/admin/menu` |
| 文档/知识库类 | `/doc/documents`、`/doc/knowledge-base` |
| 报表/看板类 | `/bi/gis`、`/finance/consolidation-reports` |
| 表单/详情类 | `/finance/vouchers`、`/finance/opening-balance`、`/finance/consolidation` |

> 完整 49 行见 CSV（api_ok=否）。`im` 模块 2 个页面均无直接 API（`/im/dashboard`、`/im/mail`），且 integration 模块 5/9 无——疑似功能未完全接线，建议优先人工复核。

### 5.3 扩展建议（按缺口 × 业务重要度排序）

1. **mes / wms / erp / finance（核心业务，覆盖 2-4%）**：先补生产订单-设备-质量主链路（mes 3 条）、入库-库存-出库链路（wms 3 条）、采购-应付（erp/finance 各 2 条），可达模块级 15%+。
2. **零覆盖高价值模块**：scm（采购主链路）、srm（供应商）、tms（运输）、crm（现有 3001 端口 spec 迁回主端口）、report。
3. **integration / doc / im / ticket（0 覆盖 + 部分无 API 页面）**：先人工确认页面功能完整度，再补冒烟级 e2e（导航可达 + 首屏渲染 + 无 console error）。
4. **通用基线**：沿用 `full-route-smoke.spec.ts` 模式做**全量路由冒烟**（518 路由 → 401/404/空白屏/console error 四断言），即可把 e2e 基线从 8.7% 提至 100% 路由可达性，再按上表加深业务断言。
5. **10-07 遗留**：e2e 实跑环境（后端 + 浏览器）已具备（83 spec 在库），建议将 e2e 纳入 CI 门禁（10-07 明确要求）。
