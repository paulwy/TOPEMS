## 1. 审计口径与方法

- **页面清单来源**：`src/routes/v2/index.ts` 模块注册表（36 模块）→ 各模块 `src/modules/<mod>/config.ts` 的 `<MOD>ModuleConfig.routes[]`（含外部路由变量，如 `wmsRoutes`）→ 提取 `path + element` 路由对；叠加静态路由 `auth.ts`（3）/ `common.ts`（3）/ `dashboard.ts`（11）/ `appRoutes.tsx` 硬编码（/performance、/core/users、/core/roles）。
- **页面文件**：组件 `@/pages/...` 映射 `src/pages/...tsx` 或目录形式 `.../index.tsx`（如 `mes/ProductionDashboardPage/`、`system/FeatureFlagPage/`）。
- **页面级测试**：同名测试（`<pdir>/__tests__/<Page>.test.tsx`、顶层 `src/pages/__tests__/<Page>.test.tsx`）或聚合测试 import 该页面路径。
- **API 接线**：页面文件内直接 import `@/api` / `@/services` / 相对 api/services 模块；间接层（hooks、统一 service 入口）不在本口径内。**2026-11-03 已对 52 页无直接 import 做全量链路复核**（含相对 import 与 store/hooks 目标文件 API 检查）。
- **三态**：页面源码 grep `isLoading/loading/skeleton`、`EmptyState/empty`、`error/ErrorBoundary`（近似统计，与 10-07 同口径）。
- **e2e**：`apps/web/e2e/**/*.spec.ts` 中 `page.goto('/...')` 路由去重后与全量清单对照。
