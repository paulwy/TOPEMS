## 0. 怎么用这份清单

- **A 组（103 族）**：证据充分，建议直接进执行；owner 只需扫一遍，**否掉不同意的**，其余默认通过。
- **B 组（34 族）**：证据不足或互相矛盾，**不作为执行依据**，每族写清了倾向结论与缺什么证据，需要 owner 定性。
- prod 侧**一律不列删除**：所有“prod”处置只有“标记历史残留、待归档”。删除动作只出现在 dev。
- 本清单只解决“权威表是谁”，列级归属随族定后再落（见主文档 §4）。

## 1. 判定规则与证据分级

| 级别 | 证据 | 说明 |
|---|---|---|
| L1 强 | **schema 限定名引用** | 代码里出现 `schema.table` 字面量（含 `only_own_schema_query!` 的 SQL 串）。给 `file:line` |
| L2 中 | **服务目录内裸名 SQL** | `svc/<svc>/` 下的 SQL 用裸表名，按服务 `SERVICE_SCHEMA` 绑定到该 schema（`analytics→bi`、`rd→rs`、`master-data→master_data`、`plugin-registry→core`、`unified-core→public`）。存在 search_path 回退风险 |
| L3 弱 | 数据 / 迁移 / 列数 / 约定 | 唯一有数据、迁移文件最新提及、列最完整、`core_*` 落 public 约定。仅作旁证 |

分级结论：`A1`=L1 唯一命中（高）；`A2`=无 L1 且 L2 唯一命中（中）；`B1`=多个成员都有 L1（冲突）；`B2`=L2 指向与数据落点矛盾；`B3`=0 引用、仅 L3 旁证（低，仅倾向）。

## 6. 方法学与复现

- 族定义：表名去掉 `core_` 前缀后同名归族；只保留含“一侧独有成员”的族。
- 列数：两侧 `information_schema.columns` 全量导出后按表计数。
- 行数：`pg_stat_user_tables.n_live_tup` 近似值 + 有 `updated_at/created_at` 的表取 `max()` 作为最近写入。
- 代码引用：HEAD 源码树倒排索引；`q`=限定名，`bare`=裸名且同行含 SQL 关键字（剔除注释行）；裸名按文件所在 `svc/<svc>` 映射 SERVICE_SCHEMA 归属。
- 迁移：扫描 `database/migrations/*.sql`，统计提及该表的版本数与最大版本；仅作旁证。
