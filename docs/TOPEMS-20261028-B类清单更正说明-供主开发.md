## 二、根因说明

1. **旧库表来源**：旧生产库的表由 `unified-core --init-db` + 各服务启动时 try_init 自建生成，该路径使用的建表 DDL 为过时/不完整版本，且 try_init 对建表失败静默吞错（core_migration_history 桩、_sqlx_migrations 表不存在即为佐证）。
2. **缺列表现**：旧库自建出的 suppliers/inbound_orders/projects/customers 等表缺少 name_en、order_date、approved_by、approved_at、cost_center_id、cost_center_name、organization_id 等列。
3. **服务代码无误**：handler SQL 与模型按权威表结构编写（引用上述列），旧库缺列 → 运行时报 `column does not exist` → 页面加载失败。此前据此将现象归类为"代码引用缺列"（B 类）。
4. **迁移 DDL 为权威版本**：database/migrations 499 个迁移文件包含全部上述列（含 align_missing_columns_selfheal 系列、各表收敛/对齐迁移）。全新迁移库建表结构完整 → 代码引用成立 → 页面全部正常。
