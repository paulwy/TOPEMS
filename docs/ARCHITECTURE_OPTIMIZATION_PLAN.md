## 二、目标架构设计

### 2.1 架构原则

| 原则 | 说明 |
|------|------|
| **高内聚低耦合** | 功能相近的服务聚合，保持代码模块化 |
| **渐进式演进** | 支持平滑过渡，不影响现有业务 |
| **可观测性** | 完善的监控和日志体系 |
| **容错性** | 服务故障不影响整体系统 |

### 2.2 服务分组设计

#### 核心服务组（Core Services）

**职责**：提供基础认证、文档管理、工作流引擎等核心能力

| 服务 | 原端口 | 聚合后路径 | 状态 |
|------|--------|------------|------|
| IAM | 8000 | /api/iam | ✅ 核心必需 |
| DOC | 8001 | /api/doc | ✅ 核心必需 |
| FLOW | 8006 | /api/flow | ✅ 核心必需 |
| AI | 8013 | /api/ai | ✅ 核心必需 |

**聚合方式**：单进程多路由，共享数据库连接池

#### 业务服务组（Business Services）

**职责**：提供业务领域服务，按需启动

| 服务 | 原端口 | 启动策略 | 优先级 |
|------|--------|----------|--------|
| ERP | 8010 | 按需 | 高 |
| HRM | 8011 | 按需 | 高 |
| CRM | 8012 | 按需 | 高 |
| PM | 8002 | 按需 | 中 |
| RS | 8020 | 按需 | 中 |
| PDM | 8023 | 按需 | 中 |
| MES | 8030 | 按需 | 中 |

#### 后台服务组（Background Services）

**职责**：异步任务处理、定时任务

| 服务 | 原端口 | 执行方式 |
|------|--------|----------|
| REPORT | 8053 | 定时任务 |
| MAIL | 8054 | 事件触发 |
| NOTIFICATION | 8003 | 事件触发 |
