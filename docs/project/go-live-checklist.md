### 9. 回滚计划

| 序号 | 触发条件 | 回滚步骤 | 预计时间 | 负责人 |
|------|---------|---------|---------|--------|
| 9.1 | 服务启动失败 | 1. 停止新版本服务<br>2. 回滚数据库迁移<br>3. 部署旧版本<br>4. 启动旧版本服务 | 30min | |
| 9.2 | 核心功能异常 | 1. 评估影响范围<br>2. 如无法快速修复则回滚<br>3. 执行回滚步骤 | 30min | |
| 9.3 | 性能严重下降 | 1. 检查资源使用情况<br>2. 如无法快速优化则回滚<br>3. 执行回滚步骤 | 30min | |
| 9.4 | 安全问题 | 1. 立即停止服务<br>2. 评估安全风险<br>3. 回滚到安全版本 | 15min | |
| 9.5 | 数据错误 | 1. 停止写入操作<br>2. 恢复数据库备份<br>3. 回滚应用版本 | 45min | |

**回滚命令：**
```bash
# 使用回滚脚本
./scripts/deploy/rollback.sh --version <previous-version>

# 或手动回滚
systemctl stop topems
# 恢复数据库备份
mysql -u root -p topems < backup.sql
# 切换到旧版本
ln -sfn /opt/topems/previous /opt/topems/current
systemctl start topems
```
