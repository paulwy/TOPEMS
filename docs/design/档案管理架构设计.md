# 档案管理架构设计

## 一、概述

档案管理系统是企业信息管理的重要组成部分，负责统一管理企业各类档案，包括文书档案、人事档案、财务档案、项目档案等。

## 二、设计原则

1. **统一管理，分散应用**：档案数据统一存储，各业务模块按需调用
2. **归档与档案分离**：业务文档 → 归档 → 档案，生命周期管理清晰
3. **权限分级控制**：档案查看、借阅、销毁等操作有严格的权限控制
4. **与文档中心协同**：复用文档中心的基础能力，避免重复建设
5. **标准化管理**：支持档号、分类、保管期限等档案管理标准

## 三、架构设计

### 3.1 模块划分

档案管理分为两个层次：

```
┌─────────────────────────────────────────────────────────────────┐
│                      业务层 (各模块)                             │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │  ERP档案 │ │  HRM档案 │ │  PM档案  │ │  CRM档案 │  ...     │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│                 档案服务层 (topems-doc 扩展)                    │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  档案管理模块 (Archive Module)                           │  │
│  │  - 档案分类管理                                           │  │
│  │  - 档案归档与移交                                         │  │
│  │  - 档案借阅与归还                                         │  │
│  │  - 档案鉴定与销毁                                         │  │
│  │  - 档案统计与报表                                         │  │
│  └─────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│              文档中心基础层 (topems-doc)                        │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ 文件管理 │ │ 文件夹   │ │ 版本管理 │ │ 权限管理 │  ...     │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 与文档中心的关系

| 维度 | 文档中心 | 档案管理 |
|------|----------|----------|
| **定位** | 通用文档协作与管理平台 | 专业的档案全生命周期管理 |
| **目标用户** | 全体员工 | 档案管理员、各部门归档人员 |
| **存储内容** | 日常工作文档、临时文件 | 具有保存价值的正式档案 |
| **编辑特性** | 支持实时协作编辑 | 只读为主，修改需走审批流程 |
| **版本管理** | 灵活的版本控制 | 规范的版本管理，不允许随意删除 |
| **权限模型** | 灵活的共享权限 | 严格的借阅、审批权限 |
| **生命周期** | 创建 → 编辑 → 归档（可选） → 废弃 | 创建 → 归档 → 保管 → 鉴定 → 销毁/永久保存 |

### 3.3 服务部署

档案管理作为 `topems-doc` 服务的扩展模块，与文档中心共享基础设施：

- **服务端口**：复用 8001 端口
- **数据库 Schema**：`doc_service` 下新增档案相关表
- **API 前缀**：`/api/v1/archives`

## 四、数据模型设计

### 4.1 档案分类表 (archive_categories)

```sql
CREATE TABLE doc_service.archive_categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    code VARCHAR(50) UNIQUE NOT NULL,          -- 分类编码
    name VARCHAR(100) NOT NULL,                -- 分类名称
    parent_id UUID REFERENCES doc_service.archive_categories(id),
    description TEXT,
    retention_period INT,                      -- 保管期限(年)，null表示永久
    sort_order INT DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by VARCHAR(255) NOT NULL
);
```

### 4.2 档案表 (archives)

```sql
CREATE TABLE doc_service.archives (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    archive_no VARCHAR(100) UNIQUE NOT NULL,   -- 档号
    title VARCHAR(255) NOT NULL,               -- 题名
    category_id UUID NOT NULL REFERENCES doc_service.archive_categories(id),
    file_id UUID REFERENCES doc_service.files(id),  -- 关联文档中心文件
    summary TEXT,                              -- 摘要
    keywords TEXT[],                           -- 关键词
    creator VARCHAR(255),                      -- 责任人
    created_date DATE,                         -- 形成日期
    retention_period INT,                      -- 保管期限(年)，覆盖分类默认值
    status VARCHAR(20) DEFAULT 'active',       -- active, archived, to_destroy, destroyed
    security_level VARCHAR(20) DEFAULT 'internal',  -- internal, confidential, secret, top_secret
    department_id UUID,                        -- 归属部门
    source_module VARCHAR(50),                 -- 来源模块(erp, hrm, pm等)
    source_id UUID,                            -- 来源业务ID
    archived_at TIMESTAMPTZ,                   -- 归档时间
    archived_by VARCHAR(255),                  -- 归档人
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by VARCHAR(255) NOT NULL
);

CREATE INDEX idx_archives_category_id ON doc_service.archives(category_id);
CREATE INDEX idx_archives_archive_no ON doc_service.archives(archive_no);
CREATE INDEX idx_archives_status ON doc_service.archives(status);
CREATE INDEX idx_archives_source ON doc_service.archives(source_module, source_id);
```

### 4.3 档案借阅表 (archive_borrows)

```sql
CREATE TABLE doc_service.archive_borrows (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    archive_id UUID NOT NULL REFERENCES doc_service.archives(id),
    borrower_id UUID NOT NULL,                 -- 借阅人ID
    borrower_name VARCHAR(255) NOT NULL,       -- 借阅人姓名
    borrow_reason TEXT NOT NULL,               -- 借阅原因
    borrow_type VARCHAR(20) NOT NULL,          -- view, download, physical
    borrow_date DATE NOT NULL,
    due_date DATE NOT NULL,                    -- 应还日期
    return_date DATE,                          -- 实际归还日期
    status VARCHAR(20) DEFAULT 'pending',      -- pending, approved, rejected, borrowed, returned
    approver_id UUID,                          -- 审批人ID
    approval_comment TEXT,
    approved_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by VARCHAR(255) NOT NULL
);

CREATE INDEX idx_borrows_archive_id ON doc_service.archive_borrows(archive_id);
CREATE INDEX idx_borrows_borrower_id ON doc_service.archive_borrows(borrower_id);
CREATE INDEX idx_borrows_status ON doc_service.archive_borrows(status);
```

### 4.4 档案销毁表 (archive_destructions)

```sql
CREATE TABLE doc_service.archive_destructions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    archive_id UUID NOT NULL REFERENCES doc_service.archives(id),
    reason TEXT NOT NULL,                      -- 销毁原因
    approver_id UUID NOT NULL,
    approved_at TIMESTAMPTZ NOT NULL,
    destroyed_at TIMESTAMPTZ,
    status VARCHAR(20) DEFAULT 'pending',      -- pending, approved, executed
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by VARCHAR(255) NOT NULL
);
```

### 4.5 档案元数据表 (archive_metadata)

```sql
CREATE TABLE doc_service.archive_metadata (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    archive_id UUID NOT NULL REFERENCES doc_service.archives(id),
    key VARCHAR(100) NOT NULL,
    value TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## 七、与业务模块的集成

### 7.1 ERP 模块集成

ERP 模块中的合同、财务凭证等可一键归档到档案管理：

```typescript
// 在 ERP 服务中调用档案 API
async function archiveContract(contractId: string) {
  const contract = await getContract(contractId);
  
  // 1. 上传合同文档到文档中心
  const file = await uploadToDocService(contract.document);
  
  // 2. 创建档案
  const archive = await archiveService.createArchive({
    title: contract.name,
    category_id: '合同档案分类ID',
    file_id: file.id,
    source_module: 'erp',
    source_id: contract.id,
    // ... 其他档案信息
  });
  
  return archive;
}
```

### 7.2 HRM 模块集成

人事档案、劳动合同等自动归档：

- 员工入职 → 自动创建人事档案
- 合同签订 → 自动归档合同文档
- 员工离职 → 档案状态变更

### 7.3 PM 模块集成

项目文档在项目结束后可批量归档：

- 项目验收 → 提示项目文档归档
- 一键归档项目相关文档到指定分类

## 八、权限设计

档案管理采用分级权限：

| 权限 | 说明 |
|------|------|
| archive.view | 查看档案目录 |
| archive.read | 查看档案详情 |
| archive.download | 下载档案文件 |
| archive.create | 创建档案 |
| archive.edit | 编辑档案信息 |
| archive.archive | 执行归档操作 |
| archive.borrow | 申请借阅 |
| archive.approve_borrow | 审批借阅申请 |
| archive.appraisal | 档案鉴定 |
| archive.destroy | 申请/审批销毁 |
| archive.admin | 档案管理员(所有权限) |
