# TOPEMS 性能优化指南

## 概述

本文档提供 TOPEMS 系统的性能优化最佳实践，包括后端服务、数据库、缓存、前端等各个层面的优化策略。

## 1. 后端服务优化

### 1.1 API 响应优化

- **连接池配置**：合理设置数据库连接池大小，避免连接耗尽
  ```yaml
  database:
    max_connections: 20
    min_connections: 5
    connection_timeout: 30
  ```

- **异步处理**：耗时操作使用异步任务队列，避免阻塞 API 响应
- **批量操作**：减少数据库往返，使用批量插入/更新
- **分页优化**：大结果集使用游标分页，避免 OFFSET 性能问题

### 1.2 并发优化

- **线程池配置**：根据 CPU 核心数调整线程池大小
- **限流策略**：实现令牌桶或漏桶算法，防止服务过载
- **熔断机制**：使用熔断器模式，防止级联故障

### 1.3 内存优化

- **对象池**：频繁创建销毁的对象使用对象池
- **流式处理**：大文件/大数据使用流式处理，避免内存溢出
- **及时释放**：大对象使用后及时释放引用

## 2. 数据库优化

### 2.1 查询优化

- **索引优化**：
  - 为常用查询字段创建索引
  - 避免在索引列上使用函数
  - 复合索引遵循最左前缀原则

- **查询分析**：
  ```sql
  EXPLAIN ANALYZE SELECT * FROM orders WHERE customer_id = 123;
  ```

- **避免 N+1 查询**：使用 JOIN 或批量查询

### 2.2 表结构优化

- **分区表**：大表按时间或范围分区
- **归档策略**：历史数据定期归档
- **字段类型**：选择合适的数据类型，避免浪费空间

### 2.3 连接池

- **连接数计算**：`连接数 = ((核心数 * 2) + 有效磁盘数)`
- **监控连接使用率**：及时调整连接池大小

## 3. 缓存优化

### 3.1 缓存策略

- **多级缓存**：本地缓存 + Redis 分布式缓存
- **缓存穿透**：使用布隆过滤器或缓存空值
- **缓存击穿**：热点数据使用互斥锁或永不过期
- **缓存雪崩**：过期时间加随机值

### 3.2 Redis 优化

- **数据结构选择**：
  - String：简单键值
  - Hash：对象存储
  - List：消息队列
  - Set：去重集合
  - ZSet：排行榜

- **内存管理**：
  - 设置 maxmemory-policy
  - 使用压缩列表节省内存
  - 定期清理过期键

### 3.3 缓存命中率监控

```
缓存命中率 = 命中次数 / (命中次数 + 未命中次数) * 100%
目标：> 90%
```

## 4. 前端优化

### 4.1 加载性能

- **代码分割**：按需加载，减少首屏体积
- **资源压缩**：Gzip/Brotli 压缩
- **CDN 加速**：静态资源使用 CDN
- **预加载**：关键资源使用 preload/prefetch

### 4.2 渲染性能

- **虚拟列表**：长列表使用虚拟滚动
- **防抖节流**：频繁触发的事件使用防抖/节流
- **懒加载**：图片/组件懒加载
- **避免重排重绘**：使用 CSS transform 替代 top/left

### 4.3 网络优化

- **HTTP/2**：启用多路复用
- **连接复用**：保持连接
- **请求合并**：减少请求数量
- **接口缓存**：GET 请求使用浏览器缓存

## 5. AI 服务优化

### 5.1 模型推理优化

- **批处理**：合并多个推理请求
- **模型量化**：使用 INT8/FP16 量化
- **模型蒸馏**：使用小模型替代大模型
- **缓存推理结果**：相同输入复用结果

### 5.2 向量检索优化

- **索引类型**：
  - HNSW：高召回率，内存占用高
  - IVF：平衡性能和内存
  - PQ：高压缩比，精度略有损失

- **参数调优**：
  - ef_construction：构建时的搜索广度
  - ef_search：查询时的搜索广度
  - nprobe：IVF 索引的探测聚类数

### 5.3 Agent 编排优化

- **并行执行**：无依赖的 Agent 任务并行执行
- **超时控制**：设置合理的超时时间
- **降级策略**：AI 服务不可用时使用规则引擎
- **结果缓存**：相似查询缓存结果

## 6. 监控与调优

### 6.1 关键指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| API 响应时间 P95 | < 500ms | 95% 请求响应时间 |
| API 响应时间 P99 | < 1000ms | 99% 请求响应时间 |
| 错误率 | < 0.1% | 5xx 错误占比 |
| 缓存命中率 | > 90% | Redis 缓存命中率 |
| 数据库连接使用率 | < 80% | 避免连接耗尽 |
| CPU 使用率 | < 70% | 预留扩容空间 |
| 内存使用率 | < 80% | 避免 OOM |

### 6.2 性能测试

使用 `scripts/performance/performance_test.py` 进行性能测试：

```bash
# 基本性能测试
python3 scripts/performance/performance_test.py --url http://localhost:8013

# 压力测试
python3 scripts/performance/performance_test.py --url http://localhost:8013 --concurrent 50 --duration 60

# 跳过压力测试
python3 scripts/performance/performance_test.py --skip-stress
```

### 6.3 调优流程

1. **监控发现问题**：通过监控指标定位性能瓶颈
2. **基准测试**：建立性能基线
3. **分析原因**：使用 profiling 工具分析
4. **实施优化**：针对性优化
5. **验证效果**：对比优化前后指标
6. **持续监控**：防止性能退化

## 7. 扩展策略

### 7.1 水平扩展

- **无状态服务**：API 服务可水平扩展
- **负载均衡**：使用 Nginx/K8s Service 分发请求
- **会话共享**：使用 Redis 存储会话

### 7.2 垂直扩展

- **资源升级**：增加 CPU/内存
- **数据库升级**：使用更高配置的数据库实例
- **读写分离**：主库写，从库读

### 7.3 微服务拆分

- **按业务域拆分**：独立部署和扩展
- **数据库分离**：每个服务独立数据库
- **事件驱动**：使用消息队列解耦

## 8. 常见问题排查

### 8.1 响应慢

1. 检查数据库慢查询日志
2. 检查缓存命中率
3. 检查外部服务调用耗时
4. 检查 GC 停顿

### 8.2 内存泄漏

1. 使用 profiling 工具分析内存
2. 检查未释放的资源
3. 检查缓存无限增长
4. 检查连接泄漏

### 8.3 连接耗尽

1. 检查连接池配置
2. 检查慢查询占用连接
3. 检查连接泄漏
4. 增加连接池大小
