# TOPEMS 性能测试最佳实践

## 概述

本文档描述 TOPEMS 系统性能测试的最佳实践，包括测试策略、指标定义、测试方法、结果分析和优化建议。

## 性能测试策略

### 测试类型

| 测试类型 | 目的 | 并发用户数 | 持续时间 | 执行频率 |
|---------|------|-----------|---------|---------|
| **烟雾测试 (Smoke)** | 验证基本功能和性能基线 | 5 VUs | 30秒 | 每次代码提交后 |
| **平均负载测试 (Average)** | 模拟正常使用场景下的性能 | 20 VUs | 2分钟 | 每日构建 |
| **压力测试 (Stress)** | 验证系统在高负载下的稳定性 | 50 VUs | 3分钟 | 每周/版本发布前 |
| **峰值测试 (Spike)** | 验证系统应对突发流量的能力 | 100 VUs | 1分钟 | 版本发布前 |
| **耐久测试 (Soak)** | 验证系统长时间运行的稳定性 | 10 VUs | 1小时 | 每月/大版本发布前 |

### 测试环境要求

1. **独立测试环境**：性能测试应在独立的环境中进行，避免与开发/测试环境共享资源
2. **生产环境配置**：测试环境的硬件配置应尽可能接近生产环境
3. **数据准备**：测试数据库应包含足够的测试数据（建议至少 10 万条记录）
4. **网络隔离**：测试环境应与其他环境网络隔离，避免网络干扰
5. **监控就绪**：确保 Prometheus、Grafana 等监控工具已配置并正常运行

## 性能指标定义

### 核心指标

| 指标 | 定义 | 目标值 | 告警阈值 |
|------|------|--------|---------|
| **响应时间 (p50)** | 50% 请求的响应时间 | < 500ms | > 1000ms |
| **响应时间 (p95)** | 95% 请求的响应时间 | < 2000ms | > 3000ms |
| **响应时间 (p99)** | 99% 请求的响应时间 | < 5000ms | > 8000ms |
| **吞吐量 (RPS)** | 每秒处理的请求数 | > 100 RPS | < 50 RPS |
| **错误率** | 请求失败的比例 | < 1% | > 5% |
| **CPU 使用率** | 服务器 CPU 使用率 | < 70% | > 85% |
| **内存使用率** | 服务器内存使用率 | < 75% | > 90% |
| **数据库连接数** | 活跃数据库连接数 | < 80% 最大连接 | > 90% 最大连接 |

### 业务指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| **AI 响应时间** | AI 服务生成响应的时间 | < 3000ms |
| **意图识别准确率** | 意图识别的准确率 | > 90% |
| **缓存命中率** | Redis 缓存的命中率 | > 80% |
| **会话完成率** | 用户会话成功完成的比例 | > 95% |

## 测试方法

### 1. 基线测试

**目的**：建立系统性能基线，作为后续优化的参考。

**步骤**：
1. 在干净的测试环境中运行烟雾测试
2. 记录所有核心性能指标
3. 将结果保存为基线数据
4. 每次性能测试后与基线对比

**命令**：
```bash
./scripts/performance/run-performance-tests.sh --scenario smoke
```

### 2. 负载测试

**目的**：验证系统在正常负载下的性能表现。

**步骤**：
1. 启动后端服务和数据库
2. 运行平均负载测试（20 VUs，2分钟）
3. 监控系统资源使用情况
4. 分析测试结果，识别性能瓶颈

**命令**：
```bash
./scripts/performance/run-performance-tests.sh --scenario average
```

### 3. 压力测试

**目的**：验证系统在高负载下的稳定性和容错能力。

**步骤**：
1. 确保测试环境资源充足
2. 运行压力测试（50 VUs，3分钟）
3. 监控系统是否出现错误或超时
4. 验证系统在高负载下的恢复能力

**命令**：
```bash
./scripts/performance/run-performance-tests.sh --scenario stress
```

### 4. 全场景测试

**目的**：全面验证系统在各种负载下的性能表现。

**步骤**：
1. 依次运行烟雾、平均、压力三种场景
2. 对比不同场景下的性能指标
3. 识别系统性能拐点
4. 生成完整的性能测试报告

**命令**：
```bash
./scripts/performance/run-performance-tests.sh --all
```

## 结果分析

### 结果解读

#### 响应时间分析

- **p50 < 500ms**：优秀，系统响应迅速
- **p50 500-1000ms**：良好，可接受
- **p50 > 1000ms**：需要优化，用户体验下降
- **p95/p50 比值 > 3**：存在长尾延迟，需要排查慢请求

#### 吞吐量分析

- **RPS 持续稳定**：系统处理能力稳定
- **RPS 随时间下降**：可能存在内存泄漏或资源耗尽
- **RPS 突然下降**：可能出现错误或超时

#### 错误率分析

- **错误率 < 1%**：优秀
- **错误率 1-5%**：可接受，但需要关注
- **错误率 > 5%**：严重问题，需要立即排查

### 常见性能问题

#### 1. 数据库查询慢

**症状**：
- 响应时间随数据量增加而显著上升
- 数据库 CPU 使用率高
- 慢查询日志中有大量慢查询

**解决方案**：
- 添加合适的数据库索引
- 优化 SQL 查询语句
- 使用查询缓存
- 考虑读写分离

#### 2. 内存泄漏

**症状**：
- 内存使用率随时间持续上升
- 系统运行一段时间后性能下降
- 需要频繁重启服务

**解决方案**：
- 使用内存分析工具定位泄漏点
- 检查是否有未释放的资源
- 优化对象创建和销毁逻辑
- 设置合理的内存限制

#### 3. 连接池耗尽

**症状**：
- 请求超时或失败
- 数据库连接数达到上限
- 错误日志中有连接超时错误

**解决方案**：
- 增加连接池大小
- 优化连接使用逻辑
- 检查是否有连接泄漏
- 使用连接池监控工具

#### 4. 缓存命中率低

**症状**：
- 数据库负载高
- 缓存命中率 < 50%
- 响应时间不稳定

**解决方案**：
- 优化缓存策略
- 增加缓存容量
- 调整缓存过期时间
- 使用多级缓存

## 性能优化建议

### 后端优化

1. **数据库优化**
   - 为常用查询字段添加索引
   - 避免 N+1 查询问题
   - 使用批量操作替代循环操作
   - 定期清理过期数据

2. **缓存优化**
   - 对热点数据使用 Redis 缓存
   - 实现合理的缓存失效策略
   - 使用本地缓存减少网络开销
   - 监控缓存命中率

3. **异步处理**
   - 将耗时操作改为异步处理
   - 使用消息队列解耦系统
   - 实现任务队列和后台处理
   - 避免在请求处理中执行耗时操作

4. **连接池优化**
   - 合理设置数据库连接池大小
   - 配置连接超时和空闲超时
   - 监控连接池使用情况
   - 避免连接泄漏

### 前端优化

1. **资源加载**
   - 使用代码分割和懒加载
   - 压缩和合并静态资源
   - 使用 CDN 加速资源加载
   - 实现资源预加载

2. **渲染优化**
   - 使用虚拟列表处理大数据
   - 避免不必要的重渲染
   - 使用 memo 和 useMemo 优化
   - 实现骨架屏提升用户体验

3. **网络优化**
   - 使用 HTTP/2 或 HTTP/3
   - 实现请求合并和去重
   - 使用请求缓存
   - 优化 API 响应数据量

### 基础设施优化

1. **服务器配置**
   - 根据负载调整服务器规格
   - 使用负载均衡分发请求
   - 实现自动扩缩容
   - 配置健康检查和自动恢复

2. **数据库配置**
   - 根据数据量调整数据库规格
   - 配置读写分离
   - 实现数据库主从复制
   - 定期备份和优化数据库

3. **监控告警**
   - 配置全面的性能监控
   - 设置合理的告警阈值
   - 实现告警通知和升级机制
   - 定期 review 监控数据

## 性能测试流程

### 定期性能测试流程

1. **测试准备**（测试前 1 天）
   - 确认测试环境可用
   - 准备测试数据
   - 确认监控工具正常运行
   - 通知相关人员

2. **执行测试**（测试当天）
   - 运行基线测试确认环境正常
   - 依次运行各种场景的测试
   - 记录测试过程中的异常
   - 保存测试结果和日志

3. **结果分析**（测试后 1 天）
   - 分析测试结果
   - 与基线数据对比
   - 识别性能问题和瓶颈
   - 生成性能测试报告

4. **优化跟进**（测试后 1 周）
   - 根据分析结果制定优化计划
   - 实施性能优化
   - 重新运行性能测试验证优化效果
   - 更新性能基线数据

### 版本发布前性能测试

1. **功能测试通过后**
2. **运行烟雾测试**确认基本功能正常
3. **运行平均负载测试**验证性能达标
4. **运行压力测试**验证系统稳定性
5. **性能指标达标后**方可发布
