## 二、两套凭证页面收敛（finance 权威）

**入口保持方式**：选择"路由保留原 path、只换届实现"（而非改菜单指向 finance 域），理由：
1. `/erp/voucher-management` 路径不变 → 已有书签、面包屑、外部链接全部有效；
2. 菜单标题与 `code`/`tier` 不变 → 菜单结构审计口径稳定；
3. 用户在 ERP 模块内仍能看到并点开凭证入口，落点是权威页。

### 2.3 权限码对齐（避免"菜单可见但接口 403"）

核查后端实际鉴权：

```
svc/finance/src/modules/mod.rs:290          security(("BearerAuth" = ["finance:voucher:read"]))
svc/finance/src/modules/cqrs_routes.rs:130  security(("BearerAuth" = ["finance:voucher:read"]))
svc/finance/src/modules/cqrs_routes.rs:56   security(("BearerAuth" = ["finance:voucher:write"]))
```

若 ERP 路由继续要求 `erp:general_ledger:read`，erp_manager 会**看到菜单但打开后列表 403**（因无 `finance:voucher:read`，DB 实测 erp_manager 对 `finance:voucher:*` 持有 0 条）。故把该路由的 `requiredPermissions` 对齐为 `finance:voucher:read` + `finance:dashboard:read`（与 finance 域 `finance-vouchers` 路由一致）。

**影响**：该 ERP 入口的可见性改由 `finance:voucher:read` 决定 —— admin / superadmin / finance_manager 可见；**erp_manager 不再可见**（原来可见但点了 403，属坏体验，现改为不可见，语义一致）。若产品希望 erp_manager 在 ERP 内也能看凭证，需给其授 `finance:voucher:read`（跨域只读授权），属权限决策，登记待拍板，本批不擅自动 DB。

`erp:general_ledger:read` 因此在本路由上不再被引用（该码本身保留在 DB，不删；若后续确认全站无其他引用，可登记清理）。
