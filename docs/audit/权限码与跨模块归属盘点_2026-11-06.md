# 权限码与跨模块归属盘点（P3 专项，2026-11-06）

> 对应整改计划 P3：权限码 FE/BE 统一、跨模块归属收敛。本文件为盘点结论与落地/登记清单，配套脚本 `scripts/audit_permission_codes.py` 可随时复跑。

## 一、权限码三端盘点

### 1.1 口径与规模

扫描口径：三端 `<module>:<resource>:<action>` 三段式权限码字符串。

| 端 | 扫描范围 | 码数 |
|---|---|---|
| FE | `apps/web/src/**/*.{ts,tsx}`（config.ts requiredPermissions、config/permissions.ts、microfrontend/config.ts、registry/core-modules.ts 等） | 433 |
| BE | `svc/**/*.rs`（axum `security()` 声明与权限常量） | 578 |
| DB | `database/init/*.sql` + `database/migrations/*.sql`（core_permissions 种子、权限同步迁移） | 890 |
| FE ∩ BE | 两端同码 | 119 |

> 说明：审计报告中的「FE 413 / BE 846」为 2026-11-01 口径；当前实况为 FE 433 / BE 578 / DB 890（期间新增迁移与前端页面）。差异属口径演进，非本轮引入。

### 1.2 四类差异

| 类别 | 定义 | 数量 | 代表项 |
|---|---|---|---|
| ① BE 有 FE 无 | 后端校验/DB 授权存在、前端未引用 | 459 | `admin:iam:write`、`ai:analysis:classify` |
| ② FE 有 BE 无 | 前端引用、后端 Rust 未声明（多数由 DB 授权兜底） | 314 | `admin:account:read`、`admin:dashboard:read` |
| ③ 命名不一致 | 同一语义两套/多套确切写法（归一化去 `_`/`-` 后同形） | **3 组** | 见 1.3 |
| ④ FE 孤儿 | 前端引用、BE 与 DB 均无 | 32 | 见 1.4 |

### 1.3 命名不一致（③，3 组，真实缺陷）

| 归一化 | 变体 | 出现端 | 证据 |
|---|---|---|---|
| `bi:datasource:read` | `bi:datasource:read` | BE（`svc/analytics/src/modules/bi/plugin.rs:76`） | 插件权限注册 |
| | `bi:data_source:read` | DB + FE（`database/migrations/20260908000014_sync_frontend_permission_codes.sql`、`apps/web/src/modules/bi/config.ts:120`） | 迁移同步脚本 + 前端 requiredPermissions |
| `mes:workorder:read` | `mes:workorder:read` | BE（`svc/mes/src/modules/work_order.rs:266,492`） | axum security 声明 |
| | `mes:work_order:read` | DB + FE（`database/migrations/20260724000004_seed_module_permissions.sql`、`apps/web/src/modules/mes/config.ts:1278`） | 权限种子 + 前端 |
| `wms:stocktake:read` | `wms:stock_take:read` | BE 内部（`grep wms:stock_take:read svc/`） | 同一后端两套写法 |
| | `wms:stocktake:read` | BE + DB + FE | 主流写法 |

**影响判定**：DB 授权的码（带下划线）与 BE 校验的码（无下划线）不一致 → 用户即使被授予权限，后端 `security()` 校验仍会拒绝（或反之），属真实功能缺陷。修复需 **DB 授权数据 + BE 校验声明 + 前端引用三端同时改**，涉及角色授权数据迁移与后端鉴权，**本轮不做**（按"无把握不动"约束），登记 P3 专项排期。

### 1.4 FE 孤儿（④，32 项）

| 子类 | 数量 | 项 | 判定 |
|---|---|---|---|
| `*:*:view`（action 命名不一致） | 17 | `ai/bi/crm/doc/ehs/erp/finance/gis/lims/monitor/pm/qms/srm:dashboard:view`、`finance:account:view`、`core:role:view`、`core:user:view`、`mes:workstation:view` | 其中 14 项有对应 `:read` 实码 → **本轮兼容修复**（见 2.1）；3 项需改模块名（`core:role:view→iam:role:read`、`core:user:view→iam:user:read`、`mes:workstation:view` 无对应 read）→ 登记 |
| 模块未实现/预留 | 7 | `lowcode:apps/form/page/workflow/dashboard:read`（5）、`network:*`（3）、`session:replay:*`（2） | 前端为未来模块预留，后端未实现 → 保留登记，不删 |
| 疑似事件/状态码误用 | 4 | `file:dashboard:write`、`registry:dashboard:read`、`shared:dashboard:read`、`admin/iam:dashboard:admin` | 逐一评估后再处理 → 登记 |

|---|---|---|---|

## 三、本轮落地与未落地

### 3.1 已落地

1. **权限码对账脚本** `scripts/audit_permission_codes.py`：三端扫描 + 四类分类 + 归一化命名冲突检出 + 证据（文件:行号）+ `--json/--summary`，可复跑、可接入 CI。
2. **`:view → :read` 兼容层**（`apps/web/src/hooks/usePermission.ts`）：`checkPermission` / `checkAnyPermission` / `checkAllPermissions` 对 `*:*:view` 做等价回退（先原码、后 `:read`），修复 14 项历史引用导致的"权限恒假 → 菜单/按钮被误隐藏"，**原引用不改**（待后端权限表补齐后再收敛），零破坏、无授权放宽（无对应 read 权限时仍拒绝）。
3. **测试**：`apps/web/src/hooks/__tests__/usePermission.test.ts` 新增 5 用例（read 命中 view 回退、无权限仍拒绝、非 view 码行为不变、any/all 回退、无权限不放行）。

### 3.2 未落地（登记）

| 项 | 原因 | 归属 |
|---|---|---|
| ③ 3 组命名双码（bi/mes/wms） | 需 DB 授权数据 + BE 校验声明 + FE 引用三端同改，涉及角色授权迁移 | P3 专项（需设计评审） |
| ① 459 项 BE-only 的"前端缺约束" | 需逐模块确认哪些应是菜单/按钮约束（数据量大、易误配） | P3 后续分批 |
| `core:role:view`→`iam:role:read` 等 3 项 | 涉及模块名改写，需确认 iam 权限语义 | P3 后续 |
| lowcode/network/session 预留码 | 后端未实现模块的预留，删除会造成未来返工 | 保留登记 |
| 供应商主数据权威、资产分类表归并 | 涉及数据迁移与跨服务改造 | P3/P5 专项 |
| tms 双写 | 当前代码无证据 | 观察项 |
