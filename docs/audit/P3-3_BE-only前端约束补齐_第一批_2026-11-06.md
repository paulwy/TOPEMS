# P3-3 BE-only 前端约束补齐（第一批 wms）

> 批 7。承接 v1.129 建议：① 45X 项 BE-only 权限码的前端约束补齐，按模块分批，只补**有 UI 落点**的码。

## 一、盘点结论

`be_only` 共 456 项，按模块分布（Top）：

| 模块 | 数量 | 前端落点可补性 |
|---|---|---|
| portal | 58 | 平台层（登录/租户/网关），按钮边界弱 → 不补 |
| mobile | 44 | BFF 聚合 + 移动端入口，本轮不动 |
| mes | 36 | 强（工单/生产/排产/设备/质量页面齐全） |
| scm / wms | 24 / 24 | 强（采购、入库、盘点、库位页面齐全） |
| crm / erp / analytics / master_data / finance / ehs / srm | 17-22 | 中 |

action 分布：`write` 214、`read` 182、`admin` 27，其余为业务动作（approve/start/complete 等）。

**本批选择 wms**：be_only 24 项，页面落点明确（入库单、盘点、库位、批次等），worst-case 影响可控。

## 二、落点判定规则（避免误配/误隐藏）

1. 只补页面**已有对应操作按钮**的码；页面无按钮（纯后端能力）一律不造 UI。
2. 只做"按钮隐藏/禁用"，不改业务逻辑与后端。
3. 未授权用户看到的是"无按钮"或"按钮禁用"，而非报错。

## 三、本批落地（3 个码）

| 码 | 落点 | 做法 |
|---|---|---|
| `wms:inbound_order:write` | `apps/web/src/pages/wms/InboundOrderPage.tsx` | `crud.showCreateButton: checkPermission('wms:inbound_order:write')`，无权限不显示"新建"按钮 |
| `wms:stocktake:write` | `apps/web/src/pages/wms/StockTakePage.tsx` | "录入盘点数""完成盘点"按钮条件加 `canWrite`；"提交盘点数"按钮 `disabled={!canWrite}` |
| `wms:stocktake:admin` | 同上 | "调整库存"按钮条件加 `canAdmin`（管理动作） |

实现复用既有 `usePermission().checkPermission`（与 v1.128 的 `:view→:read` 兼容层叠加生效），未引入新依赖、未改公共模板。
