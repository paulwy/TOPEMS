## 1. Docker 部署轮换（docker-compose 栈）

```bash
cd <部署目录>
# 1) 生成新随机密码并写入 docker/.env（已有则原地替换）
NEW_PG=$(openssl rand -hex 16)
NEW_REDIS=$(openssl rand -hex 16)
NEW_RABBIT=$(openssl rand -hex 16)
sed -i "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$NEW_PG/" docker/.env
# 按需补 Redis/RabbitMQ 键（自 2026-10-07 起 compose 强制要求，缺失即启动失败）

# 2) 数据库数据卷用旧密码初始化过，POSTGRES_PASSWORD 仅在首次初始化生效——
#    轮换密码必须重建 postgres 卷（数据如需保留先 pg_dump 备份）
docker compose down
docker compose rm -f postgres   # 仅删除 postgres 容器
docker volume rm <栈名>_postgres_data 2>/dev/null || true   # 重建卷（先备份！）

# 3) 启动并验证
docker compose up -d
docker compose exec postgres pg_isready -U "$(grep POSTGRES_USER docker/.env | cut -d= -f2)"
docker compose ps
```

**Redis/RabbitMQ**：密码同样强制注入；如 Redis 之前无密码且未暴露公网，可在 `.env` 设置 `REDIS_PASSWORD` 后启动（旧无密码实例需先 `FLUSHALL`/迁移数据再设密码）。

## 2. Kubernetes 轮换（k8s 栈）

```bash
# 1) 创建/更新 Secret（数据由 kubectl 注入，不落仓库）
kubectl create secret generic topems-secrets -n topems \
  --from-literal=POSTGRES_PASSWORD=$(openssl rand -hex 16) \
  --from-literal=DATABASE_URL="postgres://topems_app:$(openssl rand -hex 16)@postgres-service:5432/topems" \
  --dry-run=client -o yaml | kubectl apply -f -

# 2) configmap.yaml 的占位值（CHANGE_ME_DEPLOY_SECRET）部署时必须替换：
#    · 方式 A（推荐）：改 deployment 为 secretKeyRef 引用上述 Secret，configmap 不再含密码
#    · 方式 B：kubectl patch configmap 覆盖为真实密码（仍会落 etcd，安全性低于 A）
kubectl rollout restart deployment -n topems   # 滚动重启使注入生效

# 3) 验证
kubectl get pods -n topems
kubectl logs -n topems <pod> --tail=50   # 确认无认证失败
```

## 3. 验证清单

- [ ] `docker compose config -q`（docker 栈）通过，无 `required variable ... is missing`
- [ ] 应用日志无 `password authentication failed` / `Access denied`
- [ ] `curl <gateway>/api/core/health` 返回 200
- [ ] Redis `AUTH` 生效（若设置密码）：`redis-cli -a <新密码> ping` → PONG
- [ ] gitleaks/secret 扫描不新增真实密码命中

## 4. 回滚

- 轮换前保留旧密码记录（如 `docker/.env.bak.$(date +%Y%m%d)` 或运维密码库），失败时恢复旧值并重启；**旧值仅作回滚用，轮换成功后即销毁**。
- k8s 回滚：`kubectl rollout undo deployment -n topems`（Secret 需同步还原旧值）。

## 5. 长期安全项

- 禁止任何部署默认密码落仓库（已由 `:?` 强制注入 + CI 门禁保障）
- 建议引入外部密钥管理（Vault/云厂商 Secret Manager/SealedSecrets）替代 kubectl 手管 Secret
- GitHub Security 页：确认旧 commit 告警已随历史清理消失；如有仍标记的告警，人工关闭
