## 四、供应商分类字典（解决跨源分裂）

### 4.1 问题

`master_data.mdm_suppliers` 的 `category` 为**自由文本列**，两来源取值分裂：

| source_system | category 原值 | 行数 |
|---|---|---|
| scm | `raw_material`（英文） | 195 |
| srm | `原材料`（中文） | 92 |

### 4.2 建字典表（迁移 `20261107000031`）

`master_data.mdm_supplier_categories`：

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | uuid PK | `gen_random_uuid()` |
| `code` | varchar NOT NULL | 规范化代码，**`UNIQUE`** |
| `name_zh` | varchar NOT NULL | 中文名 |
| `name_en` | varchar | 英文名 |
| `source_values` | jsonb | 各来源原始取值映射 |
| `description` / `sort_order` / `status` / `created_at` / `updated_at` / `deleted_at` / `tenant_id` | — | 同 schema `mdm_*` 惯例 |

- **RLS `ENABLE + FORCE` 双开**，策略表达式**照抄同 schema `mdm_suppliers` 的 `tenant_isolation_mdm_suppliers`**（不自创）
- `topems_app` 授 SELECT/INSERT/UPDATE/DELETE
- 索引 `code` / `status`
- 全文 `IF NOT EXISTS` + 策略 `DO $$ ... pg_policies` 幂等

### 4.3 种子（实测取值）

| code | name_zh | name_en | source_values |
|---|---|---|---|
| `raw_material` | 原材料 | Raw Material | `{"scm":"raw_material","srm":"原材料"}` |

| **`GET`** | `/api/master-data/supplier-categories` | **分类字典（本批新增，只读）** |

### 5.2 关键设计

- **`source_system` 强制 `'mdm'`**、`source_id` 为 `NULL`；**客户端不可覆盖**这两个溯源字段（只由系统写）
- **唯一约束冲突正确报错**：捕获 sqlx `23505` → 返回 **400 `供应商编号已存在`**，不是 500、不静默吞
- **`category_code` 校验而非硬编码映射**：请求给了 `category_code` 就校验其存在于字典表（`status='active'` 且未软删），不存在则 400 `供应商类别编码 'xxx' 在字典表中不存在或未启用`；只给 `category` 不给 `category_code` 时允许 `category_code` 留 NULL——**Rust 里不硬编码中英文映射表**
- **软删语义**：`DELETE` 只 `SET deleted_at = now()`，**绝不物理删除**；软删后 list 排除、get 返回 `404 未找到: 供应商不存在`
- **必填校验前移**：`supplier_no` / `name` / `status` / `risk_level` 缺失返回 400 + 明确字段名，不撞 DB 约束报 500
- **权限**：沿用服务级 `require_module_access("master-data")` 模块级门（`main.rs:69-71`），**本批不新建任何权限码**（用户明确要求）
- 模块头注释同步改为完整 CRUD 描述（原「本模块**只读**」的表述已过时）

## 十、经验固化

1. **「宁缺勿假」包括 `0`**：把随机值改成 `0` 看似"安全"，实际更有害——`0` 看起来完全可信，会被读成"真实统计确实是 0"。正确做法是**空数组/空图表/移除卡片/明确"未接入"**。本批第一轮曾把 18 处改成 `0`，被打回返工为 `[]`。
2. **可达性判定要有三重证据**：路由注册 + 菜单项 + 权限码。本批 `MobileScanPage` 正是靠这三项确认"用户点得到"（`/mobile/scan-page` + `mobile.nav.mobile-scan` + `mobile:scan:read`），从而必须处理；反之微前端模块无任一引用才可保留。
3. **字典不预造未出现的值**：实测 `GROUP BY` 只有 2 个取值 → 字典只建 1 行 code，不凑满完整分类体系。
4. **规范化列与自由文本列并存要登记**：加 `category_code` 不等于删 `category`，两者并存需产品确认去向，不能擅自删列。
5. **迁移文件名避开 `test`**：批 32 的坑，本批已规避并实测 `directed-migrations` 命中 0。
