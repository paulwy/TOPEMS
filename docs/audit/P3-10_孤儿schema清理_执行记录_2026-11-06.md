## 一、`schemas/erp/voucher.ts` 搬家：**判定不成立，不搬**

批 19 登记的"搬家"前提是"数据走 finance、仅目录位置错"。本批核实后发现前提不成立：

| 核实点 | 证据 | 结论 |
|---|---|---|
| `schemas/finance/voucher.ts` 是否已存在 | 已存在，`:16` `export const voucherSchema`，且 `schemas/finance/index.ts:12` 导出 | **目标文件已占位** |
| `schemas/erp/voucher.ts` 是否孤儿 | `pages/erp/VoucherPage.tsx:17` `import { voucherSchema } from '@/schemas/erp/voucher'`；该页面在 `modules/erp/config.ts:169` `lazyWithRetry(() => import('@/pages/erp/VoucherPage'))` 注册路由 | **活文件，被活页面消费** |
| 两个文件是否同一份内容 | `diff` 差异 511 行 | **两个不同 schema** |
| finance 侧谁在用 | `pages/finance/FinanceVoucherPage/index.tsx:32` `import { voucherSchema, accountingSubjectSchema } from '@/schemas/finance'` | **另一个活页面** |

**结论**：`schemas/erp/voucher.ts` 与 `schemas/finance/voucher.ts` 服务于**两个不同的活页面**（ERP 域 `pages/erp/VoucherPage.tsx`、Finance 域 `pages/finance/FinanceVoucherPage/index.tsx`），不是"同主题两版并存"，也不是孤儿。搬家会覆盖 finance 侧已占位的同名文件、并破坏 erp 页面的 import，**不执行搬家**。

批 19 只订正了 `api.module` 声明这一项是对的（该字段确无运行时用途），但"移动目录"的依据不足。真正的遗留问题是**两个凭证页面功能重复**（ERP 域与 Finance 域各一套凭证 CRUD），属产品级去重决策，登记待拍板，本批不动。

### 2.3 一次误删与回滚（如实记录）

初次执行时删除了 `schemas/wms/outbound.ts` 并移除 `schemas/wms/index.ts:3` 的导出行，随即 `pnpm --filter topems-portal typecheck` 报出：

```
src/pages/wms/OutboundOrderPage.tsx(14,10): error TS2724: '"@/schemas/wms"' has no exported member named 'outboundOrderSchema'
src/pages/wms/OutboundPage.tsx(11,10): error TS2724: '"@/schemas/wms"' has no exported member named 'outboundOrderSchema'
```

**根因**：批 3 删除的是 `pages/wms/WmsOutboundOrderPage.tsx`（带 `Wms` 前缀），而 `pages/wms/OutboundOrderPage.tsx` 与 `pages/wms/OutboundPage.tsx` 是**另外两个活页面**，仍在使用 `outboundOrderSchema`。初次人工 grep 时用了 `| head -8`，输出被前面的测试文件行占满，页面引用被截断，导致误判为孤儿。

**处置**：立即 `git checkout -- apps/web/src/schemas/wms/outbound.ts apps/web/src/schemas/wms/index.ts` 回滚，并改用**不截断的全量 grep** 复核；tsc 复跑 0 error。

教训：清理类批量判断不能依赖带 `head` 的截断输出；以"符号级扫描 + 不截断 grep + tsc 兜底"三层交叉验证。
