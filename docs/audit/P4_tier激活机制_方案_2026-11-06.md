# P4 tier 激活机制：现状与方案（2026-11-06）

> 批 8。结论：**停在方案阶段**，不落地（标注 3 项评审）。原因见第五节。

## 一、现状（取证）

### 1.1 DB

`core_tenant_modules` 建表定义在 `database/init/06_iam_schema.sql:841`：

```
id uuid, tenant_id uuid, module_code varchar(64), module_name varchar(128),
is_active boolean default true, activated_at timestamptz, expires_at timestamptz, deleted_at timestamptz
UNIQUE (tenant_id, module_code)
```

- **无 `tier` 列**。
- 本地库实测**该表在 4 个 schema 各一份**：`public` / `iam` / `flow` / `mes`；数据行数 0（空表）。

### 1.3 FE

`apps/web/src` 无 `tenant_modules` / 模块 tier 的消费逻辑（仅 plugin uninstall 的 `tier` 参数，语义无关）。菜单渲染（`GlobalLayoutV3`/`SideRail`）目前**不读租户模块激活状态**。

## 二、语义设计（建议）

### 2.1 三级 tier

| tier | 含义 | 典型模块 |
|---|---|---|
`basic` | 基线套件，所有租户默认激活 | portal、iam/core、admin、dashboard |
`standard` | 标准业务套件 | mes、wms、scm、crm、erp、qms |
`enterprise` | 增值套件 | analytics/bi、srm、tms、gis、lims、ehs、mobile、ai、automation |

### 2.2 激活/停用语义

- 激活：`is_active = TRUE`，`activated_at = now()`；可选 `expires_at`（试用/订阅到期）。
- 停用：`is_active = FALSE`（软停用，不删行，便于恢复与审计）。
- 生效判定：`is_active AND (expires_at IS NULL OR expires_at > now()) AND deleted_at IS NULL`。

### 2.3 与菜单/权限可见性的关系（双层）

1. **菜单层**：`GlobalLayoutV3.buildSidebarItems` 增加一级过滤——租户激活模块集合之外的一级模块不下发（模块级整块隐藏，而非逐项）。
2. **权限层**：不改 IAM 权限模型；未激活模块的权限码仍存在于权限表（避免授权丢失），仅在菜单/路由入口不可达。路由层保留 `ProtectedRoute` 现有权限校验。
3. **兜底**：租户无任何激活记录时按 `basic` 全集放行（兼容存量的"未初始化"租户，避免一键上线导致全站菜单消失）。

## 三、落地所需的改动（供评审后执行）

1. **DB**：`ALTER TABLE core_tenant_modules ADD COLUMN IF NOT EXISTS tier varchar(32) NOT NULL DEFAULT 'basic';`（幂等；回滚 `DROP COLUMN`，需先备份）
2. **BE**：handler SQL 与列对齐（402/727 行的 tier 读写保留，语义按 2.1）；激活/停用加 `expires_at` 判定。
3. **FE**：`useTenantModules()` hook（GET 租户激活模块，5 分钟缓存）+ `GlobalLayoutV3` 一级模块过滤 + 兜底放行。
4. **数据**：`core_tenant_modules` 初始化脚本（为现有租户按 tier 预置 basic 全集），幂等 `INSERT ... ON CONFLICT (tenant_id, module_code) DO NOTHING`（该表有唯一约束，可用）。

## 四、可回滚性评估

| 项 | 幂等 | 可回滚 |
|---|---|---|
| 补 tier 列 | ✅ `ADD COLUMN IF NOT EXISTS` | ⚠️ `DROP COLUMN` 会丢 tier 数据（执行前备份） |
| 预置激活记录 | ✅ `ON CONFLICT DO NOTHING` | ✅ `DELETE ... WHERE activated_at >= 批次时间` |
| FE 菜单过滤 | — | ✅ 特性开关 `tenantModulesFilterEnabled` 默认 false，回退即关闭 |

## 五、为什么本批不落地（评审项）

1. **tier 分级未经产品确认**：basic/standard/enterprise 的模块归属是产品定价决策，不能由工程擅定。
2. **表在 4 个 schema 漂移**（public/iam/flow/mes）：此时加列/预置数据会加剧副本不一致，须先完成 P5 副本归一（批 9）。
3. **存量租户影响不可控**：本地库 tenants 数据为空，无法评估"上线即过滤菜单"对真实租户的冲击；需真实环境灰度。

**评审需拍板**：① tier 分级与模块归属；② 菜单过滤是否默认开启（灰度策略）；③ 与 P5 副本归一的先后顺序（建议 P5 先行）。
