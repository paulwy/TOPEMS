## 三、未落地项及原因（已登记）

### 1. FE 菜单过滤（拍板项 2）——**不落地**

拍板要求"按 `is_active AND (expires_at IS NULL OR expires_at > now())` 判定菜单可见性，无激活记录租户兜底放行"。

取证发现的**结构性阻碍**：`core_tenant_modules.module_code` 的取值体系是 `erp:addressbook`、`pm:*` 这类**功能模块级**（`BASIC_MODULE_CODES` 50 条，前缀仅 `erp` / `pm` 两个）；而 FE 一级菜单的 code 是 **35 个业务域**（`mes` / `wms` / `scm` / `crm` / `erp` …）。两套体系层级不同，无法直接映射。

若强行按"module_code 前缀 == nav code"过滤，导航只会保留 `erp`/`pm` 两组，**其余 30+ 模块全部消失**——属于会直接打挂应用的功能性破坏，不做。

**登记**：需先定义 `module_code → 一级 nav code` 映射表（或把 tier 机制整体改到业务域级），属设计决策，待评审。

### 2. tier 三级命名不一致

- 拍板：`basic / standard / enterprise`；
- 代码注释（`models.rs:166`）：`'basic' | 'advanced' | 'infrastructure'`；
- `activate_basic_modules` 只写 `'basic'`。

**登记**：与第 1 项一并处理（统一为 basic/standard/enterprise 需同时确认 module_code 体系）。

### 3. 租户激活数据为空

`public.core_tenant_modules` 0 行（703 个租户均无激活记录）→ 按拍板的"无记录兜底放行"，当前即使实现 FE 过滤也不会隐藏任何菜单，行为不变。这也意味着 FE 过滤可安全延后。
