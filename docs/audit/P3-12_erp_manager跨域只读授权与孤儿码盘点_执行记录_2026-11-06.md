# P3-12 erp_manager 跨域只读授权与"无人引用权限码"盘点（批 22，2026-11-06）

## 一、背景：批 21 收敛带出的两个待拍板项

批 21 把 ERP 凭证入口（`/erp/voucher-management`）的落点收敛到 finance 权威页 `FinanceVoucherPage`，
后端 `/finance/vouchers` 实际鉴权码为 `finance:voucher:read`（`svc/finance/src/modules/mod.rs:290`、
`cqrs_routes.rs:130`）。由此产生两个待决策项：

1. `erp_manager` 对 `finance:voucher:*` 持有 **0 条** → 保留 ERP 入口却对 ERP 角色不可用（拍板：补只读）。
2. `erp:general_ledger:read` 从该路由摘除后是否为孤儿（需三端核实后才能决定删否）。

## 二、`erp:general_ledger:read` 三端盘点（结论：保留，不删）

全量 grep（不截断），实测引用如下：

| # | 位置 | 性质 | 判定 |
|---|------|------|------|
| 1 | `apps/web/src/modules/erp/config.ts:597` | navItem `erp-general-ledger` 的 `permission` | **活引用**（决定菜单可见性） |
| 2 | `apps/web/src/config/menuPermissions.ts:66` | `'/erp/accounting-management': 'erp:general_ledger:read'` | 所在文件**全站零引用 = 死文件**（见第三节），且该映射本身已过期（实际 `accountingManagementRoute` 用 `erp:accounting_subject:read`，`config.ts:421`） |
| 3 | `apps/web/src/config/permissions.ts:542` | `PERMISSION_DEFS` 清单条目（`Record<string,string>` 自映射） | 非判定引用：该表仅用于 dev 期"重复键完整性自检"（`permissions.ts:920-931`，`ALL_3PART_PERM_CODES` 只参与重键检测），**不参与运行时权限判定** |
| 4 | 后端 `svc/` `lib/` `database/init/` | 零命中 | — |
| 5 | DB | 码 1 条（`erp:general_ledger` / `read`）+ 授权 2 条（admin、superadmin） | 有授权但无 manager 消费 |

**结论**：唯一活引用是 #1 的 navItem，而该 navItem 指向的正是已收敛到 finance 的凭证功能。
本批把它对齐为 `finance:voucher:read` 后，该码的**活引用归零**，但仍在 #3 的自检清单与 DB 中存在。

按纪律（删码前必须三端零引用核实、有引用则保留并登记）→ **保留该码，登记**。
后续若要清理，需连同 `PERMISSION_DEFS` 条目一起处理，属独立清理项。

## 三、顺带清掉的死文件：`config/menuPermissions.ts`（169 行）

盘点 #2 时发现该文件全站零引用：

```
grep -rn "menuPermissions" apps/web scripts packages --include=*.ts --include=*.tsx --include=*.mjs --include=*.py | grep -v "^apps/web/src/config/menuPermissions.ts:"
→ （空）
```

该文件是一份"路由路径 → 权限码"映射表（169 行），与 `navItem.permission` 构成双轨，
但**没有任何代码消费它**，且其中多条已与真实路由的 `requiredPermissions` 不一致（如
`'/erp/accounting-management': 'erp:general_ledger:read'` vs 实际 `erp:accounting_subject:read`）。

→ 删除。理由：零引用 + 内容过期，留着只会误导后续排查。

## 四、菜单与路由权限双轨不一致（批 21 遗漏，本批修）

| 声明位置 | 批 21 状态 | 批 22 处置 |
|---|---|---|
| `voucherRoute.requiredPermissions`（`config.ts:180`） | `['finance:voucher:read','finance:dashboard:read']` | 收敛为 `['finance:voucher:read']` |
| navItem `erp-general-ledger.permission`（`config.ts:599`） | `'erp:general_ledger:read'`（旧码，未随路由同步） | 改为 `'finance:voucher:read'` |

两处不一致的后果：菜单按 erp 码判定可见、路由按 finance 码判定可进 →
`erp_manager` 会"看到菜单点进去 403"。本批让两处同源。

**同时移除多余要求 `finance:dashboard:read`**：实测 `FinanceVoucherPage/index.tsx` 全文只有
一处 `navigate(FINANCE_PATHS.dashboard)`（`:700`，一个跳转按钮），**不消费 dashboard 数据**。
保留它会让"只有 voucher:read 的角色"仍被挡住，属过度授权要求 → 移除。

新增契约断言（`erpVoucherRouteContract.test.ts` 第 6 例）：扫描 `path: ERP_PATHS.voucherManagement`
后的 navItem `permission`，断言必须为 `finance:voucher:read` → 锁住双轨一致，防回潮。

## 五、erp_manager 跨域只读授权（迁移 `20261107000010`）

```sql
INSERT INTO public.core_role_permissions (role_id, permission_id, created_at)
SELECT r.id, p.id, now()
FROM public.core_roles r
JOIN public.core_permissions p ON p.code = 'finance:voucher:read'
WHERE r.name = 'erp_manager'
  AND NOT EXISTS (SELECT 1 FROM public.core_role_permissions x
                  WHERE x.role_id = r.id AND x.permission_id = p.id);
```

- 只补 **read**，不补 write —— ERP 角色不获财务写权限，保持最小权限。
- 幂等：实跑首次 `INSERT 0 1`，二次 `INSERT 0 0`。
- 未新建权限码 → `core_permissions` 仍 **1087** 条（对账 db 计数不变）。
- 已附 ROLLBACK 段（DELETE 该 role×permission 组合）。

**授权后 `finance:voucher:read` 持有者（DB 实测）**：admin、superadmin、finance_manager、**erp_manager**。

## 六、"无人引用权限码"盘点（登记，不盲删）

对账脚本口径 `db_only` = 653 条（DB 有、静态扫描未在前端/后端源码里出现字面）。
但静态扫描**看不到 CrudPage 的运行时拼码**（`resolveCrudPermissionCodes` 按
`permissionResource` 动态拼出 `模块:资源:create|update|delete`），故 653 不能直接当孤儿清单。
按 `permissionResource` 覆盖情况重新分类：

| 分类 | 条数 | 说明 |
|---|---|---|
| 已被 `permissionResource` 覆盖（运行时真实使用） | **217** | 77 个去重前缀（批 16~19 接入的 schema）动态拼码，**不是孤儿** |
| 未被覆盖（候选） | **436** | 见下 |

候选 436 条按动作拆分：

| 动作 | 条数 | 性质判定 |
|---|---|---|
| create / update / delete | 409（136 / 137 / 136） | **已建码但对应页面尚未接入 `permissionResource`** → 属"接入待办"，删码会阻断后续接入，**保留** |
| read | 13 | 需逐条人工判定（可能是模块占位码） |
| write | 12 | 同上 |
| approve / tenant | 各 1 | 需人工判定 |

候选按模块分布（前 10）：finance 70、hrm 34、pdm 33、rd 33、srm 33、wms 33、crm 28、qms 24、lims 21、ehs 20。

**结论**：436 条中 409 条为 CRUD 细码，属"建码已到位、页面接入未完成"，不应删；
剩余 27 条（read 13 / write 12 / approve 1 / tenant 1）登记待人工逐条判定，本批不动。
