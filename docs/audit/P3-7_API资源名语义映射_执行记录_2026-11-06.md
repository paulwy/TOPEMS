# P3-7 API 资源名 → DB 权限资源名 语义映射（批 17 执行记录）

> 执行日期：2026-11-06　批次：批 17（承接批 16 遗留）
> 目标：把批 16 盘点出的 69 个「FE 资源名 ≠ DB 资源名」页面逐条语义映射，可映射的接入 `permissionResource`，其余登记。

## 1. 问题本质：两套命名空间

批 16 已确认，但本批逐条验证后进一步坐实：

| 体系 | 取值形态 | 来源 | 示例 |
|---|---|---|---|
| API 资源名 | camelCase 复数 | `EntitySchema.api.resource`（前端路由/接口路径） | `purchaseOrders` / `orders` / `boms` / `inboundOrders` |
| DB 权限资源名 | snake_case 单数业务实体 | `core_permissions.resource`（`模块:资源` 或 `模块_资源`） | `purchase_order` / `production_order` / `bom_version_policy` / `inbound` |

两者**不能机械推导**：`orders` → 不是 `order` 而是 `production_order`；`boms` → 不是 `bom`；
`inboundOrders` → 不是 `inbound_orders` 而是 `inbound`。因此本批采用「逐条读 `entity` + API 方法 + DB 资源清单」的人工语义判定，
不依赖字符串相似度（相似度最高的候选多次是错误答案，例如 `mes:materialIssues` 相似度最高是 `mes:material`，
但领料单 ≠ 物料主数据）。

**新建资源的语义依据（为何不与既有资源合并）**：
- `mes:material_issue` / `material_requirement` / `material_return` ≠ `mes:material`：后者是**物料主数据**（物料的编码/规格/分类），前者是**领料单/物料需求单/退料单**业务单据，写权限语义完全不同（给物料主数据写权限≠给领料单写权限）。
- `scm:incoming_inspection` ≠ `scm:supplier_admission`：后者是**供应商准入**（供应商资质审核），前者是**来料检验**（到货物料的检验单）。
- `scm:incoming_notice` ≠ `scm:delivery_appointment`：后者是**送货预约**（供应商预约送货时间），前者是**到货通知**（仓库侧到货登记）。
- `finance:accounting_subject` ≠ `finance:ledger`：后者是**总账**，前者是**会计科目**（科目表维护）。
