## 一、对账脚本口径改源（核心变更）

### 1.1 改什么

| 项 | 改前 | 改后 |
|---|---|---|
`db` 集合来源 | `scan_codes('database/init') + scan_codes('database/migrations')`（扫 SQL 文件） | `SELECT code FROM public.core_permissions`（live DB） |
SQL 声明集 | 并入 `db` 集合 | 独立输出 `code_drift.sql_only_never_persisted` / `db_only_not_in_sql` |
连接串 | — | `--dsn` > 环境变量 `TOPEMS_AUDIT_DSN` > 内置本机默认 |
失败处理 | — | psql 不可用/连接失败 → 回退 SQL 扫描，并在输出标注 `db_source: sql_fallback` 与原因 |
输出 | 无口径标识 | 新增 `db_source`、`db_source_error`、`code_drift` 三个字段；summary 首行打印来源与漂移 |

### 1.2 为什么改

改前口径把两类无关噪音混进 `db_only`：

- **SQL-only（声明了但从未落库）**：如 `finance:counterparty:write`、`admin:iam:tenant` 等，DB 里 `count(*)=0`，删无可删。
- **DB-only（历史迁移链建了但 SQL 无声明）**：如 `admin:iam:dashboard:approve`、`ai:admin` 等，属存量迁移遗留。

批 25 因此产生过一次判断风险：删除对象一度以 SQL 声明为准，实测 94 项候选里只有 92 项在 DB 有行，另 2 项（`finance:budget:approve`、`finance:report:write`）纯属 SQL 声明。

### 1.3 实施细节

- SQL 查询限定标准三段码：`code ~ '^[a-z][a-z0-9_]*:[a-z][a-z0-9_]*:[a-z][a-z0-9_]*$' AND deleted_at IS NULL`。
  原因：live DB 中存在四段码（如 `admin:iam:tenant:write`、`admin:iam:dashboard:approve`），而脚本的 `CODE_RE` 只识别三段，直接纳入会导致 `normalize()` 解包失败（本批实测崩过一次，已修复）。
- `normalize()` 增加非三段防御：`len(parts) != 3` 时原样返回。

## 三、`finance:dashboard:write` 错位修正

### 3.1 取证

| 项 | 事实 |
|---|---|
路由 | `apps/web/src/modules/finance/config.ts:288`（`finance-voucher-create`，`element: VoucherCreatePage`） |
改前 | `requiredPermissions: ['finance:voucher:create', 'finance:dashboard:write']` |
`finance:voucher:create` 持有者 | admin、superadmin、**finance_manager** |
`finance:dashboard:write` 持有者 | admin、superadmin、finance_manager |
`hasPermission` 聚合规则（批 15） | `X:write` 聚合 `X:create/update/delete` —— 聚合范围是**同一 resource** |

**判定错位**：`finance:dashboard:write` 聚合的是 `finance:dashboard:create/update/delete`，与「创建凭证」无语义关系，也不构成「finance 域写总闸」。它只是把一个无关的写权限叠加到凭证创建路由上。

### 3.2 修正

```diff
- requiredPermissions: ['finance:voucher:create', 'finance:dashboard:write'],
+ // 批26：移除与凭证创建无语义关系的 finance:dashboard:write（dashboard:write 按 hasPermission
+ // 聚合规则只覆盖 dashboard 资源的 create/update/delete，不是域级写总闸）。
+ requiredPermissions: ['finance:voucher:create'],
```

**可用性验证**：finance_manager 同时持有 `finance:voucher:create`（DB 实测），移除 `finance:dashboard:write` 后其凭证创建入口不受影响；`finance:dashboard:write` 码本身**保留在 DB**（其他场景可能使用），只是不再被该路由要求。
