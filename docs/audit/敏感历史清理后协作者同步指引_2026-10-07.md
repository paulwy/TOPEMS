# 敏感历史清理后协作者同步指引（2026-10-07）

## 背景

2026-10-07 对仓库执行了 `git filter-repo` 历史重写，清除 11 个含真实凭证/密钥的环境文件在**全部历史**中的出现：

- 根目录：`.env.production`、`.env.shared`、`.env.mail`、`.env.development`、`.env.test`、`.env.docker`、`.env.prod`
- `frontend/`：`.env.production`、`.env.development`、`.env.test`
- `config/standalone.env`

**因此 origin/main 已 force push，所有历史 commit 哈希被重写**（旧 HEAD `b9c9ecf91` → 新 HEAD `0845264b4`，并持续演进）。任何基于旧历史的本地 clone 与远端**不再有共同祖先**。

## 对协作者的影响

- 本地分支基于旧哈希 → `git pull` / `git fetch` 会出现**分叉**，普通 merge/rebase 可能产生重复提交或错误合并
- 本地未推送的 commit 基于旧历史 → 推送会被远端 rejected

## 同步步骤

### 情况一：本地无未推送 commit（只是落后）

```bash
git fetch origin
git reset --hard origin/main
# 警告：会丢弃本地所有未提交/未推送改动，先确认 stash 或备份
```

### 情况二：本地有未推送 commit（需保留）

```bash
# 1. 保存未推送提交为补丁/分支
git branch backup-before-rewrite          # 指向当前本地 main（旧历史）
git fetch origin

# 2. 基于新远端历史重放自己的提交（推荐 rebase，冲突逐个解决）
git rebase origin/main
# 或合并（不推荐，会产生 merge commit）：
# git merge origin/main

# 3. 有本地未提交改动时先 stash：
git stash
git rebase origin/main
git stash pop
```

### 情况三：本地有基于旧历史的分支（feature 等）

```bash
git fetch origin
git checkout <branch>
git rebase origin/main        # 重放到新历史
```

### 彻底重置（最简单，适合无本地贡献的 clone）

```bash
git fetch origin
git reset --hard origin/main
git clean -fd                 # 清理 untracked（注意先确认无重要文件）
```

## 验证同步成功

```bash
git log --oneline -3          # 应看到 0845264b4 及其后续提交哈希
git rev-list --all --objects | grep -cE "(^|/)(\.env\.(production|shared|mail|development|test|docker|prod)|standalone\.env)$"
# 输出应为 0（敏感文件在所有历史中不可达）
```

2. **GitHub secret scanning**：检查仓库 Security 页告警；force push 后旧 commit 告警仍需人工关闭。
3. **密码策略**：任何新环境文件**不得提交**（`.gitignore` 已覆盖所有 `.env*` 模式）；配置一律走 `config/env/_template.env.example` 模板 + 注入。
