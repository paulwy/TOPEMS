## 1. 盘点方法与口径

`CrudPage` 的权限码只能来自 `EntitySchema.api` 与 DB 实际码，二者不是同一命名空间：

- `api.module` = 业务模块（`scm`/`mes`/`erp`…），与 DB 码第一段一致；
- `api.resource` = **API 路径名**（`purchaseOrders`、`inboundOrders`、`orders`）；
- DB 资源名 = **业务实体名**（`purchase_order`、`inbound_order`、`production_order`）。

因此 `api.resource` **不能机械转成权限码**，必须逐个核对 DB 是否存在同名资源。

盘点流程：① 扫描 `apps/web/src` 全部 `api: { module, resource }` 声明 → 得到 (模块, 资源) 对；
② 资源名归一（camel→snake、去复数）后与 `public.core_permissions` 比对；
③ 只统计**真实缺失**——要求该资源在 DB **已有 read 码**（证明资源已被识别为权限实体），才把它缺的写动作计入缺口。

**盘点面**：217 个文件引用 `CrudPage`，其中 **208 个**带 `api.module + api.resource`，去重后 **200 个 (模块, 资源) 对**。

## 5. 补码迁移（`database/migrations/20261107000005_resource_write_codes.sql`）

- **补 135 条**细粒度码：`aps=9, bi=6, doc=3, erp=39, hrm=3, iam=3, integration=9, mobile=3, monitor=6, qms=3, rd=33, tms=12, workflow=6`。
- **命名**：`code = <模块>:<资源>:<动作>`，`resource` 字段沿用同资源既有 read 码的写法（colon 风格 `模块:资源`），`action` 取 `create|update|delete`，`level = 1`，`name` 取 schema title + 中文动作。
- **幂等**：`NOT EXISTS(code)` 判重 → 实测首次 `INSERT 0 135`，二次 `INSERT 0 0`。
- **回滚段**：注释中给出按 `description LIKE '[batch16]%'` 标记的 DELETE 语句。
- **未补 `:write` 聚合码**：DB 现有 `:write` 全是模块级两段码（`mes:write`/`scm:write`），无资源级 `<模块>:<资源>:write`；本批按细粒度码制补齐，与既有 483 个细码一致，不新增第二种写语义。

### 5.1 授权映射（按角色名，最小权限）

| 模块 | 授权角色 | 理由 |
|---|---|---|
erp | `erp_manager` | 该域经理（此前仅持 `erp:read|write` 两段码，补细码后三段码判定才可见） |
hrm | `hrm_manager` | 该域经理 |
qms | `qms_manager` | 该域经理 |
iam | `admin` | IAM 域由平台管理员管辖 |
admin / superadmin | **全部 135 条** | 管理员语义即全量；不补会导致管理员在新页面看不到写按钮（误锁管理员） |
employee / finance_user 等基础角色 | **不授权** | 保持最小权限，不给基础角色补写权限 |
aps / bi / doc / integration / mobile / monitor / rd / tms / workflow | **无对应 manager 角色** | 只建码不授权，登记待角色规划 |

实测授权结果：admin 135、superadmin 135、erp_manager 39、hrm_manager 3、qms_manager 3，合计新增 315 条授权行（`INSERT 0 267` 为管理员段，经理段 48 为首次执行时插入）。
