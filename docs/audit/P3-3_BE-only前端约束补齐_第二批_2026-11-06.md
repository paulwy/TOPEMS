# P3-3 BE-only 前端约束补齐：第二批 + ListPageTemplate 行操作权限开关（2026-11-06）

> 批 12。落地通用能力 + mes 首批页面。

## 一、通用能力：ListPageTemplate 行操作权限开关

### 设计

避免逐页复制权限判断，采用"**列标记 + 模板统一过滤**"的最小侵入方案：

| 改动 | 位置 | 说明 |
|---|---|---|
| `DataTableColumn.writeOnly?: boolean` | `components/redesign/data/DataTable.tsx:16` | 标记该列（通常是操作列）属于写操作，参与权限过滤 |
| `ListPageTemplateProps.writePermission?: string` | `components/redesign/templates/ListPageTemplate.tsx:31` | 页面级写权限码 |
| 过滤逻辑 | `ListPageTemplate.tsx:56-59` | `canWrite = !writePermission || checkPermission(writePermission)`；无权限时 `columns.filter(c => !c.writeOnly)` |

**零回归设计**：`writePermission` 不传时 `canWrite` 恒为 true，不过滤任何列 —— 存量数十个页面行为完全不变，采用与否由各页自行决定，可增量迁移。

### 验证

`__tests__/ListPageTemplate.test.tsx` 新增 3 用例（mock `usePermission`，因该 hook 依赖 AuthProvider）：
1. 未传 `writePermission` → `writeOnly` 列照常渲染（存量零回归）；
2. 传且无权限 → 整列隐藏，普通列保留；
3. 传且有权限 → 渲染，且 `checkPermission` 以正确码调用。

6 tests passed。
