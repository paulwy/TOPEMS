## 三、实施计划

### Phase 1: shared-types 模块化拆分（1天）🔧 P0

**目标**: 将单一 barrel 导出拆分为域-specific 入口，减少不必要的类型导入

| 事项 | 说明 |
|------|------|
| 创建 `shared-types/src/auth.ts` | 认证相关类型（已有，需确认独立导出） |
| 创建 `shared-types/src/org.ts` | 组织架构类型 |
| 创建 `shared-types/src/common.ts` | 通用类型（ApiResponse, PaginatedResponse等） |
| 更新 `shared-types/src/index.ts` | 保留统一入口，但各域类型从子模块导出 |
| 更新 Web 端类型引用 | 使用 `@topems/shared-types/auth` 形式导入 |

### Phase 2: Mobile 客户端缓存优化（1天）🔧 P0

**目标**: 修复内存泄漏风险，添加缓存大小限制和清理策略

| 事项 | 说明 |
|------|------|
| 添加缓存大小限制 | 最大100条记录 |
| 实现 LRU 淘汰策略 | 超出限制时移除最旧条目 |
| 添加缓存清理机制 | 页面卸载时清理 |
| 添加 TTL 过期机制 | 默认5分钟 |

### Phase 3: Admin Chunk 瘦身（2天）🔧 P0

**目标**: 大幅减小 admin-chunk 体积

| 事项 | 说明 |
|------|------|
| 分析 admin-chunk 依赖 | 识别大依赖项 |
| 按需加载非关键组件 | 路由级懒加载优化 |
| 移除未使用的导入 | 代码清理 |
| 压缩配置文件 | 大型 JSON 配置使用 webpack 压缩 |

### Phase 4: 后端性能优化（1天）🔧 P1

**目标**: 修复 Clippy 警告，提升后端代码质量

| 事项 | 说明 |
|------|------|
| 修复 migration-sdk | unnecessary_sort_by, redundant_closure |
| 修复 analytics-service | clone_on_copy |
| 检查其他服务 | 批量修复类似问题 |

### Phase 5: 插件化缓存策略（1天）🔧 P1

**目标**: 减少插件配置重复请求

| 事项 | 说明 |
|------|------|
| 添加插件配置缓存 | PluginManager 内置缓存 |
| 实现缓存失效机制 | 支持手动刷新 |
| 验证缓存效果 | 减少 API 请求次数 |
