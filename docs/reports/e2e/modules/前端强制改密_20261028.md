# 前端强制改密流程（2026-10-28）

> 状态：✅ 已闭环并实机验证
> 范围：`apps/web` 前端——登录后 `must_change_password=true` 用户强制改密后才能进入系统。
> 背景：后端 S2 首启强制改密已闭环（JWT claim `must_change_password` + `POST /users/me/password` 改密端点）；前端此前 **0 处** 读取该标志，强制流程从零建。

## 一、后端契约（已闭环，未改动）

| 项 | 内容 |
|---|---|
| 登录响应 | `data.user.must_change_password`（UserInfo 字段，auth.rs login） |
| JWT claim | payload 含 `must_change_password`（auth.rs:386） |
| 改密端点 | `POST /api/core/iam/users/me/password`（routes/iam.rs 自服务组，仅需登录） |
| 改密语义 | 验旧密 → 新密 ≥6 位 → bcrypt hash → `UPDATE iam.users SET password_hash=$1, must_change_password=false, password_changed_at=NOW()` → 200 |
| 注意 | 改密成功后**旧 JWT 仍带 must_change_password=true**（直到重新登录）；前端处理 = 改密成功强制 logout 重新登录 |

## 二、前端实施

### 1. 登录跳转（LoginPage.tsx onSuccess）
登录成功 → 读 `response.data.user.must_change_password` → `true` 则 `navigate('/force-change-password')`，不进入系统。

### 2. 强制改密页（ForceChangePasswordPage.tsx，新建）
- 路由 `/force-change-password`（routes/auth.ts 裸路由，非 Guest/Protected）
- 表单：当前密码 / 新密码 / 确认新密码（zod 校验：新密 ≥6 位、两次一致）
- 提交：`authApi.changePassword({ current_password, new_password })`
- 成功：通知 → `logout()` → `navigate('/login')`（强制重新登录，新 token 标志为 false）
- 页面内部兜底：未登录 → /login；非强制用户访问 → /dashboard
- 视觉复用 AuthPageTemplate（与 LoginPage 同风格），文案全走 i18n

### 3. 路由守卫（ProtectedRoute.tsx）
所有受保护路由：`user.must_change_password === true` 且当前非改密页 → 重定向 `/force-change-password`（防深链绕过——刷新/直链/导航都拦得住）。

### 4. 类型链路（shared-types 三处）
- `User` 接口 + `must_change_password?: boolean`
- `RawApiUserResponse` + 字段
- `mapApiUserToUser` + 透传（login 落 localStorage 的 user 保留标志，守卫可读）
- dist/index.d.ts 同步（tsc 走 dist 类型）
- 另：`api/iam/types.ts` User 同步 + 字段（页面断言用）

## 三、实机验证（BFF :8099）

构造临时用户 `force_pwd_e2e`（must_change_password=true，复用 test_admin 的 admin123 hash）：

```
登录（admin123）          → user.must_change_password=True ✓  JWT claim=True ✓
POST /users/me/password（admin123 → NewPass2026!）→ 200 修改密码成功 ✓
新密码再登录               → user.must_change_password=False ✓
旧密码登录                 → 401 用户名或密码错误 ✓
```

临时用户已清理（DELETE，count=0）。库内真实用户（admin/test_admin 等）均 must_change=false，不受影响。

## 六、边界与后续

- **改密后强制重新登录**为既定语义（后端不清旧 token，前端 logout 重登）；如需无感（改密后自动重签发 token），需后端扩展，不在本次范围。
- `GET /users/me` 响应不含 must_change_password（profile.rs SELECT 无该列）——刷新后守卫依赖 localStorage user（login 时 mapper 透传），无需后端改动。
- 首次启用的 admin（ADMIN_INITIAL_PASSWORD 登录）将自动进入强制改密流程。
