> 状态：✅ 已完成并实测闭环

## 一、现状与决策依据

| 维度 | iam.users | public.core_users |
|---|---|---|
| 列数 | 29（含 roles/permissions/must_change_password 全套认证字段） | 15 |
| 数据 | 4 行（admin=b172efee / test_admin=c31c393a / sc_r2_regular / sc_s2_r1_user01） | 1 行（test_admin=e91e2228，仅测试数据） |
| 认证链 | ✅ 全走此表（auth.rs login/register/tenant handlers INSERT-SELECT、JWT sub、权限 JOIN） | ❌ 无 |
| 业务读取 | 无（权威写表） | communication（notification.rs 1 处 + mail.rs 4 查询 + 2 JOIN 取 email）+ search（handlers.rs 用户名检索） |
| FK 入向 | core_sessions / core_refresh_tokens / iam.data_permissions / iam.resource_permissions / iam.user_positions | core_user_roles / iam.sessions / iam.refresh_tokens / public.refresh_tokens |
| RLS | — | 已开启 |

**核心缺陷**：认证在 iam.users，但 communication/search 按 core_users 取 email/检索用户——对真实用户（如 test_admin=c31c393a）永远查空（S13 曾踩同一根因）。注释矛盾：auth.rs:680 原注「统一写 core_users（唯一权威源）」但实际 INSERT 写 iam.users——历史意图残留。

**僵尸确认**：iam.sessions / iam.refresh_tokens / public.refresh_tokens / core_user_roles 均 0 行；除 core_user_roles（角色系统部分，role.rs 计数引用）外均无代码引用。

**决策**：`iam.users` 权威化；core_users 废弃删除；core_user_roles 保留（角色系统，FK 重指 iam.users）；core_roles（19 行角色权威）不受影响。

## 二、落地清单

```sql

DROP TABLE IF EXISTS iam.sessions;
DROP TABLE IF EXISTS iam.refresh_tokens;

-- 2) core_user_roles 用户 FK 重指 iam.users（权威身份表）
ALTER TABLE public.core_user_roles DROP CONSTRAINT IF EXISTS core_user_roles_user_id_fkey;
ALTER TABLE public.core_user_roles
  ADD CONSTRAINT core_user_roles_user_id_fkey FOREIGN KEY (user_id) REFERENCES iam.users(id);

-- 3) 废弃 core_users
DROP TABLE IF EXISTS public.core_users;
```
