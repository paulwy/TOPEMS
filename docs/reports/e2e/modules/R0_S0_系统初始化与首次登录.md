## 详细结果

### S0-① 空库启动自愈（独立空库 topems_s0_fresh）
- **前置**：CREATE DATABASE topems_s0_fresh（0 表）
- **执行**：DATABASE_URL 指向空库启动 → 3 分钟建池 → 自愈建表
- **结果**：
  - ✅ 服务正常启动（monitor health=200，topems-iam healthy）
  - ✅ **392 张核心表自愈创建**（bi.reports/crm.contacts 等 + schema_defense_ledger/audit_logs）
  - ❌ **iam.users / iam.core_users 未自愈创建** → **登录 POST /auth/login 返回 500**（"内部服务器错误"，表不存在），而非 401"用户不存在"
- **结论**：schema_defense 覆盖大部分模块核心表，但 **iam 用户域表不在自愈范围**；空库首次部署时登录接口以 500 失败（P2 级初始化缺陷，建议：空库自愈补 iam 用户表，或登录在表缺失时返回明确的"系统未初始化"）。

### S0-② 超管创建与首次登录
- **实测**：新库无任何用户（无自动种子）；手工 INSERT iam.users（bcrypt admin123）后登录成功。
- **权限**：初始插入 is_superuser=false → 业务模块 403（"权限不足：需要 X 模块权限"）；UPDATE is_superuser=true 后登录 JWT 含 `permissions:["*"]`、`role:"admin"` → **ehs/scm/srm/tms/ticket/bi 等全部从 403 恢复 200**。
- **缺口记录**：无自动超管种子/引导流程（首次部署需运维手工建超管）。

### S0-③ must_change_password
- **实测**：`iam.users.must_change_password=false`（插入默认）；登录响应/JWT 无强制改密指示；代码无 first_login 分支。
- **缺口记录**：字段存在但机制未实现（P3 记录级）。

### S0-④ 初始化状态查询
- `/api/monitor/health`：**16 个服务注册**（iam/crm/hrm/pm/erp/wms/scm/lims/qms/ehs/pdm/rd/srm/mes/bi/ai），除 **pm=degraded（response_time 150ms）** 外均 healthy（记录：pm 降级待查）。
- `/api/info`：401（需认证——public 接口白名单不含，属正常保护）。
