### 初始化机制实测结论（2026-10-27，供 S0 设计依据）
- **启动期系统初始化存在**：每个真实模块 build 时执行 schema_defense（CREATE TABLE IF NOT EXISTS + 列自愈/迁移验证，`run_schema_migration_and_verify`）与 `init_database`——空库启动可自愈建表（历史已验证"DB 空库自愈"）。
- **无首次登录引导**：登录接口无 first_login/onboarding 处理；`iam.users` 有 `must_change_password` 列但代码未见强制逻辑；**超管 test_admin 需手工创建（无自动种子）**——S0 作为验证点/潜在缺口。

## 一、目标与原则

- **全覆盖**：40 个模块/域（16 业务模块 + 24 业务域）均至少 1 个典型场景，尽量真实业务流串联。
- **场景真实**：模拟一线用户典型操作路径（输入→提交→读回→关联）。
- **迭代补充**：7 轮迭代；每轮复盘补充负例/边界；问题即修即验。
- **数据隔离**：sc_ 前缀，保留在库。

## 四、执行方式

1. **前置**：先为 test_admin 配置全模块权限（超管 role / core_tenant_modules 全开）——否则 S5/S13/S14-S24 大量 403。
2. **登录**：POST /api/core/iam/auth/login 取 JWT（长超时 -m 20+，登录后 sleep 2-3s 再批量请求，避免冷路径超时）。
3. **调用**：真实 HTTP（:8099 完整 URL，严禁相对路径）；场景内串联；跨模块 ID 直接传递。
4. **验证**：响应 envelope + 落库（psql 按前缀）+ 契约；预置验证点优先复现定位。
5. **缺陷处理**：发现即定位（日志/psql）→ 修复 → 复测；P1/P2 优先。
6. **缺口处理**：unified-core 未挂载子模块（file/audit/settings）——确认设计意图→报告记录。

## 五、迭代与补充机制

- R1→R7 顺序执行；每轮产出小结（通过/发现/修复/缺口）。
- R1-R5 异常 → 归入 R6 负例集；R6 新风险 → 补入 R7 回归集。
- 每轮按实测修正字段/枚举/端点，记录勘误。
- **退出标准**：S29 回归通过、无 P1/P2 遗留、缺口与记录级发现全部文档化。

## 六、验收标准

- 40 域在覆盖矩阵均有 ✅。
- 每场景"输入→响应→读回/落库"闭环，关键断言有证据。
- 缺陷有根因与修复/留档结论；负例验证错误语义。
- 未挂载子模块给出明确缺口结论。
