## 8. 优先级建议

1. **高优先级（业务数据表）**：对同时缺少 tenant_id 与 RLS 的表，
   优先评估是否存储了跨租户敏感数据。若是，应立即添加 tenant_id 列并启用 RLS 策略。
2. **中优先级（RLS 补齐）**：对已含 tenant_id 但未启用 RLS 的表，
   通过 `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` 与策略绑定补齐。
3. **中间件覆盖**：确认所有业务服务在路由层均应用了 rls_middleware / tenant_middleware；
   对标记为 `none` 的服务需重点复查。
4. **表名/schema 校准**：对 tenant_id/RLS 引用但未扫描到定义的表，核对 schema/表名一致性，
   清理已删除表的残留引用，统一命名规范。
5. **验证机制**：建议在 CI 中保持本脚本运行，并将阈值逐步下调至 0。

## 9. 扫描范围与假设

- 扫描路径：`svc/*/migrations/*.sql`、`svc/*/init.sql`、`database/**/*.sql`、`migrations/*.sql`
- 排除：`database/test/`、模板生成器测试 SQL。
- tenant_id 检测来源：CREATE TABLE 语句含 tenant_id 列，或 ALTER TABLE ... ADD COLUMN tenant_id。
- 表名去重以 schema.table 为键；未指定 schema 的默认按 `public` 处理。
- RLS 覆盖率按「已知 CREATE TABLE 定义且启用 RLS」计算，避免引用未扫描表导致虚高。
