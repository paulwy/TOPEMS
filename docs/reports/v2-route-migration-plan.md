# V2 路由系统迁移方案

> 版本: 1.0 | 日期: 2026-07-01 | 状态: 待实施
> 负责人: Agent Team | 预计工时: 5 天

---

## 一、背景与问题

### 1.1 现状

项目中存在两套并行的路由系统：

| 系统 | 位置 | 模块数 | 路由数 | 使用方 |
|------|------|--------|--------|--------|
| 旧路由 | `src/routes/*.ts` | 23 | 282 | App.tsx（主入口） |
| V2 路由 | `src/routes/v2/*.ts` | 31 | 281 | PageContainerV2（仅面包屑/标题） |

### 1.2 核心问题

**导航路径与实际路由路径大量不匹配：**

- 导航系统（`.nav.ts`）使用 V2 风格路径：`/hrm/dashboard`, `/hrm/employees/:id`
- App.tsx 实际路由使用旧路径：`/hrm/companies`, `/hrm/employee/:id`
- 约 40% 的导航路径在旧路由中不存在，点击后被 `*` 通配符重定向到 `/dashboard`

### 1.3 缺失模块

旧路由缺少 9 个模块：`admin`, `asset`, `doc`, `ehs`, `integration`, `lims`, `notification`, `oa`, `qms`

这些模块的导航项点击后直接跳回首页。

---

## 二、迁移目标

1. **统一数据源**：App.tsx 切换到 V2 路由，与导航系统 1:1 对应
2. **路径规范化**：所有模块路径统一使用 `/{module}/dashboard` 格式
3. **消除重复维护**：删除旧路由文件，只保留 V2 一套
4. **平滑过渡**：保留旧路径重定向，不破坏用户书签
5. **元数据丰富**：路由包含 `title`/`template`/`group`/`layout` 等元信息

---

## 三、迁移策略

### 3.1 总策略：渐进式迁移

```
阶段0：双路由并存（V2优先）→ 阶段1：核心模块迁移 → 阶段2：业务模块迁移 → 阶段3：边缘模块+清理 → 阶段4：收尾优化
```

### 3.2 兼容性保障

- 所有旧路径添加 301 重定向到新路径
- 重定向规则统一在 `compatibility.tsx` 中维护
- 旧路径保留至少 2 个版本周期
- 开发环境下控制台输出 deprecation warning

## 六、风险与应对

| 风险 | 影响等级 | 概率 | 缓解措施 |
|------|---------|------|---------|
| 页面间跳转路径错误 | 高 | 中 | 全局搜索 `navigate(` 和 `<Link`，批量替换 |
| 外链/用户书签失效 | 中 | 高 | 旧路径重定向保留 2 个版本 |
| 权限控制失效 | 高 | 低 | 逐模块验证 requiredPermissions |
| 布局类型不匹配 | 中 | 低 | 验证 layout 字段配置 |
| 动态路由参数错误 | 高 | 中 | 重点验证 `:id` 类路径 |
| TypeScript 类型错误 | 低 | 中 | 编译期检查，CI 门禁 |

## 八、回滚方案

如迁移过程中出现严重问题，可快速回滚：

1. 移除 App.tsx 中 V2 路由的导入和渲染
2. 恢复被删除的旧路由文件（Git 历史）
3. 重新构建部署

预计回滚时间：15 分钟

---

## 九、迁移后收益

1. **导航-路由 100% 对齐**：侧边栏点击路径 = 实际路由路径
2. **单一数据源**：消除两套路由维护成本
3. **路径规范统一**：所有模块命名风格一致
4. **元数据丰富**：支持自动化生成面包屑、标题、权限检查
5. **模块完整**：31 个模块全部可通过路由访问
6. **可维护性提升**：新增模块只需创建一个 V2 路由文件
