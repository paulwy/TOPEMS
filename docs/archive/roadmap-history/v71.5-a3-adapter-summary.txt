## 1. 适配层设计

### 1.1 核心问题

后端 utoipa 生成 snake_case 字段（is_enabled / created_at / parent_id），
前端手写业务类型用 camelCase（isEnabled / createdAt / parentId）。
A2 阶段仅处理了 Account 类型的 2 个字段（is_enabled→isactive, account_type→category），
A3 需要提供通用适配工具覆盖 ≥24 处冲突字段。

### 1.2 模块结构

```
packages/shared-types/src/
├── openapi-adapter.ts          # 适配层主文件（289 行）
├── __tests__/
│   └── openapi-adapter.test.ts # 单元测试（296 行 · 26 tests）
├── vitest.config.ts            # 测试配置（新建）
└── package.json                # 添加 vitest devDep + test 脚本
```

### 1.3 API 清单

| 导出名 | 类型 | 用途 |
|--------|------|------|
| `FIELD_MAPPING` | const (130+ 条) | 蛇形→驼峰 白名单字典（直接命名冲突） |
| `SEMANTIC_MAPPING` | const (2 条) | 语义重命名字典（account_type→category, is_enabled→isactive） |
| `FULL_MAPPING` | const | FIELD + SEMANTIC 合并（SEMANTIC 覆盖同名 key） |
| `Adapt<T, M>` | type | 泛型工具：Omit 蛇形 + 添加驼峰（编译期字段重命名） |
| `AdaptedKeys<M>` | type | 提取映射后的字段名列表 |
| `FieldMapping` | type | 字段映射配置类型 `Readonly<Record<string,string>>` |
| `adapt<T>(data, mapping?)` | function | 蛇形→驼峰 运行时转换 |
| `adaptReverse<T>(data, mapping?)` | function | 驼峰→蛇形 反向转换（自动反转 mapping） |
| `snakeToCamel(s)` | function | 通用 snake→camel 转换（不依赖白名单） |
| `camelToSnake(s)` | function | 通用 camel→snake 转换（不依赖白名单） |

## 5. 后续（A4 衔接）

A3 适配层已就绪，A4 任务（前端 1329 API 函数接入生成类型）可：
1. 在 API 层 `adapt(apiResponse, FIELD_MAPPING)` 将后端蛇形数据转为驼峰
2. 在请求前 `adaptReverse(payload, FIELD_MAPPING)` 将驼峰转回蛇形
3. 使用 `Adapt<FinanceTypes.Account, typeof FIELD_MAPPING>` 获得类型安全的适配后类型
4. 对语义重命名字段使用 `FULL_MAPPING`（含 account_type→category 等）
