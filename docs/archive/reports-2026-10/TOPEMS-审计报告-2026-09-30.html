03关键矛盾专项：TODO.md 自述（09:02） vs HEAD 实测（17:00）

本章为全报告信息密度最高的一节：工程内 TODO.md 写于当日 09:02，其「全绿」叙述与 17:00 对同一 HEAD（07a076544）的实测结果逐条对照——六项核心自述全部不成立。

TODO.md 自述（09:02）判定实测证据（退出码 / 日志）
「MES 模块编译错误清零：cargo check --workspace 0 错误」不成立 SQLX_OFFLINE=true cargo check --workspace 退出 101，在 wms 即中止（11 错误），根本未编到 mes。日志 logs/check_workspace.log。
「-p topems-mes --all-targets 0 错误」不成立 退出 101，mes 24 个错误 + 18 警告；E0433 rust_decimal 仍在 production_order.rs:811:35。日志 logs/check_mes_alltargets.log。
「cargo test -p topems-mes --lib 458/458 全过（0 failed）」不成立 绕过 sccache 重跑退出 101：mes lib test 编译不过，0 个测试执行，全程无任何 test result: 行。日志 logs/test_mes_nosccache.log。
「pre-push 五门禁全绿（check/clippy/fmt/test/shellcheck，511s）」不成立 check/clippy/test 均 101、fmt 退出 1（49 文件不符）；shellcheck 本机未安装无法复核。9 条门禁实测 7 红 2 绿（typecheck/build）。
「全仓 cargo fmt 统一」不成立 cargo fmt --check --all 退出 1，49 个文件存在格式 diff（unified-core 418 hunks、mes 5 文件）。清单 logs/fmt_dirty_files.txt。
「workspace lib 测试 13239 全绿」无法验证 workspace 连 cargo check 都过不了，测试编译无从谈起；本次未运行全量 workspace test。
前端「bundle 全绿 / typecheck」部分成立 pnpm typecheck 退出 0、pnpm build 退出 0；pnpm lint 因环境 OOM 退出 134，未得出结论。

成因解释（为什么自述与实测会漂移）

  • 12:48 之后的新提交引入了错误。errors.txt（12:47）记录 mes 24 错误；12:48 提交「fix: 修复 production_order.rs 中的 quantity 类型错误」只改了表达式形状，没有把 rust_decimal 从 dev-dependencies 移到 dependencies，E0433 原样残留到 HEAD。其后 12:59–16:33 又推入 16+ 条 feat: 新增X模块真实数据库查询API，其中 wms 的 batch/discrepancy/inventory_alert 新增了 11 个同类 Option<String> 类型错配。
  • errors.txt 准确反映现状、且只覆盖了一半。它是一次 cargo check -p topems-mes 的输出，从未检查 wms；真实错误面 = wms 11 + mes 24 = 35。errors.txt 本身是未跟踪文件留在工作区——开发者明知主干红仍继续推 feature。
  • 门禁未实际拦截。TODO.md 声称 pre-push 五门禁全绿，但 origin/main HEAD 处于 Rust 编译红——推送绕过了本地门禁（机制详见第 08 节专项）。

07门禁失效机制专项（实测确认）

生效链路实测：core.hooksPath 为空（未设置）；git 实际调用的是 .git/hooks/pre-commit / .git/hooks/pre-push——二者内容为 lefthook 安装的垫片，经 node_modules/.pnpm/lefthook-darwin-arm64@2.1.10 执行 call_lefthook run。lefthook 是唯一生效的钩子体系。

  • 垫片内含 LEFTHOOK=0 显式旁路开关；脚本本身也提示可用 --no-verify 跳过。
  • 本机未安装 shellcheck，check-shellcheck.sh 遇缺失即 exit 1——按设计本应拦在合法 pre-push 之前。
  • 但 HEAD 处于编译红色（workspace check/clippy/test 全 101、fmt 1）仍被推上 origin/main，含 16+ 条 feature 提交。

结论：推送绕过了本地门禁（--no-verify / LEFTHOOK=0 / 他机推送三者之一），门禁链未实际拦截本次红推；.githooks/（需 core.hooksPath 指向才生效的在线 cargo check）与 .pre-commit-config.yaml（自述备选需手动 install）、.husky/（空壳）均为孤儿配置，且存在 hooksPath 漂移切换到需连库旧链路的风险。
