## S1 — BI 模块 SQL 注入防御深化

### 现状分析

经代码验证，原报告"直接拼接用户可控参数"的描述需要修正：

| 文件 | 风险点 | 实际风险 | 现有防御 |
|------|--------|---------|---------|
| [chart_service.rs](file:///Users/xingzhai/TOPEMS/svc/analytics/src/modules/bi/chart_service.rs#L175) L175/197/217 | `format!("SELECT {} FROM {}", cols[0], table)` | **低** — SQL 从未真正执行，`execute_query` 只返回 sample data | `validate_identifier` + `quote_identifier` 已对输入做白名单校验 |
| [multidimensional_analysis.rs](file:///Users/xingzhai/TOPEMS/svc/analytics/src/modules/bi/multidimensional_analysis.rs#L157) L157/259/362 | `format!("SELECT {} FROM analytics_data ORDER BY {} {} LIMIT {} OFFSET {}", ...)` | **中** — SQL 确实通过 `sqlx::query(&query)` 执行 | 标识符经 `validate_identifiers` + `quote_identifier` 校验；LIMIT/OFFSET 为 `i64` 类型安全 |
| [multidimensional_analysis.rs](file:///Users/xingzhai/TOPEMS/svc/analytics/src/modules/bi/multidimensional_analysis.rs#L436) L436 | `format!("SELECT {} FROM analytics_data LIMIT 100", select_clause)` | **中** — 同上 | `select_clause` 经 `validate_identifiers` 校验 |

**结论**：已有第一层防御（标识符白名单 + 引号包裹），但缺少纵深防御（参数化绑定 + 元数据白名单 + AST 解析）。

### 实施步骤

#### S1.1 — LIMIT/OFFSET 参数化绑定

将 `multidimensional_analysis.rs` 中 4 处 `format!` 的 LIMIT/OFFSET 从字符串拼接改为 `sqlx::query_as_with` 绑定参数。

**改动文件**: `svc/analytics/src/modules/bi/multidimensional_analysis.rs`

**改动模式**（以 `query_cube` 为例）:

```rust
// BEFORE
let query = format!(
    "SELECT {} FROM analytics_data ORDER BY {} {} LIMIT {} OFFSET {}",
    select_clause, sort_by, sort_order, limit, offset
);
let data_result = sqlx::query(&query).fetch_all(&state.pool).await;

// AFTER
let query = format!(
    "SELECT {} FROM analytics_data ORDER BY {} {} LIMIT $1 OFFSET $2",
    select_clause, sort_by, sort_order
);
let data_result = sqlx::query_as::<_, (serde_json::Value,)>
    (&query)
    .bind(limit)
    .bind(offset)
    .fetch_all(&state.pool)
    .await;
```

**覆盖函数**: `query_cube` (L157) · `slice_cube` (L259) · `dice_cube` (L362) · `pivot_table` (L436 仅 LIMIT) · `rank_data` (L527 仅 LIMIT)

**验收**: `grep -n 'format!.*LIMIT\|format!.*OFFSET' svc/analytics/src/modules/bi/multidimensional_analysis.rs` 输出中不再包含用户输入变量名（limit/offset），仅保留 SQL 模板字符串。

#### S1.2 — chart_service.rs 实际查询路径加固

`chart_service.rs` 的 `execute_query` 当前只返回 sample data，未执行真实 SQL。但如果未来接入真实数据库查询，`ChartQuery.query` 字段（用户可设的完整 SQL 字符串）将成为注入入口。

**改动文件**: `svc/analytics/src/modules/bi/chart_service.rs`

**措施**:
1. 将 `ChartQuery.query` 字段标记为 `#[deprecated]`，新增 `ChartQuery.columns: Vec<String>` 结构化字段
2. `generate_line_chart` / `generate_bar_chart` / `generate_pie_chart` 内部不再构造 SQL 字符串，改为传递结构化列信息
3. `execute_query` 未来接入真实查询时，强制走 `validate_dataset` → `sqlx::query_as_with` 路径

**验收**: `grep -n 'query: format!' svc/analytics/src/modules/bi/chart_service.rs` 返回 0 行。

#### S1.3 — 新增 BI 数据集白名单校验

创建 `bi_datasets` 元数据表，记录允许查询的表名和列名白名单。

**新增文件**:
- `database/migrations/20260808120000_create_bi_datasets.sql`
- `svc/analytics/src/modules/bi/dataset_whitelist.rs`

**表结构**:

```sql
CREATE TABLE bi_datasets (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    table_name  VARCHAR(128) NOT NULL,   -- 白名单表名
    column_name VARCHAR(128) NOT NULL,   -- 白名单列名
    data_type   VARCHAR(32)  NOT NULL,   -- string | number | datetime
    is_active   BOOLEAN      NOT NULL DEFAULT TRUE,
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT NOW(),
    UNIQUE(table_name, column_name)
);
```

**校验逻辑**: 在 `multidimensional_analysis.rs` 各 handler 入口处，调用 `dataset_whitelist::validate_columns(&pool, &table, &columns)` 校验请求的列名是否在白名单内。未注册的列直接返回 400。

**验收**: 向 `query_cube` 传入白名单外的列名 → 返回 `{"success": false, "message": "Column 'xxx' is not in the BI dataset whitelist"}`。

## A2 — unified-core 模块瘦身

### 现状分析

[modules/mod.rs](file:///Users/xingzhai/TOPEMS/svc/unified-core/src/modules/mod.rs) 声明 18 个模块。[routes/mod.rs](file:///Users/xingzhai/TOPEMS/svc/unified-core/src/routes/mod.rs#L120-L131) 将其中 12 个模块路由合并到 core。

**膨胀根因**: unified-core 承担了"API 网关 + IAM + 流程引擎 + 文件管理 + 主数据 + 插件注册 + 监控 + 帮助 + 审计 + 字典 + 设置 + 迁移"等过多职责。

### 拆分策略

按**领域边界**和**变更频率**筛选拆分候选：

| 候选模块 | 当前职责 | 拆分去向 | 理由 |
|---------|---------|---------|------|
| **monitor** | 系统监控、指标采集 | 独立为 `svc/monitor` 微服务 | 领域独立，变更频率低，可独立部署 |
| **plugin** | 插件注册、运行时管理 | 独立为 `svc/plugin-registry` 微服务 | 已有 token 鉴权边界，天然适合独立 |
| **help** | 帮助文档 CRUD | 合并到 `svc/portal` 或独立为轻量服务 | 体量极小，不值得占 core 编译时间 |
| **migration** | 数据迁移 SDK | 合并到 `svc/integration` | integration 已承担同步/集成职责，migration 与其同域 |
| **dict** | 数据字典 CRUD | 合并到 `svc/master-data` | 字典是主数据的子集，master-data 已存在 |
| **login_log** | 登录日志 | 合并到 `svc/audit` 或留在 core audit 内 | 与 audit 同域，可合并为 audit 子模块 |

**目标**: 18 模块 → 12 模块（core 保留: audit, communication, doc, file, flow, iam, master, menu, settings, tenant, openapi, mod）

## A4 — topems_shared 去门面化

### 现状分析

[lib/src/lib.rs](file:///Users/xingzhai/TOPEMS/lib/src/lib.rs) 有 **119 条 `pub use`**，将 8 个子 crate 的所有公开类型全部 re-export 到一个"门面"crate。

**已有子 crate 结构**:

| 子 crate | 职责 | pub use 条目数（估算） |
|---------|------|---------------------|
| `topems-shared-core` | API/配置/CORS/健康/日志/指标/响应/校验 | ~35 |
| `topems-shared-db` | 数据库/审计/备份/RLS/Schema/存储 | ~15 |
| `topems-shared-auth` | 认证/中间件/权限/租户/限流/安全 | ~20 |
| `topems-shared-event` | 事件/缓存/集群/Redis/Consul/Saga/服务发现 | ~20 |
| `topems-shared-observability` | 监控/遥测/性能/可观测性 | ~10 |
| `topems-shared-ai` | AI 客户端/嵌入/向量存储/Ollama | ~10 |
| `topems-shared-service-client` | 服务间调用客户端 | ~5 |
| `topems-shared-bootstrap` | 服务启动引导 | ~4 |

**问题**: 每个服务只要 `use topems_shared::*` 就会引入全部 119 个符号，即使只用到 3~5 个。编译器无法有效裁剪，且新增类型会自动"泄露"到所有服务。

### 拆分策略

**不拆子 crate（已拆好）**，只拆**门面 re-export**。

#### A4.1 — 分类保留核心 re-export

将 `lib/src/lib.rs` 的 119 条 `pub use` 精简为以下 3 类：

**类别 1: 保留（高频跨服务通用类型，≤30 条）**

```rust
// 响应/错误/分页 — 几乎每个服务都用
pub use topems_shared_core::response::{ApiResponse, ListResponse, PaginatedResponse, PaginationParams};
pub use topems_shared_core::error::{Result, TopemsError};
pub use topems_shared_core::list_resp;

// 认证核心 — 几乎每个服务都用
pub use topems_shared_auth::auth::{auth_middleware, verify_jwt_token, Claims, AuthState};
pub use topems_shared_auth::tenant::{TenantContext, TenantManager};

// 数据库核心 — 有 DB 的服务都用
pub use topems_shared_db::database::{create_database_pool, ReadWritePool};
pub use topems_shared_db::schema::{with_schema, AI_SCHEMA, BI_SCHEMA, /* ... */};

// Schema 枚举 — 跨服务共享
pub use topems_shared_core::common_types;
pub use topems_shared_core::service_port;
```

**类别 2: 标记 `#[deprecated]`（本次不删，编译 warning 驱动迁移）**

```rust
#[deprecated(note = "直接依赖 topems-shared-core，use topems_shared_core::config::AppConfig")]
pub use topems_shared_core::config::AppConfig;

#[deprecated(note = "直接依赖 topems-shared-event，use topems_shared_event::redis::RedisPool")]
pub use topems_shared_event::redis::RedisPool;
// ... 其余 ~89 条全部加 #[deprecated]
```

**类别 3: 直接删除（无外部引用的死导出）**

通过 `grep -r "topems_shared::XXX" svc/` 扫描实际引用，零引用的直接删除。

#### A4.2 — 逐服务迁移到直接依赖

按服务批次迁移，每批 3~5 个服务：

| 批次 | 服务 | 操作 |
|------|------|------|
| 1 | analytics, unified-core, iam | Cargo.toml 新增 `topems-shared-core`/`topems-shared-db`/`topems-shared-auth` 直接依赖；`use topems_shared::*` → `use topems_shared_core::response::*` 等 |
| 2 | hrm, finance, erp, crm | 同上 |
| 3 | mes, qms, lims, ehs, pdm | 同上 |
| 4 | 剩余全部 | 同上 |

**每批迁移后验证**: `cargo check -p <service>` 0 error 0 warning。

#### A4.3 — 最终清理

全部服务迁移完成后：
1. 删除 `lib/src/lib.rs` 中所有 `#[deprecated]` 条目
2. 仅保留类别 1 的 ≤30 条核心 re-export
3. 更新 `examples/minimal-service/` 作为"仅依赖子 crate"的标杆示例

**验收**:
- `grep -cE "^pub use " lib/src/lib.rs` ≤ 30
- `cargo build --workspace` 0 error 0 warning
- 冷编译时间对比（`cargo clean && time cargo build --workspace`）下降 ≥15%
