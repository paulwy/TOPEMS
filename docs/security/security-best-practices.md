# TOPEMS 安全最佳实践

## 概述

本文档是 TOPEMS 系统的安全最佳实践指南，包含安全架构、认证授权、数据安全、应用安全、运维安全、安全审计等内容，确保系统在设计、开发、部署和运维各个阶段都符合安全要求。

## 1. 安全架构

### 1.1 安全设计原则

| 原则 | 说明 |
|------|------|
| **最小权限原则** | 用户和服务只拥有完成任务所需的最小权限 |
| **纵深防御** | 多层安全防护，单层被突破仍有其他层保护 |
| **默认安全** | 系统默认配置是安全的，需要显式开启不安全功能 |
| **零信任架构** | 不默认信任任何内部或外部请求，每次都需验证 |
| **数据最小化** | 只收集和存储必要的数据，减少数据泄露风险 |
| **安全左移** | 在开发早期就考虑安全，而不是后期补救 |
| **可审计性** | 所有安全相关操作都有日志记录，可追溯 |

## 2. 认证授权安全

### 2.1 身份认证

#### 2.1.1 密码策略

| 策略项 | 要求 |
|--------|------|
| 最小长度 | 至少 12 个字符 |
| 复杂度 | 包含大小写字母、数字、特殊字符 |
| 密码历史 | 不能与最近 5 次密码相同 |
| 密码过期 | 90 天强制更换 |
| 账户锁定 | 连续 5 次失败锁定 30 分钟 |
| 密码存储 | 使用 bcrypt/argon2 加密，cost >= 12 |
| 禁止弱密码 | 检查常见弱密码字典 |

#### 2.1.2 多因素认证（MFA）

- **管理员账户**：强制启用 MFA
- **普通用户**：建议启用 MFA
- **MFA 方式**：TOTP（Google Authenticator）、短信验证码、邮件验证码
- **MFA 降级**：MFA 服务不可用时，应有安全的降级方案

#### 2.1.3 JWT Token 安全

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 签名算法 | RS256/ES256 | 使用非对称加密，避免密钥泄露 |
| Access Token 过期 | 15-30 分钟 | 短有效期，减少泄露风险 |
| Refresh Token 过期 | 7-14 天 | 长有效期，用于刷新 Access Token |
| Token 存储 | HttpOnly Cookie | 防止 XSS 攻击窃取 Token |
| Token 撤销 | 支持黑名单 | 用户登出或密码修改后撤销 Token |
| Issuer 验证 | 验证 iss 字段 | 防止 Token 伪造 |
| Audience 验证 | 验证 aud 字段 | 防止 Token 重放 |

### 2.2 权限控制

#### 2.2.1 RBAC 权限模型

- **角色定义**：预定义系统管理员、部门管理员、普通用户等角色
- **权限粒度**：菜单权限、操作权限（增删改查）、数据权限
- **数据权限**：全部数据、本部门数据、本部门及下级、本人数据
- **权限继承**：支持角色继承，减少重复配置
- **权限审计**：定期审查权限分配，及时回收不必要的权限

#### 2.2.2 API 权限控制

- **接口级权限**：每个 API 接口都需要权限验证
- **方法级权限**：GET/POST/PUT/DELETE 分别控制
- **数据级权限**：查询和操作时过滤用户有权限的数据
- **越权检测**：检测水平越权（访问他人数据）和垂直越权（访问高级功能）

### 2.3 会话管理

- **会话超时**：无操作 30 分钟自动登出
- **并发会话**：限制同一用户同时在线设备数（建议 3-5 个）
- **会话监控**：记录用户登录设备、IP、时间，异常登录告警
- **强制登出**：管理员可强制用户下线
- **会话固定防护**：登录后重新生成会话 ID

## 3. 数据安全

### 3.1 数据分类

| 数据级别 | 说明 | 示例 | 保护要求 |
|---------|------|------|---------|
| **公开数据** | 可公开访问的数据 | 系统公告、帮助文档 | 完整性保护 |
| **内部数据** | 仅限内部员工访问 | 业务数据、统计报表 | 访问控制 + 审计 |
| **敏感数据** | 泄露会造成损失的数据 | 用户信息、财务数据 | 加密 + 访问控制 + 审计 |
| **高度敏感** | 泄露会造成严重损失的数据 | 密码、密钥、身份证号 | 强加密 + 严格访问控制 + 完整审计 |

### 3.2 数据加密

#### 3.2.1 传输加密

- **HTTPS/TLS**：所有外部通信使用 HTTPS，TLS 1.2+
- **证书管理**：使用可信 CA 签发的证书，定期更新
- **HSTS**：启用 HTTP Strict Transport Security
- **内部通信**：服务间通信也建议使用 TLS

#### 3.2.2 存储加密

| 数据类型 | 加密方式 | 说明 |
|---------|---------|------|
| 密码 | bcrypt/argon2 | 单向哈希，不可解密 |
| 敏感字段 | AES-256-GCM | 对称加密，需要时解密 |
| 数据库 | TDE（透明数据加密） | 数据库文件级加密 |
| 备份数据 | AES-256 | 备份文件加密存储 |
| 密钥 | KMS/HSM | 使用密钥管理服务管理加密密钥 |

#### 3.2.3 密钥管理

- **密钥轮换**：加密密钥定期轮换（建议 90 天）
- **密钥存储**：使用 KMS（密钥管理服务）或 HSM（硬件安全模块）
- **密钥访问**：严格控制密钥访问权限，记录所有密钥使用
- **密钥备份**：密钥安全备份，防止密钥丢失导致数据不可用

### 3.3 数据脱敏

#### 3.3.1 脱敏规则

| 数据类型 | 脱敏规则 | 示例 |
|---------|---------|------|
| 手机号 | 中间 4 位用 * 替换 | 138****8000 |
| 邮箱 | 用户名部分脱敏 | a***@example.com |
| 身份证号 | 中间 10 位用 * 替换 | 110***********1234 |
| 银行卡号 | 中间 12 位用 * 替换 | 6222 **** **** 1234 |
| 姓名 | 只显示姓 | 张** |
| 地址 | 只显示到区/县 | 北京市朝阳区**** |

#### 3.3.2 脱敏场景

- **日志脱敏**：日志中不记录敏感数据，或记录脱敏后的数据
- **接口脱敏**：API 返回数据根据用户权限进行脱敏
- **展示脱敏**：前端展示敏感数据时进行脱敏
- **导出脱敏**：数据导出时根据权限进行脱敏

### 3.4 数据备份与恢复

- **备份策略**：全量备份（每天）+ 增量备份（每小时）
- **备份加密**：备份文件加密存储
- **备份验证**：定期验证备份文件可恢复
- **异地备份**：重要数据异地备份，防止单点故障
- **恢复演练**：定期进行数据恢复演练（建议每季度）
- **保留周期**：根据合规要求确定备份保留周期（建议至少 90 天）

## 4. 应用安全

### 4.1 输入验证

- **白名单验证**：使用白名单验证输入，而不是黑名单
- **类型验证**：验证输入数据类型（字符串、数字、日期等）
- **长度验证**：验证输入长度，防止超长输入
- **格式验证**：验证输入格式（邮箱、手机号、URL 等）
- **范围验证**：验证数值范围、日期范围
- **业务验证**：验证业务规则（如结束日期大于开始日期）

### 4.2 输出编码

- **HTML 编码**：输出到 HTML 时进行 HTML 实体编码
- **JavaScript 编码**：输出到 JavaScript 时进行 JS 编码
- **URL 编码**：输出到 URL 参数时进行 URL 编码
- **CSS 编码**：输出到 CSS 时进行 CSS 编码
- **使用框架**：使用 React/Vue 等框架的自动转义功能

### 4.3 SQL 注入防护

- **参数化查询**：使用参数化查询，禁止字符串拼接 SQL
- **ORM 框架**：使用 SQLx/SeaORM 等 ORM 框架
- **输入验证**：对用户输入进行严格验证
- **最小权限**：数据库账户只授予必要的权限
- **存储过程**：敏感操作使用存储过程
- **错误信息**：不向用户返回详细的数据库错误信息

### 4.4 XSS 防护

- **输入过滤**：过滤或转义用户输入中的 HTML/JS 代码
- **输出编码**：输出时根据上下文进行编码
- **CSP**：配置 Content Security Policy，限制脚本来源
- **HttpOnly Cookie**：敏感 Cookie 设置 HttpOnly，防止 JS 访问
- **X-XSS-Protection**：启用浏览器 XSS 过滤器
- **富文本处理**：使用 DOMPurify 等库处理富文本输入

### 4.5 CSRF 防护

- **CSRF Token**：每个表单包含随机 CSRF Token，提交时验证
- **SameSite Cookie**：Cookie 设置 SameSite=Strict/Lax
- **自定义请求头**：API 请求使用自定义请求头（如 X-Requested-With）
- **验证 Referer**：验证请求的 Referer/Origin 头
- **敏感操作二次确认**：重要操作要求二次确认或重新输入密码

### 4.6 文件上传安全

- **文件类型验证**：验证文件扩展名和 MIME 类型
- **文件大小限制**：限制上传文件大小
- **文件内容检查**：检查文件内容，防止伪装文件
- **文件名处理**：重命名上传文件，防止路径遍历
- **存储位置**：上传文件存储在非 Web 可访问目录
- **病毒扫描**：上传文件进行病毒扫描
- **下载安全**：文件下载时设置正确的 Content-Type 和 Content-Disposition

### 4.7 API 安全

- **认证授权**：所有 API 都需要认证和授权
- **速率限制**：实施 API 速率限制，防止滥用
- **输入验证**：严格验证 API 输入参数
- **响应过滤**：根据用户权限过滤返回数据
- **版本管理**：API 版本化，支持平滑升级
- **错误处理**：统一错误处理，不泄露敏感信息
- **API 文档**：保持 API 文档与实际接口一致

## 5. 网络安全

### 5.1 防火墙配置

- **入站规则**：只开放必要的端口（80、443、SSH 等）
- **出站规则**：限制出站连接，只允许必要的外部访问
- **SSH 安全**：SSH 使用密钥认证，禁用密码登录，修改默认端口
- **管理端口**：管理端口只允许特定 IP 访问
- **定期审查**：定期审查防火墙规则，清理不必要的规则

### 5.2 DDoS 防护

- **流量清洗**：使用 CDN 或云服务商的 DDoS 防护服务
- **速率限制**：实施应用层速率限制
- **连接限制**：限制单 IP 并发连接数
- **弹性扩容**：配置自动扩容，应对流量突增
- **监控告警**：监控网络流量，异常时及时告警

### 5.3 WAF（Web 应用防火墙）

- **SQL 注入防护**：检测和拦截 SQL 注入攻击
- **XSS 防护**：检测和拦截 XSS 攻击
- **CC 攻击防护**：防护 CC（Challenge Collapsar）攻击
- **敏感信息泄露防护**：防止敏感信息泄露
- **自定义规则**：根据业务特点配置自定义防护规则
- **定期更新**：定期更新 WAF 规则库

## 6. 运维安全

### 6.1 系统加固

- **系统更新**：及时安装系统安全补丁
- **服务最小化**：只安装和运行必要的服务
- **账户管理**：禁用不必要的系统账户，使用强密码
- **文件权限**：合理设置文件和目录权限
- **审计日志**：启用系统审计日志，记录关键操作
- **安全基线**：遵循 CIS Benchmark 等安全基线标准

### 6.2 容器安全

- **镜像安全**：使用官方或可信基础镜像，定期扫描镜像漏洞
- **最小权限**：容器以非 root 用户运行，只挂载必要的卷
- **网络隔离**：使用 Docker 网络隔离不同服务
- **资源限制**：限制容器 CPU、内存等资源使用
- **密钥管理**：不将密钥硬编码在镜像中，使用环境变量或密钥管理服务
- **镜像签名**：使用镜像签名，确保镜像完整性

### 6.3 日志审计

- **日志收集**：集中收集系统、应用、安全日志
- **日志存储**：日志安全存储，防止篡改和删除
- **日志分析**：实时分析日志，检测异常行为
- **日志保留**：根据合规要求保留日志（建议至少 180 天）
- **关键事件告警**：登录失败、权限变更、数据导出等关键事件实时告警
- **定期审计**：定期审查日志，发现安全隐患

### 6.4 备份安全

- **备份加密**：备份数据加密存储
- **备份隔离**：备份存储与生产环境隔离
- **访问控制**：严格控制备份数据的访问权限
- **备份验证**：定期验证备份文件的完整性和可恢复性
- **异地备份**：重要数据异地备份，防止灾难丢失
- **备份审计**：记录备份操作，定期审计备份策略

## 7. 安全监控与应急响应

### 7.1 安全监控

| 监控项 | 监控内容 | 告警阈值 |
|--------|---------|---------|
| 登录异常 | 多次登录失败、异地登录、非工作时间登录 | 5 次失败/小时 |
| 权限变更 | 用户权限变更、角色变更 | 实时告警 |
| 数据访问 | 大量数据查询、敏感数据访问 | 超过正常阈值 |
| 数据导出 | 大量数据导出、敏感数据导出 | 实时告警 |
| API 异常 | API 错误率突增、异常 API 调用 | 错误率 > 5% |
| 系统异常 | CPU/内存/磁盘异常、服务异常重启 | 超过阈值 |
| 网络异常 | 异常流量、异常连接、端口扫描 | 实时告警 |

### 7.2 漏洞管理

- **漏洞扫描**：定期进行漏洞扫描（建议每周）
- **依赖检查**：定期检查第三方依赖漏洞
- **漏洞评级**：根据 CVSS 评分对漏洞评级
- **修复时限**：
  - 严重漏洞：24 小时内修复
  - 高危漏洞：72 小时内修复
  - 中危漏洞：1 周内修复
  - 低危漏洞：1 个月内修复
- **修复验证**：漏洞修复后进行验证
- **漏洞披露**：建立负责任的漏洞披露机制

### 7.3 应急响应

#### 7.3.1 应急响应流程

```
发现安全事件 → 启动应急响应 → 事件评估 → 遏制扩散 → 调查分析 → 修复恢复 → 总结改进
```

#### 7.3.2 事件分级

| 级别 | 说明 | 响应时间 | 负责人 |
|------|------|---------|--------|
| 特别重大 | 系统完全不可用、大量数据泄露 | 15 分钟 | CTO/CEO |
| 重大 | 核心功能不可用、敏感数据泄露 | 30 分钟 | 安全负责人 |
| 较大 | 部分功能异常、少量数据泄露 | 1 小时 | 运维负责人 |
| 一般 | 轻微安全问题、无数据泄露 | 4 小时 | 开发负责人 |

#### 7.3.3 常见事件处理

**数据泄露事件：**
1. 立即阻断泄露渠道
2. 评估泄露数据范围和影响
3. 通知受影响用户
4. 修复漏洞，防止再次发生
5. 向监管机构报告（如需要）
6. 进行事后分析和改进

**账户被盗事件：**
1. 立即锁定被盗账户
2. 强制该账户所有设备下线
3. 重置账户密码和密钥
4. 检查账户操作记录，评估影响
5. 通知用户并协助恢复
6. 加强账户安全措施

**勒索软件事件：**
1. 立即隔离受感染系统
2. 不要支付赎金（除非有明确指示）
3. 从备份恢复数据
4. 清除恶意软件
5. 修复入侵路径
6. 加强防护措施

## 8. 合规要求

### 8.1 常见合规标准

| 标准 | 适用范围 | 核心要求 |
|------|---------|---------|
| **等保 2.0** | 中国境内信息系统 | 安全物理环境、通信网络、区域边界、计算环境、管理中心 |
| **GDPR** | 处理欧盟个人数据 | 数据保护权、数据可携权、被遗忘权、数据泄露通知 |
| **个人信息保护法** | 中国境内个人信息处理 | 告知同意、最小必要、目的限制、安全保障 |
| **网络安全法** | 中国境内网络运营 | 网络安全等级保护、关键信息基础设施保护、数据本地化 |
| **ISO 27001** | 信息安全管理体系 | 信息安全管理体系、风险评估、控制措施 |
| **SOC 2** | 服务组织控制 | 安全性、可用性、处理完整性、保密性、隐私性 |

### 8.2 数据主体权利

- **知情权**：告知用户数据收集和使用情况
- **同意权**：用户有权同意或拒绝数据处理
- **访问权**：用户有权访问自己的个人数据
- **更正权**：用户有权更正不准确的数据
- **删除权**：用户有权要求删除个人数据
- **可携权**：用户有权获取和转移自己的数据
- **限制处理权**：用户有权限制数据处理
- **反对权**：用户有权反对数据处理

### 8.3 数据泄露通知

- **通知时限**：发现数据泄露后 72 小时内通知监管机构
- **通知内容**：泄露数据类型、数量、影响范围、已采取措施
- **用户通知**：可能对用户造成风险时，及时通知用户
- **记录留存**：记录所有数据泄露事件，包括未达到通知阈值的事件

## 9. 安全培训

### 9.1 培训对象和内容

| 培训对象 | 培训内容 | 培训频率 |
|---------|---------|---------|
| **全体员工** | 安全意识、密码安全、钓鱼识别、数据保护 | 每年至少 1 次 |
| **开发人员** | 安全编码、OWASP Top 10、代码审计、依赖安全 | 每半年 1 次 |
| **运维人员** | 系统加固、网络安全、日志审计、应急响应 | 每半年 1 次 |
| **管理人员** | 安全管理、合规要求、风险管理、事件响应 | 每年 1 次 |
| **新员工** | 安全制度、安全意识、岗位安全要求 | 入职时 |

### 9.2 安全意识要点

- **密码安全**：使用强密码，不共享密码，定期更换
- **钓鱼防范**：不点击可疑链接，不下载可疑附件，核实发件人
- **数据保护**：不随意发送敏感数据，使用加密传输，妥善保管设备
- **设备安全**：设置屏幕锁定，不随意连接公共 WiFi，及时安装更新
- **社会工程学**：警惕陌生人询问，核实身份，不透露内部信息
- **事件报告**：发现安全事件及时报告，不隐瞒，不擅自处理
