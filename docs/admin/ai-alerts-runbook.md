## 1. 概述

### 1.1 目的

本文档为 TOPEMS AI 服务的 Prometheus 告警规则提供对应的故障排查手册（Runbook），帮助运维人员快速定位和解决 AI 服务相关的问题。

### 1.2 告警级别定义

| 级别 | 说明 | 响应时间 |
|------|------|---------|
| **critical** | 严重，服务不可用或数据有丢失风险 | 立即（< 5 分钟） |
| **warning** | 警告，服务性能下降或存在潜在风险 | 30 分钟内 |
| **info** | 提示，信息记录或使用量较高 | 24 小时内 |

### 1.3 常用命令

```bash
# 查看 AI 服务状态
systemctl status topems-ai

# 查看 AI 服务日志
journalctl -u topems-ai -f --since "10 minutes ago"

# 重启 AI 服务
systemctl restart topems-ai

# 查看健康状态
curl http://localhost:8013/health

# 查看 Prometheus 指标
curl http://localhost:8013/metrics | grep ai_
```

## 2. AI 服务可用性告警

### 2.1 AIServiceDown

**告警级别：** critical  
**触发条件：** AI 服务宕机超过 1 分钟

#### 排查步骤

1. 确认服务状态：`systemctl status topems-ai`
2. 查看服务日志：`journalctl -u topems-ai -n 200`
3. 检查依赖服务：PostgreSQL、Redis、AI 模型服务
4. 检查端口占用：`lsof -i :8013`
5. 检查系统资源：CPU、内存、磁盘

#### 处理方法

- 服务崩溃：查看日志错误，修复后重启
- 依赖服务不可用：先恢复依赖服务，再重启 AI 服务
- 端口冲突：停止占用端口的进程，或修改端口配置
- 资源不足：释放资源或扩容，然后重启服务

---

### 2.2 AIServiceFrequentRestarts

**告警级别：** warning  
**触发条件：** AI 服务在 15 分钟内重启超过 3 次

#### 排查步骤

1. 查看重启历史：`journalctl -u topems-ai | grep "Started\|Stopped\|Failed"`
2. 查看崩溃日志：搜索 error、panic、fatal、oom
3. 检查 OOM：`dmesg | grep -i "oom\|killed"`
4. 查看内存使用趋势（Grafana 仪表盘）
5. 检查并发请求量是否异常

#### 处理方法

- 内存泄漏：重启临时缓解，排查代码
- OOM 被杀：增加内存限制或系统内存
- 流量过高：启用限流，扩容实例
- 依赖服务不稳定：增加重试和熔断机制

---

### 2.3 AIHealthCheckFailed

**告警级别：** critical  
**触发条件：** AI 服务健康检查持续失败超过 2 分钟

#### 排查步骤

1. 查看详细健康状态：`curl http://localhost:8013/health/detailed`
2. 检查失败的组件：数据库、Redis、AI 模型服务、向量数据库
3. 查看健康检查相关日志
4. 检查依赖服务的详细状态

#### 处理方法

- 数据库连接失败：检查配置，恢复数据库服务
- Redis 连接失败：检查配置，恢复 Redis 服务
- AI 模型服务不可用：切换到备用模型或 mock 模式
- 向量数据库异常：检查索引状态，必要时重建

## 3. AI 服务性能告警

### 3.1 AIAPIHighLatencyP95

**告警级别：** warning  
**触发条件：** AI API p95 响应时间 > 2 秒，持续 5 分钟

#### 排查步骤

1. 查看慢请求端点（Grafana 仪表盘）
2. 查看 AI 模型响应时间指标
3. 检查数据库慢查询日志
4. 检查系统资源：CPU、内存、磁盘 I/O
5. 检查并发请求量是否突增

#### 处理方法

- AI 模型响应慢：切换更快模型，增加资源，使用缓存
- 数据库慢查询：优化查询，添加索引，增加连接池
- 资源不足：扩容实例，增加系统资源
- 流量过高：启用限流，扩容实例，使用负载均衡
- 缓存命中率低：优化缓存策略，增加缓存容量

---

### 3.2 AIAPIHighLatencyP99

**告警级别：** critical  
**触发条件：** AI API p99 响应时间 > 5 秒，持续 5 分钟

#### 排查步骤

1. 按照 AIAPIHighLatencyP95 的步骤排查
2. 重点关注极端慢请求
3. 检查超时配置：AI 模型调用、数据库查询
4. 检查是否有阻塞操作：长时间事务、锁等待

#### 处理方法

- 按照 AIAPIHighLatencyP95 的方法处理
- 极端慢请求：增加超时限制，异步处理长耗时操作
- 死循环/阻塞：修复代码逻辑，增加超时保护
- 锁等待：优化事务逻辑，减少锁持有时间

---

### 3.3 AIAgentExecutionTimeout

**告警级别：** warning  
**触发条件：** AI Agent 执行时间 > 30 秒

#### 排查步骤

1. 查看 Agent 执行日志
2. 查看是哪个 Agent 或任务执行时间长
3. 检查是否有死循环或无限重试
4. 检查 Agent 调用的外部服务响应时间

#### 处理方法

- 死循环：修复代码，增加最大迭代次数限制
- 外部服务慢：增加超时，异步调用，增加缓存
- 复杂任务：优化任务分解，并行执行独立步骤
- 资源不足：增加执行资源，限制并发 Agent 数量

---

### 3.4 AIModelHighLatency

**告警级别：** warning  
**触发条件：** AI 模型响应时间 > 10 秒，持续 5 分钟

#### 排查步骤

1. 查看模型响应时间（按模型）
2. 测试模型服务连通性
3. 检查模型服务状态：本地模型（Ollama）、云端模型（OpenAI）
4. 检查 API Key 是否有效，是否有额度限制
5. 检查网络连接

#### 处理方法

- 本地模型服务异常：重启模型服务，增加资源
- 云端模型服务异常：切换到备用模型，等待服务恢复
- API Key 问题：更新 API Key，检查额度
- 网络问题：优化网络连接，使用代理
- 模型本身慢：切换更快模型，使用模型缓存

## 4. AI 服务错误率告警

### 4.1 AIAPIHighErrorRate

**告警级别：** critical  
**触发条件：** AI API 5xx 错误率 > 5%，持续 5 分钟

#### 排查步骤

1. 查看错误请求详情（按端点和状态码）
2. 查看服务错误日志
3. 检查依赖服务：数据库、Redis、AI 模型服务
4. 检查最近的变更：代码部署、配置变更、依赖升级
5. 检查系统资源

#### 处理方法

- 代码 bug：回滚到稳定版本，修复后重新部署
- 配置错误：恢复正确配置，重启服务
- 依赖服务异常：恢复依赖服务，切换到备用服务
- 资源不足：扩容实例，增加资源
- 流量攻击：启用限流和防护，封禁恶意 IP

---

### 4.2 AIAPIRateLimited

**告警级别：** warning  
**触发条件：** AI API 429 限流请求 > 10 次/分钟，持续 5 分钟

#### 排查步骤

1. 查看限流请求详情（按端点和用户/IP）
2. 检查限流配置是否合理
3. 分析流量模式：是否异常突增，是否单个用户大量请求
4. 检查是否有恶意请求

#### 处理方法

- 正常业务增长：调整限流阈值，扩容实例
- 单个用户过量：联系用户，调整用户级限流
- 恶意请求：封禁 IP，启用 WAF 防护
- 限流配置过严：调整配置，增加阈值
- 突发流量：启用弹性扩容，临时增加阈值

---

### 4.3 AIAgentHighFailureRate

**告警级别：** warning  
**触发条件：** AI Agent 执行失败率 > 10%，持续 5 分钟

#### 排查步骤

1. 查看 Agent 失败详情（按 Agent 类型和失败原因）
2. 查看 Agent 执行日志
3. 检查 Agent 配置：模型、工具、权限
4. 检查依赖服务：AI 模型、工具/API、数据库、缓存

#### 处理方法

- 配置错误：修复配置，重启服务
- 模型服务异常：恢复服务，切换备用模型
- 工具/API 异常：恢复服务，增加容错处理
- 权限问题：修复权限配置
- 代码 bug：修复执行逻辑，增加错误处理

---

### 4.4 AIModelCallFailed

**告警级别：** warning  
**触发条件：** AI 模型调用在 10 分钟内失败 > 5 次

#### 排查步骤

1. 查看模型调用失败详情（按模型和失败原因）
2. 测试模型服务连通性
3. 检查模型配置：API Key、模型名称、端点 URL、额度
4. 查看模型服务状态

#### 处理方法

- API Key 无效/过期：更新 API Key
- 额度不足：充值或切换模型/服务商
- 模型名称错误：修正配置
- 模型服务异常：等待恢复，切换备用模型
- 网络问题：修复连接，配置代理
- 本地模型崩溃：重启服务，查看错误日志

## 5. AI 治理合规告警

### 5.1 AIComplianceRateLow

**告警级别：** critical  
**触发条件：** AI 合规率 < 95%，持续 10 分钟

#### 排查步骤

1. 查看合规检查详情（AI 治理仪表盘）
2. 查看不合规请求详情
3. 查看合规检查日志
4. 分析不合规原因：内容安全、PII 脱敏、频率限制、数据保留
5. 检查是否有异常使用或新功能未接入

#### 处理方法

- 合规规则过严：调整规则，平衡安全和可用性
- 用户违规使用：警告或封禁用户，加强教育
- 新功能未接入：接入合规检查流程
- 合规检查 bug：修复逻辑
- 误报率高：优化规则，减少误报

---

### 5.2 AIContentSafetyBlocked

**告警级别：** warning  
**触发条件：** AI 内容安全在 10 分钟内拦截 > 10 次

#### 排查步骤

1. 查看拦截详情（内容类型、用户分布、拦截原因）
2. 查看内容安全日志
3. 分析拦截模式：单个用户大量拦截、特定内容类型、正常内容误拦截
4. 检查内容安全规则配置

#### 处理方法

- 用户滥用：警告或封禁用户，加强教育
- 规则过严：调整规则，减少误拦截
- 规则过松：加强规则，增加拦截类别
- 误报率高：优化模型，增加白名单
- 新型违规内容：更新规则，覆盖新型内容

---

### 5.3 AIPIILeakageRisk

**告警级别：** critical  
**触发条件：** AI 服务在 10 分钟内检测到并阻止了 > 5 次 PII 数据泄露风险

#### 排查步骤

1. 查看 PII 泄露详情（数据类型、用户、来源）
2. 查看 PII 检测日志
3. 分析泄露风险模式：用户故意输入、AI 输出包含、数据查询返回
4. 检查 PII 脱敏配置和规则

#### 处理方法

- 用户故意输入：警告用户，限制输入内容
- AI 输出包含 PII：优化提示词，加强输出过滤，增加脱敏
- 数据查询泄露：限制查询范围，增加数据权限控制
- PII 规则遗漏：更新检测规则，覆盖更多类型
- 脱敏未生效：修复脱敏逻辑，确保所有输出经过脱敏

---

### 5.4 AIGovernanceScoreLow

**告警级别：** warning  
**触发条件：** AI 治理评分 < 70，持续 15 分钟

#### 排查步骤

1. 查看治理评分详情（AI 治理仪表盘）
2. 查看是哪些维度拉低评分（合规、安全、成本、性能）
3. 查看治理指标趋势
4. 分析低分原因
5. 检查最近的变更

#### 处理方法

- 合规率低：按照 AIComplianceRateLow 处理
- 安全事件多：按照 AIContentSafetyBlocked 和 AIPIILeakageRisk 处理
- 成本高：按照 AIDailyCostOverBudget 处理
- 性能差：按照 AIAPIHighLatencyP95 处理
- 新功能影响：优化新功能，必要时回滚

## 6. AI 成本告警

### 6.1 AIDailyCostOverBudget

**告警级别：** warning  
**触发条件：** AI 日成本 > $100

#### 排查步骤

1. 查看成本详情（按模型、业务模块、用户分布）
2. 查看 Token 消耗趋势
3. 分析成本增长原因：用户量、使用频率、单次 Token 消耗、模型切换、异常使用
4. 检查预算配置是否合理

#### 处理方法

- 正常业务增长：调整预算，优化成本效率
- 模型选择不当：切换更便宜模型，使用分级策略
- Token 消耗过高：优化提示词，使用更短上下文，启用缓存
- 异常使用：识别并限制异常用户，启用用户级限流
- 预算过低：根据需求调整阈值
- 成本优化：批量处理，异步处理，缓存常用结果

---

### 6.2 AICostAbnormalIncrease

**告警级别：** warning  
**触发条件：** AI 服务今日成本是昨日的 2 倍以上

#### 排查步骤

1. 对比今日和昨日成本（按小时、模型、功能）
2. 查看异常请求（用户/IP、长请求）
3. 检查是否有新功能上线
4. 检查是否有配置变更（模型切换、参数调整）

#### 处理方法

- 异常用户/IP：限制或封禁，加强监控
- 新功能成本高：优化功能，调整模型，必要时回滚
- 配置变更：恢复之前配置，评估成本影响
- 正常业务增长：调整预算，优化成本效率
- 攻击/滥用：启用防护，封禁恶意来源

---

### 6.3 AITokenUsageHigh

**告警级别：** info  
**触发条件：** AI 服务过去 1 小时 Token 消耗量 > 100 万

#### 排查步骤

1. 查看 Token 消耗详情（按模型、业务模块、用户）
2. 分析使用模式是否正常
3. 查看是否有优化空间

#### 处理方法

- 正常使用：关注即可
- 可优化：优化提示词，使用缓存，切换更高效模型
- 记录趋势：用于预算规划

## 7. AI 资源使用告警

### 7.1 AIServiceHighMemory

**告警级别：** warning  
**触发条件：** AI 服务内存使用 > 4GB，持续 10 分钟

#### 排查步骤

1. 查看内存使用趋势（Grafana 仪表盘）
2. 查看进程内存详情：`ps aux | grep topems-ai`、`top -p <pid>`
3. 分析内存增长原因：缓存、内存泄漏、大对象、并发请求、向量索引
4. 查看应用内存统计指标

#### 处理方法

- 缓存过多：调整缓存大小限制，优化淘汰策略
- 内存泄漏：重启临时缓解，排查代码
- 大对象：优化处理，使用流式处理，及时释放
- 并发过高：限制并发，扩容实例
- 向量索引大：优化索引，使用更高效算法，分片存储
- 资源不足：增加系统内存，扩容实例

---

### 7.2 AIServiceHighCPU

**告警级别：** warning  
**触发条件：** AI 服务 CPU 使用率 > 80%，持续 10 分钟

#### 排查步骤

1. 查看 CPU 使用趋势
2. 查看进程和线程级 CPU 使用
3. 分析高 CPU 原因：请求量、复杂计算、AI 推理、向量搜索、数据处理、死循环
4. 查看请求量和响应时间

#### 处理方法

- 请求量高：扩容实例，负载均衡，启用限流
- 复杂计算：优化算法，异步处理，增加资源
- AI 推理慢：使用更快模型，增加资源，GPU 加速
- 向量搜索慢：优化索引，近似搜索，分片搜索
- 死循环/异常：修复代码，增加超时保护
- 资源不足：增加 CPU 核心，扩容实例

---

### 7.3 AIConcurrentRequestsHigh

**告警级别：** warning  
**触发条件：** AI 并发请求数 > 100，持续 5 分钟

#### 排查步骤

1. 查看并发请求详情（按端点、用户）
2. 查看请求量趋势
3. 检查服务性能（响应时间、错误率、资源使用）
4. 检查限流配置

#### 处理方法

- 正常业务高峰：扩容实例，调整限流阈值
- 异常并发：识别并限制异常来源，启用防护
- 性能下降：优化性能，增加资源
- 限流过严：调整配置，增加并发限制
- 弹性扩容：启用自动扩容

---

### 7.4 AICacheHitRateLow

**告警级别：** info  
**触发条件：** AI 缓存命中率 < 50%，持续 15 分钟

#### 排查步骤

1. 查看缓存详情（命中率、按类型、大小使用）
2. 分析低命中率原因：容量不足、过期时间短、请求重复率低、键设计不合理、淘汰策略不合理
3. 查看缓存配置

#### 处理方法

- 容量不足：增加缓存容量
- 过期时间短：调整过期时间，根据数据更新频率设置
- 请求重复率低：分析请求模式，针对重复请求优化
- 缓存键不合理：优化键设计，确保相同请求使用相同键
- 淘汰策略不合理：调整策略（LRU/LFU）
- 缓存类型选择：根据数据特点选择合适类型

## 8. AI 业务 Copilot 告警

### 8.1 AICopilotSessionCreationFailed

**告警级别：** warning  
**触发条件：** AI Copilot 在 10 分钟内会话创建失败 > 5 次

#### 排查步骤

1. 查看失败详情（失败原因、用户、模块）
2. 查看 Copilot 日志
3. 检查依赖服务：数据库（会话存储）、Redis（会话缓存）、AI 模型（意图识别）
4. 检查 Copilot 配置：模块配置、权限配置、会话存储配置

#### 处理方法

- 数据库异常：恢复服务，检查连接池
- Redis 异常：恢复服务，检查缓存配置
- 配置错误：修复配置，重启服务
- 权限问题：修复权限配置
- 代码 bug：修复会话创建逻辑，增加错误处理

---

### 8.2 AICopilotIntentAccuracyLow

**告警级别：** info  
**触发条件：** AI Copilot 意图识别准确率 < 80%，持续 30 分钟

#### 排查步骤

1. 查看意图识别详情（准确率趋势、低准确率意图、误识别案例）
2. 分析低准确率原因：训练数据不足、意图定义不清、用户表达多样、模型选择不当、提示词不合理
3. 查看意图识别配置

#### 处理方法

- 训练数据不足：收集更多数据，微调模型
- 意图定义不清：优化定义，增加示例，明确边界
- 用户表达多样：增加更多表达示例，使用更灵活模型
- 模型选择不当：切换更适合意图识别的模型
- 提示词不合理：优化提示词，增加上下文和示例
- 使用规则辅助：对明确意图使用规则匹配辅助

---

### 8.3 AICopilotActiveSessionsHigh

**告警级别：** info  
**触发条件：** AI Copilot 活跃会话数 > 50，持续 10 分钟

#### 排查步骤

1. 查看活跃会话详情（按模块、用户、持续时间）
2. 分析使用模式是否正常
3. 查看是否有异常长时间会话

#### 处理方法

- 正常使用：关注即可
- 会话超时：调整超时时间，及时清理不活跃会话
- 资源优化：优化会话存储，使用更高效管理
- 记录趋势：用于容量规划

## 9. 通用故障排查流程

### 9.1 故障排查通用步骤

1. **确认问题**：确认告警内容和影响范围，确认问题是否持续
2. **收集信息**：查看服务状态和日志，查看监控指标，查看最近变更，查看依赖服务
3. **定位原因**：分析日志和指标，排查可能原因，验证假设
4. **处理问题**：根据原因采取措施，优先恢复服务，记录处理过程
5. **验证恢复**：确认服务恢复，确认告警解除，确认用户可正常使用
6. **事后总结**：记录故障原因和处理，分析预防措施，更新文档，创建改进任务

### 9.2 紧急恢复措施

| 问题类型 | 紧急恢复措施 |
|---------|-------------|
| 服务崩溃 | 重启服务，回滚到稳定版本 |
| 依赖服务异常 | 切换备用服务，使用 mock 模式 |
| 配置错误 | 恢复正确配置，重启服务 |
| 资源不足 | 扩容实例，增加资源 |
| 流量攻击 | 启用限流，封禁恶意 IP |
| 数据库异常 | 重启数据库，恢复备份 |
| 缓存异常 | 重启缓存服务，清除异常缓存 |
