# 模板变量替换失败排查指南

## 一、常见警告类型及排查方法

### 1. ⚠️ "模板中未找到变量 {{xxx}}"

**现象**：
```
⚠️ 警告: 模板中未找到变量 {{workflow_name}}
```

**原因分析**：
- 模板内容中没有该变量的引用
- 变量名拼写错误
- 变量定义多余，模板实际不需要

**排查步骤**：

#### 步骤1：检查模板原始内容
在日志中找到"原始内容"部分，搜索变量名：
```
=== 开始模板渲染 ===
原始内容:
【{{work_flow_name}}】  ← 注意这里可能是 work_flow_name 而不是 workflow_name
```

#### 步骤2：对比变量定义
检查变量定义列表：
```
变量定义: [
  { "key": "workflow_name", ... }  ← 定义的是 workflow_name
]
```

#### 步骤3：确认问题
- 如果模板中是 `{{work_flow_name}}`，定义是 `workflow_name` → **变量名不匹配**
- 如果模板中确实没有该变量 → **变量定义多余**

**解决方案**：
```javascript
// 方案1：修正模板中的变量名
// 将 {{work_flow_name}} 改为 {{workflow_name}}

// 方案2：删除多余的变量定义
// 在变量配置中移除 workflow_name
```

### 2. ⚠️ "发现未处理的变量"

**现象**：
```
⚠️ 发现未处理的变量:
  - {{unknown_var}}
  - {{another_var}}
```

**原因分析**：
- 变量未配置值
- 变量名不匹配
- 特殊变量格式（条件判断、默认值等）

**排查步骤**：

#### 步骤1：检查变量配置
查看日志中的"变量配置"部分：
```
变量配置: {
  "workflow_name": "测试流程",
  "description": "测试描述"
  // 注意：缺少 unknown_var 和 another_var
}
```

#### 步骤2：检查变量定义
查看"变量定义"部分，确认是否定义了这些变量：
```
变量定义: [
  { "key": "workflow_name", ... },
  { "key": "description", ... }
  // 没有 unknown_var 和 another_var 的定义
]
```

#### 步骤3：分析变量来源
- 如果变量在定义中存在但配置中缺少 → **需要配置值**
- 如果变量不在定义中 → **模板中有未定义的变量引用**

**解决方案**：
```javascript
// 方案1：添加变量配置值
const variables = {
  workflow_name: "测试流程",
  unknown_var: "默认值",  // 添加缺失的变量
  another_var: "另一个值"
};

// 方案2：使用默认值语法
// 在模板中使用 {{unknown_var || "默认值"}}
```

### 3. ❌ "变量 {{xxx}} 替换后仍存在"

**现象**：
```
❌ 错误: 变量 {{special_var}} 替换后仍存在
```

**原因分析**：
- 变量值包含特殊字符导致替换失败
- 正则表达式匹配问题
- 编码问题

**排查步骤**：

#### 步骤1：检查变量值
查看日志中的变量值：
```
变量 [special_var]:
  - 值: "{{another_var}}" (类型: string)  ← 值本身包含花括号
```

#### 步骤2：检查特殊字符
常见特殊字符问题：
- 值本身包含 `{{` 或 `}}`
- 值包含换行符或特殊空白字符
- 值为 null 或 undefined

**解决方案**：
```javascript
// 方案1：清理变量值中的特殊字符
const value = originalValue.replace(/[{}]/g, '');

// 方案2：使用转义
const value = encodeURIComponent(originalValue);

// 方案3：检查变量值来源，确保不包含模板语法
```

## 二、条件判断问题排查

### 问题：条件判断未生效

**现象**：
```
条件块 {{#if is_urgent}}:
  - 条件变量: is_urgent
  - 变量值: "true" (类型: string)  ← 注意是字符串而不是布尔值
  - 布尔转换: true
  - 处理结果: 保留内容
```

但实际输出中条件内容被删除了。

**原因分析**：
- 变量类型不正确（字符串 "true" vs 布尔值 true）
- 变量值为空字符串或 "false"

**排查步骤**：

#### 步骤1：检查变量类型
查看日志中的变量类型：
```
变量 [is_urgent]:
  - 值: "true" (类型: string)  ← 应该是 boolean 类型
```

#### 步骤2：检查布尔转换逻辑
```
布尔转换规则：
- 字符串: 非空为 true，空为 false
- 数字: 非0为 true，0为 false
- 布尔: 直接使用
- null/undefined: false
```

**解决方案**：
```javascript
// 方案1：使用正确的布尔值
const variables = {
  is_urgent: true  // 使用布尔值而不是字符串
};

// 方案2：字符串转布尔
const isUrgent = stringValue === 'true';

// 方案3：在模板中使用字符串比较
// {{#if is_urgent == "true"}}
```

## 三、默认值问题排查

### 问题：默认值未生效

**现象**：
```
默认值块 {{priority || "normal"}}:
  - 变量: priority
  - 变量值: ""
  - 默认值: "normal"
  - 最终值: ""  ← 应该是 "normal"
  - 使用默认值: false  ← 应该是 true
```

**原因分析**：
- 空字符串被视为有效值，不会使用默认值
- 默认值语法格式错误

**排查步骤**：

#### 步骤1：检查变量值
确认变量值是否为空：
```
变量 [priority]:
  - 值: "" (类型: string)
```

#### 步骤2：检查默认值逻辑
当前逻辑：`value && value !== "" ? value : default`

**解决方案**：
```javascript
// 方案1：不传递空字符串，传递 null 或不传递
const variables = {
  workflow_name: "测试",
  // priority 不传递，会使用默认值
};

// 方案2：显式设置为 null
const variables = {
  workflow_name: "测试",
  priority: null  // 会触发默认值
};

// 方案3：修改模板使用条件判断
// {{#if priority}}{{priority}}{{else}}normal{{/if}}
```

## 四、动态变量问题排查

### 问题：动态变量未替换

**现象**：
```
⚠️ 发现未处理的变量:
  - {{today}}
  - {{now}}
```

**原因分析**：
- 动态变量替换逻辑未执行
- 动态变量名拼写错误

**排查步骤**：

#### 步骤1：检查支持的动态变量
支持的动态变量：
- `{{today}}` - 当前日期 (YYYY-MM-DD)
- `{{now}}` - 当前时间戳
- `{{now_date}}` - 当前日期
- `{{now_time}}` - 当前时间
- `{{now_timestamp}}` - Unix时间戳

#### 步骤2：检查变量名拼写
```
错误示例：
- {{Today}}  ← 大写T，应该是 {{today}}
- {{NOW}}    ← 全大写，应该是 {{now}}
- {{date}}   ← 不支持，应该是 {{today}}
```

**解决方案**：
```javascript
// 使用正确的动态变量名
模板内容：
创建时间：{{today}}
时间戳：{{now}}
```

## 五、完整排查流程

### 排查清单

1. **查看完整日志**
   ```
   === 开始模板渲染 ===
   模板名称: xxx
   原始内容: ...
   变量配置: ...
   变量定义: ...
   ```

2. **检查变量替换步骤**
   ```
   --- 步骤1: 替换变量 ---
   变量 [xxx]:
     - 值: ...
     - 匹配次数: ...
   ```

3. **检查条件判断步骤**
   ```
   --- 步骤2: 处理条件判断 ---
   条件块 {{#if xxx}}:
     - 处理结果: ...
   ```

4. **检查默认值步骤**
   ```
   --- 步骤3: 处理默认值 ---
   默认值块 {{xxx || "yyy"}}:
     - 最终值: ...
   ```

5. **检查动态变量步骤**
   ```
   --- 步骤4: 替换动态变量 ---
   动态变量:
     - {{today}}: 2026-06-13
   ```

6. **检查未处理变量**
   ```
   --- 步骤5: 检查未处理的变量 ---
   ⚠️ 发现未处理的变量: ...
   ```

7. **查看最终结果**
   ```
   === 渲染完成 ===
   最终内容: ...
   ```

## 六、常见问题速查表

| 问题现象 | 可能原因 | 解决方案 |
|---------|---------|---------|
| ⚠️ 未找到变量 | 变量名不匹配 | 检查模板中的变量名拼写 |
| ⚠️ 未处理变量 | 变量未配置值 | 添加变量配置或使用默认值 |
| ❌ 替换失败 | 特殊字符问题 | 清理变量值中的特殊字符 |
| 条件判断失效 | 类型错误 | 使用正确的布尔值类型 |
| 默认值失效 | 空字符串问题 | 使用 null 或不传递变量 |
| 动态变量失效 | 变量名错误 | 使用正确的动态变量名 |

## 八、最佳实践

### 1. 变量命名规范
- 使用小写字母和下划线：`workflow_name`
- 避免使用特殊字符
- 保持变量名简洁明了

### 2. 变量定义规范
- 必填变量标记 `required: true`
- 提供合理的默认值
- 添加清晰的 `label` 和 `description`

### 3. 模板编写规范
- 使用标准 Mustache 语法：`{{variable}}`
- 条件判断：`{{#if variable}}...{{/if}}`
- 默认值：`{{variable || "default"}}`
- 动态变量：`{{today}}`, `{{now}}`

### 4. 测试验证
- 编写单元测试覆盖各种场景
- 使用真实数据测试模板
- 定期检查模板渲染结果
